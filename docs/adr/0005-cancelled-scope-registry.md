# ADR-0005: One registry of cancelled scopes

- Status: accepted (2026-09-12); third structural change of the rebuild
- Evidence: `docs/rebuild/INVENTORY.md` S3; `inventory/runtime.md` D2; commit dbe0ca4 (a fix for one copy that had been missed)

## Context

A translation session's scope can end for certain — the reader restores the page, closes the tab, or the page itself reports a different session — or only probably, when `tabs.onUpdated` reports a load that may be a same-document hash change. The background answered the two cases with the same `remember` flag written in three places:

- `entrypoints/background/sessions.ts` kept `dropped: Set<string>` (unbounded), added on a remembered drop, read by `forCall` and `bind` so a dropped scope is never re-bound.
- every `createTranslateService` owned a `CancelledScopeRegistry` (ported from Read Frog, TTL ten minutes, 256 entries), marked by its own `cancel(scope, { remember })`, read after the cache read, before the cache write and by the batch queue's liveness hook. A chain of three engines had three registries; a rebuilt chain started with empty ones, which is why `forCall` had to cancel a dead scope again on whatever chain it met.
- `entrypoints/background/ocr.ts` kept `cancelled: Set<string>` (unbounded), marked by its own `cancel(scope, { remember })`, read at entry and after the cache read.

Each copy carried its own reading of `remember`, `CancelOptions` had to travel through `TranslationTransport`, `TranslateService`, the fallback service and `OcrService` so the router's decision reached every store, and the guard ledger records a fix (dbe0ca4) for one copy that had been left out. The content script's `alive()` (ADR-0004) is not a fourth copy of this fact: it is the page's own view of its session and lives in another realm.

## Decisions

1. **One registry, created once, injected everywhere.** `background/index.ts` creates a single `CancelledScopeRegistry` and hands it to the session router, to `createLocalTransport` (which passes it to every `createTranslateService`, on-chain and off-chain) and to `createOcrService`. The registry is a required dependency of all four factories — `pnpm typecheck` is what proves the wiring is complete.
2. **The router is the only writer.** Whether a scope is dead for certain is the router's decision (`drop` with `remember`, the default; the grace-period probe's `unknown` answer and `dropAndRebindAll` drain without marking). The services only read: `TranslateService.cancel(scope)`, `TranslationTransport.cancel(scope)` and `OcrService.cancel(scope)` drain queued and in-flight work and return the count; `CancelOptions` is gone.
3. **Mark before anything is awaited.** `drop` marks every scope it was given before it drains any of them, so a call suspended on its cache read wakes up to a scope already dead — the property the service-level "mark, then drain" used to provide, now guaranteed once and for every reader, including a chain built after the drop.
4. **Nothing expires.** The ported registry pruned entries by a TTL (ten minutes) and a size cap (256); the first version of this change kept both, and the local review reproduced the consequence: a `forCall` held on a chain build while its tab closed, followed by 256 other drops, woke to an evicted mark, bound the dead session and let its request reach the provider. The router's old `dropped` set never forgot, and the property it gave — a scope ended for certain stays ended for the worker's life — is a correctness guarantee, not a memory policy (charter §4). The registry is therefore a set that only grows: an entry is a few dozen bytes per ended session, and the worker's own life bounds it (recycled after thirty idle seconds). Session ids are never reused, so remembering can never wrongly refuse a live request.
5. **Ported code keeps what is called** (ADR-0001 §9). `CancelledScopeRegistry` is rewritten to the two calls that remain, `markScope` and `has` — no prefix marks (the router drops by exact scope), no pruning; `TranslationCancelledError` stays as ported. The attribution header and `docs/THIRD_PARTY.md` record the change.

## Consequences

- One place answers "is this scope dead", one place decides it; a service built for a new chain or a new OCR backend (ADR-0002) reads the same answer without being told again.
- The router's tests observe the soft/hard distinction on the registry instead of on a flag echoed by a fake transport; the service and OCR tests mark the registry the way the router does before asserting that later calls are refused.
- `tests/providers/request/cancellation.test.ts` loses its prefix, TTL and size-cap cases; a router test pins that a certain drop survives hundreds of later drops and ten minutes with a chain build held. The queues' `cancelWhere` (called by `cancelByScope`) is untouched.
- The review's second pass surfaced an inherited race in the same bookkeeping, fixed here in its own commit: a text request's first `forCall` registered its scope only after the chain build, so a tab closed during the build found no session to drop and the continuation bound the dead scope and let the request out. `forCall` now records the scope and tab before its first await, as `bind` does for OCR; and a `rebind` / `dropAndRebindAll` that lands during the build keeps its choice instead of being overruled by the chain the build returns. Pinned by a router test and by a router-plus-real-service test in `tests/providers/transport.test.ts`. The third pass found the same race in `dropAndRebindAll`: moving one session per awaited drain let a build landing in the gap bind the chain being replaced; it now moves every session synchronously first and drains the old chains afterwards, with its own regression test. The fourth pass found two more inherited holes, both fixed here: a request of a live session suspended in a replaced chain's cache read — outside every queue — went on to the deleted provider and cached its result, so a local chain now has `retire()`, called by `dropAndRebindAll` before it drains, and a retired chain refuses every call that wakes inside it while the scope lives on; and a navigation probe that awaited the page could re-arm its stale scopes over the timer of a newer session on the same tab, so each tab's probe carries a number and a superseded probe stops. The same pass showed the no-expiry regression could not see a TTL that prunes on write; it now writes after the clock moves. The fifth pass turned `retire()` against itself: two engine-ready rebuilds can finish newer-first, and the older one's `dropAndRebindAll(itsChain)` moved every session onto the stale build and retired the chain in force, after which every fresh page bound to a retired chain. The router's movers no longer take a destination — `rebind(scope)` and `dropAndRebindAll()` move onto what `current()` answers now, so only chains other than the one in force can be retired; the unused `rebindAll` is gone. The same pass showed retirement stopped only scoped work: the connection test carries no scope, so a retired chain's services now refuse every call after its awaits and every batch at dispatch through a scope-independent `retired` gate. The sixth pass went one level deeper on both: the background's `transportOf()` captured the `active` promise when called, so a mover awaiting a superseded build still moved the sessions back onto it — the chain in force is now a small object of its own, `background/chain.ts`, whose `current()` answers with the build in force at the moment it resolves (looping until the build it awaited is still the one in force), unit-tested with a held build resolving after a newer one; and the request queue retries its stored thunk without re-entering the batch queue, so the retirement gate moved to the one place every attempt passes, the top of `translateItems`, non-retryable. The seventh pass closed the two gaps that remained: the router retired only chains its sessions led to, and a connection test has no session — the chain holder now remembers every build and `retireOthers(inForce)`, called by `dropAndRebindAll` after the move and before any await, retires all but the chain in force; and `current()` treated a superseded build's failure as its own — it now follows the build in force and fails the caller only when the build in force fails. Both pinned: a connection test's retry after its service was deleted, through `activate()` and `dropAndRebindAll()`, and a superseded build rejecting after a newer one succeeded. The eighth pass found the handler itself acting only on its own rebuild's success — a deletion whose rebuild failed after a newer one succeeded skipped the move and the retirement — so the action is now `background/engine-ready.ts`, which observes its rebuild and acts on the chain in force, tested at that level; and it measured the build set growing by one per configuration change, so `current()` now lets go of every superseded chain no session is on (`router.sessionsOn`) and no call is inside (`TranslationTransport.busy`), keeping the rest for retirement. The ninth pass showed the deletion's enforcement still riding on a successful rebuild — `current()` rejecting, or a superseded build that never settles, left the deleted service's chain alive — so `dropAndRebindAll` now retires and drains every chain and lets the sessions go unmarked when no chain is in force, and `current()` stops waiting for a build the moment it is superseded. Both pinned at the holder and at the engine-ready level, with a negative `reset` case. The tenth pass caught the handler still waiting for its own build before reaching `current()` — it now only starts the rebuild — and the failure path clearing the session table, which lost the scope → tab entries a later tab close needs to drain image recognition; the entries stay and only their chains go. The eleventh pass found the configuration watcher's rebuild chained onto the build in force, so a hung build blocked every later rebuild; the holder now compares a change with the configuration the chain was last asked to be built from and starts the rebuild independently — and, after the twelfth pass, a build from the stored configuration learns what it built from when it lands (a setting repaired after a fallback build rebuilds again), while a stale landing never overwrites a change that arrived meanwhile. The thirteenth pass showed the deletion still waiting for its replacement before retiring — a replacement hung in an engine probe, with no other rebuild coming, left the deleted service serving the sessions pinned to it — so `dropAndRebindAll` now works in three steps: the holder retires every chain but the build in force (every chain, while that build has not landed) and the router takes the retired chains off their sessions, all before the first await; the retired chains are drained; only then is the replacement awaited and bound to the sessions that lost their chain. A chain retired while a `forCall` awaited its build is never bound: the call waits for the replacement. The fourteenth pass showed retirement stopping only future dispatch: a request still in flight on a chain its session had left for a language pack came back with a result after the deletion, since the registry never marks a live session — retiring a chain now drains every scoped request queued or in flight on it (`TranslateService.cancelAll`), whichever session left it there. The fifteenth pass found two leaks past the drain: a task an unscoped subscriber shared survives it and completes, and a call split over two batches came back aborted with the finished batch as `partial`, which the live page renders — the service now has the last word after every batch has settled and returns aborted with nothing attached when the scope is dead or the chain retired; and off-chain services built per named call were outside `cancel` and `retire` — the transport keeps the ones with a call inside and drains them with the chain. The sixteenth pass closed the two windows left at the answer boundary: the fallback chain reattached an earlier engine's partial result to an aborted answer (it no longer does: a refusal carries nothing), and the cache write after the last check was one more wait during which a retirement or a drop went unseen (the check is repeated after it; what was written stays, sound translations under content-derived keys). The seventeenth pass found a dropped scope drained only from the chain it was bound to: a session moved on by a language pack leaves its earlier requests on a chain other sessions may still use, which is not retired — `drop` now drains the scope from every chain the holder still has (`cancelScope`), and the attempt-time gate refuses a batch whose every scope has died, drained or not.
