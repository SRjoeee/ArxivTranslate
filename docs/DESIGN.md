## 1. Goals and Scope

**Purpose**: A Chrome translation extension specifically for arXiv Experimental HTML pages (`https://arxiv.org/html/*`). Provide stable, reversible full-paper translation suitable for sustained reading while preserving paper structure, equations, code, links, and interactions.

**v1 scope [Decided]**
- Chrome only; `https://arxiv.org/html/*` only
- Three freely switchable reading modes: side-by-side (`side`), stacked bilingual (`stack`), and translation only (`only`); restore the original losslessly at any time
- Translation engines: LLM (OpenAI-compatible; see §8.1 for deferred Anthropic / Gemini implementations) + free engines (prefer Chrome's built-in Translator API, with `google-web` translateHtml as fallback; it replaces the originally planned gtx, see §8.1)
- Local cache: reopen the same paper and display translations immediately
- Translation style presets + glossary
- Image translation [Decided, 2026-09-07]: text in bitmap `img.ltx_graphics`; on Mac, invoke local Vision OCR through Native Messaging and overlay translations on the image (following Safari image translation, see §15)

**Non-goals [Deferred]**: Other sites, PDF, subtitles, TTS, vocabulary notebooks, Firefox/Safari support, Microsoft's free channel, DeepLX, and image-translation fallback on non-Mac platforms (§15.1). The architecture permits these, but none belongs in v1.

## 2. Core Conclusions

arXiv HTML is generated by LaTeXML. Its DOM is highly regular, with `ltx_*` classes on each element. Therefore:

1. **A general translator's heuristic DOM walker and site-rule subscription system are unnecessary**. Use deterministic LaTeXML rules for block segmentation and skipping, centralized in one versioned file.
2. **All three modes share one DOM; switching modes changes only one CSS attribute**. Translation nodes are always adjacent siblings of original blocks; the original subtrees are never modified. This is the basis of reversibility.
3. **Provider capability flags, not engine types, determine the two render paths**. The markup path translates whole blocks with placeholders; the runs path splits at non-translatable inline nodes. Phase 0 / Phase 3 measurements found that LLMs, Google translateHtml, and Chrome's built-in Translator all preserve placeholders, so every v1 provider defaults to markup; runs is the fallback after placeholder validation fails (RESEARCH.md §5 / §6). Each provider declares its path through `preservesMarkup`.

## 3. Terminology

| Term | Meaning |
|---|---|
| Block | A translation unit corresponding to a LaTeXML element, such as `.ltx_p`, `.ltx_title`, or `.ltx_caption` |
| Protected node | An inline node that must remain unchanged within a block: equations, citations, code, footnote markers, etc. |
| Placeholder | A tag replacing a protected node in model input: void `<x id="n"/>` or paired `<t id="n">…</t>` |
| Render path | `markup` (whole-block translation with placeholders) or `runs` (translate segments separated by protected nodes) |
| Mode | `side` / `stack` / `only`, controlled by `html[data-axt-mode]` |
| Provider | A translation-engine adapter implementing the common interface |
| Fixture | A real arXiv HTML page stored in the repository for testing |

Prefix convention: all extension-injected classes, data attributes, and CSS variables begin with `axt-` / `data-axt-` / `--axt-` respectively.

## 4. Overall Architecture

```
┌────────────────────────── content script (arxiv.org/html/*) ──────────────────────────┐
│                                                                                        │
│  extractor ──► scheduler ──► [cache?] ──► protector ──► (msg to background) ──► ...    │
│      │              │                         │                                        │
│   rules.ts    IntersectionObserver      serialize block                                │
│                                          → {text, slots}                               │
│                                                                                        │
│  ... ──► validator ──► rehydrator ──► renderer ──► DOM (sibling insert + CSS attr)      │
│                                            │                                           │
│                                         restore                                        │
└────────────────────────────────────────────────────────────────────────────────────────┘
                                   │ runtime message │
┌────────────────────────── background (service worker) ────────────────────────────────┐
│  request-queue + batch-queue (per-provider rate) ──► providers/* ──► cache (IndexedDB) │
│  health check + fallback chain                                                         │
└────────────────────────────────────────────────────────────────────────────────────────┘
┌────────────────────────── ui ─────────────────────────────────────────────────────────┐
│  popup: translate/restore, mode, engine, progress                                       │
│  options: providers, styles, glossary, cache management                                 │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

**Data flow (one block)**
1. `extractor` collects all Blocks according to the rules and assigns stable IDs (`data-axt-id`).
2. `scheduler` translates only blocks entering the viewport (plus the preload distance); blocks not reached by scrolling send no requests and consume no resources (§10, ported from Read Frog).
3. Check the cache first (cache and requests both live in background; content never touches IndexedDB); render hits directly.
4. On a miss, `protector` serializes the block into `{text, slots}`. The provider's `preservesMarkup` selects markup (whole block with placeholders) or runs (segments).
5. The ported background `request-queue` dispatches under per-provider token-bucket rates and concurrency limits; `batch-queue` accumulates batches (§8.0: requests run in background as of 2026-09-06). Failures trigger backoff, retries, 429 pauses, and fallback-provider switching when necessary.
6. `validator` checks placeholder integrity; failure → retry that block once → downgrade to runs.
7. `rehydrator` replaces placeholders with protected-node clones, stripping `id` attributes.
8. `renderer` inserts the translation as the original block's next sibling and writes to cache.
9. Mode switching and restoration bypass this pipeline; they are pure DOM/CSS operations.

### 4.1 Block Model [Decided]

```ts
interface Block {
  id: string        // data-axt-id: prefer the element's own ID (LaTeXML S3.p1.1 etc., stable across loads); otherwise axt-b<n> in document order; suffix duplicates
  kind: 'text' | 'table'
  el: Element       // Original node; never modify its subtree
  unit: string      // Matched rule ID (p / title / caption / note / bibitem / ack / keywords / table)
  cells?: { el: Element; numeric: boolean }[]   // table only: .ltx_td at any depth under the outermost .ltx_tabular, including nested tabular cells; numeric follows §5.3
}
```

- `extract(doc): Block[]` is read-only; only `markBlocks(blocks)` writes `data-axt-id`. **On page load, extract only**; mark only for `#axt-debug` or when translation starts. Leave the page untouched before translation. Popup statistics come from the content script's in-memory `Block[]`, not DOM queries.
- **Decouple traversal from classification**: DFS from the translation root. Use `classify(el)` to decide emission and descent separately: `skip` neither emits nor descends; `table` emits a table block without descending (internal `.ltx_p` belongs to cells, not standalone blocks); `unit` emits a text block if it contains translatable text and **continues descending** to find nested units; `protect` does not emit and normally does not descend, except rules with `descend: true`. `.ltx_note` is the first protect-but-descend case: void to the outer paragraph, but its `.ltx_note_content` must still become a separate block (of 56 fixture footnotes, 51 are inside `.ltx_p` and 3 inside `.ltx_caption`).
- Translatable text means text containing Unicode letters (`/\p{L}/u`) after excluding protect / skip subtrees. A `.ltx_p` containing only equations, numbers, or punctuation is not a block. Likewise, tables without any nonnumeric cell containing letters (empty layout tabulars inside paragraphs, equation-only tables) are not blocks.

## 5. Block Model and Rules

The selectors below were calibrated against 10 fixtures (RESEARCH.md §2; 99.97% coverage of body text nodes). All current live arXiv pages are generated by LaTeXML oxide 0.7.6. Rules live in `src/core/rules/latexml.ts`.

**Translation root [Decided]**: `article.ltx_document`. Extract nothing outside it: `.ltx_page_navbar` (TOC), arXiv-injected headers/footers, report-issue dialogs, and announcement bars. Individual selectors are unnecessary (RESEARCH.md §3.1).

### 5.1 Translation Units

| Selector | Description |
|---|---|
| `.ltx_p` | Body paragraph. `.ltx_para` is the container with an anchor ID; `.ltx_p` is the text block. This rule also covers paragraphs in abstracts, list items, theorems, and proofs; no separate rules (Phase 0 showed complete overlap, violating one rule per text node). Context such as abstract/theorem is only a provider hint. `.ltx_p` may be a `<span>` (inside tables or inline-blocks); extract and render by class, not tag name. |
| `.ltx_title` (excluding `.ltx_title_acknowledgements` / `.ltx_title_keywords`), `.ltx_subtitle` | Headings and subtitles at all levels. Internal `.ltx_tag` section numbers need void placeholders; theorem run-in headings ("Theorem 1.") are included. |
| `.ltx_caption` | Figure/table captions. Internal `.ltx_tag` ("Table 1: ", with nested `.ltx_text`) needs a void placeholder. |
| `.ltx_note_content` | Footnote body as a separate block. Footnotes are **nested blocks**: the entire `.ltx_note` (marker + `.ltx_note_outer > .ltx_note_content`) sits inside a paragraph, which treats it as void; the second `.ltx_note_mark` and `.ltx_note_type` inside `.ltx_note_content` are void. |
| (tables) | Handled separately: §5.3 TABLE rules treat the outermost `.ltx_tabular` as one unit. `.ltx_td` cells, including nested tabular cells, are segments within that block, not independent blocks; protector descends into cell `.ltx_p` during serialization (§5.3). |
| `.ltx_bibblock` | Segments within bibliography entries (authors / title / publication); `.ltx_bibitem` is the fallback for unsegmented entries, see 5.4. |
| `.ltx_acknowledgements` | Acknowledgements. Body text is bare text inside the container, which is itself the unit. Its run-in heading **is not a separate block** (revised 2026-09-04): otherwise the outer unit clones an English heading as void, yielding two English headings and one Chinese body (observed in 2609.00095). Without a separate block, the heading is paired, translated with the container, and restored in place. Same for `.ltx_keywords`. |
| `.ltx_keywords` | Keywords |
| `.ltx_personname` | Author names (since 2026-09-06, see §5.2). A `<span>` inside `.ltx_creator`; its translation is a sibling span after the original, naturally inline. `<sup>*</sup>` footnote markers in names are restored in place through paired placeholders. |
| `.ltx_contact`, `.ltx_role_affiliation`, `.ltx_role_address`, `.ltx_dates`, `.ltx_date` | Author affiliations, contact details, and dates. **Revised 2026-09-04**: change the author area from entirely skipped to translated by default, excluding only names and email addresses. The old policy missed acknowledgement-like author notes, such as “†Equal contribution. Listing order is random…” in *Attention Is All You Need*, inside `.ltx_creator > .ltx_note`. |
| `.ltx_role_dedicatory`, `.ltx_item`, `.ltx_marginpar`, `.ltx_indexentry`, `.ltx_cv_item_label`, `.ltx_cv_item_content`, `.ltx_cv_entry_date` | Dedications, bare list-item text, margin notes, index entries, and CV fields. Absent from downloaded real papers; guarded by `tests/fixtures/arxiv/synthetic-structures.html` (RESEARCH.md §2.12). |

### 5.2 Skip Rules (Entire Blocks)

| Selector | Description |
|---|---|
| `math`, `.ltx_Math` | MathML (inline equations become placeholders; block equations are skipped entirely) |
| `.ltx_equation`, `.ltx_equationgroup` | Display equations |
| `.ltx_tag` | Equation/section/figure/table numbers, list markers, code line numbers |
| `.ltx_listing`, `.ltx_listingline`, `.ltx_listing_data`, `.ltx_verbatim`, `pre`, `code` | Code, verbatim text, hidden code data. Algorithm boxes `figure.ltx_float.ltx_algorithm` / `.ltx_float_algorithm` contain `.ltx_listingline` and are covered here; their `.ltx_caption` translates normally. |
| `.ltx_text.ltx_font_typewriter` | Monospaced text (treated as code) |
| `.ltx_author_before`, `.ltx_author_after` | Separators between authors (“ and ”, “, ”); independent blocks would break the name list |
| `.ltx_classification` | MSC / ACM classification codes, e.g. “Primary: 11L07” |
| `.ltx_ERROR`, `.ltx_FATAL`, `.ltx_WARNING`, `.ltx_INFO` | LaTeXML conversion errors and notices, not paper content |
| `.ltx_pubnotes` | Publication metadata (ACM template CCS / DOI / journal / volume and issue) |
| `svg`, `.ltx_picture` | TikZ figures; no translatable text found, see §15.1 |
| `.ltx_ERROR` | LaTeXML conversion errors, also on failed-conversion “Untitled Document” pages; the extension must handle these quietly |
| `.ltx_page_navbar`, `.ltx_TOC` | Navigation and TOC, outside the translation root; listed only for renderer hiding |

- **Translate author names too** [Decided, 2026-09-06, user decision]: the rest of the author area (affiliations, contacts, dates, author notes) was enabled on 2026-09-04. Names alone remained excluded because transliteration could break citation lookup. That argument does not hold for a **bilingual** reader: stack and side show the original beside the translation, ready to copy for lookup. Only `only` hides it, an inherent tradeoff for all content in that mode, not a reason to single out names. Move `.ltx_personname` from skip rules to translation units.

  **Fixture measurements** (30 `.ltx_personname` across 12 papers): all are in `.ltx_creator` inside `article.ltx_document`; **none are in bibliographies**. Citation authors use `.ltx_bibblock`, enabled later the same day by §5.4. Structure is consistent: plain text, occasionally `<sup>*</sup>` footnote markers (paired placeholders). Some templates put two authors in one element (`Matías Blaña and Marcelo D. Mora`); translating the whole element is still correct.

  **Translation-quality measurements** (google-web, the worst case among free engines): 28 of 30 were normal transliterations, even recovering Chinese characters for names (`Yuan Xia` → 袁霞, `Haipeng Cai` → 蔡海鹏, `Fumihiro Imoto` → 井本文宏; exact characters are guesses). One failure: **`Brian Street` → 布莱恩街**, treating the surname as a common noun. Roughly 3% error, visibly wrong, with the original beside it. LLMs have title/abstract context and should do better. **No prompt change**: adding a constraint to every batch for a few names is not worthwhile, and bumping `PROMPT_VERSION` invalidates all caches; revisit only with real feedback.

  This rule requires a `RULES_VERSION` bump (in the cache key), now 0.7.0. Author separators `.ltx_author_before` / `.ltx_author_after` remain skipped: separate blocks would break the name list.

- **Do not translate `.ltx_contact_name` labels** [Decided, 2026-09-06, observed in testing]: LaTeXML generates labels such as `Affiliation: ` / `Email: ` / `E-mail ` for each `.ltx_contact`. **arXiv CSS sets them to `display: none`** (three live pages: computed display `none`, 0×0 boxes). These are template-generated, not author content; treat them as void.

  Otherwise there is a **visible consequence**: the hidden label is the only translatable text in an email `.ltx_contact` (the address is protected `mailto`), so the block qualifies for translation. Its translated “电子邮件：” label is also hidden by site CSS, leaving two identical address lines (reported by the user in 2507.00150). Affiliations do not duplicate because they contain real text, but translating invisible labels wastes work; google-web also rendered `Affiliation:` as “联系：”.

  Across 12 fixtures, all 43 `.ltx_contact_name` elements are within `.ltx_contact`. Twelve belong to `ltx_role_email` and have **no translatable text** after removing the label, so those blocks and duplicate lines disappear. The 29 `ltx_role_affiliation`, one `ltx_role_note`, and one `ltx_role_correspondent` still have real content; blocks remain, without translating a hidden label.

  **No general computed-style hidden-element filter**: extractor is pure DOM. Calling `getComputedStyle` for every candidate forces many style calculations on papers with hundreds of blocks, the same performance trap as the read-only measurements in §7.2. This is the only known hidden template label; putting it in `PROTECT_RULES` is cheaper and easier to audit. Bump `RULES_VERSION`, now 0.7.1.

- **Translate description-list terms too** [Decided, 2026-09-06, Codex #18]: LaTeXML puts the term from `\item[Compactness]` in `.ltx_tag.ltx_tag_item`. Protected tags leave `.ltx_item` with no own text, so it **never becomes a block** and the term never translates. Add `.ltx_tag_item` to `NAMED_TAGS`, using existing content checks: of 371 across 12 fixtures, only 8 contain words (`Markov categories:`, `CD categories:`, `Compactness.`, `RQ1`–`RQ5`); the other 363 are markers such as `(1)` and `•`, still void. google-web returned `RQ1` unchanged and translated `Markov categories:` as “马尔可夫分类：”, leaving identifiers intact. The snapshot delta is exactly these 8.
- ~~**Prefer semantic annotations when identifying bibliography author segments** (2026-09-06, Codex #18)~~ **Retired, 2026-09-06**: author segments are no longer skipped (§5.4); remove `isBibAuthorBlock` and this test. It solved the now-obsolete question of which segment contains authors: every segment translates.
- **Translate `.ltx_tag` containing environment names** [Decided, 2026-09-05, user feedback]: LaTeXML also puts theorem, figure, table, algorithm, and appendix **names** in `.ltx_tag`. Protecting all of `Definition 1.1.` as a number leaves Chinese readers with English. Distinguish subclasses: translate `ltx_tag_theorem` / `ltx_tag_figure` / `ltx_tag_table` / `ltx_tag_float` / `ltx_tag_appendix` / `ltx_tag_part` / `ltx_tag_chapter`; keep others (equation, section, subsection, ref, item, note) void. **Classes alone are insufficient**: subfigure panels also use `.ltx_tag_figure` for pure identifiers `(a)` `(b)` `(c)` (5 of 387 named tags, Codex #53); translating them can rewrite identifiers and break panel correspondence. Add `isNamedTag`: class must be listed and, **after removing parenthesized identifier-only groups**, contain at least two consecutive letters. Keep parentheses containing non-Roman words: `(Figure 1)` must not lose its environment name (Codex #53). Counting letters alone misses multi-letter Roman panel IDs `(ii)` `(iii)`; LaTeXML uses parentheses for identifiers, not environment names (`Definition 1.2 (Hall set)` retains Definition and still translates). Evidence: all 1241 `.ltx_tag` across 12 fixtures: 246 theorem tags all resemble “Definition 1”, 43 table tags “Table 1:”, 58 of 63 figure tags “Figure 1.”, 20 appendix tags “Appendix A”, 13 float tags “Algorithm 1”; conversely, only 13 of 344 equation tags contain letters (untouchable LaTeX labels such as `(let.lin)`), all letter-bearing tags among 439 section/subsection/ref tags are Roman numerals (II, III.1), and 54 note tags are footnote markers. **Never translate Roman-numbered labels**: google-gtx tests on 2026-09-05 (Codex #53) gave `Table IV:` → `表四：`, `Table X:` → `表十：`, `Part I` → `第一部分`, while references remain protected originals, breaking correspondence. Arabic numbers (`Table 4:` → `表 4：`), letter numbering (`Appendix A` → `附录A`), and parenthesized panels (`Figure 1(a)`) retained their identifiers. Google itself treats only I / V / X / L / M as numbers, and single C / D as letters; `ROMAN_ID` follows this. For compound numbering, inspect the first part (`Table IV.1` → 表四.1; both `IV.1` / `IV-A` are Roman), case-insensitively (LaTeX `\roman`: `Table iv:` → 表四：). `fixtures-stats.ts` must also count rule hits through `classify()`, not selectors, or allowed tags are incorrectly counted as protect/tag. Papers use consistent numbering styles, so readers will not see “表 4” and “Table IV” together. Fixture result: 368 of 387 named tags translate, 19 remain protected (5 panel labels + 13 Roman-numbered tables + `Part I`). Bump `RULES_VERSION` (cache key), now 0.6.2. Measured in 2609.04056v1: theorem-title blocks increased from 34 to 75; `Definition 1.2 (Hall set).` → `定义 1.2（大厅布置）。`

### 5.3 Tables [Decided]

Treat each **outermost** `.ltx_tabular` as one unit (15 of 58 fixture tabulars are outside `.ltx_table`, so that cannot be the root; 3 are nested in other tabulars and belong to outer cells; every `th` has `ltx_td`, so `.ltx_td` suffices; 239 `.ltx_td` are equation-alignment cells already skipped by `.ltx_equation`):
- side / stack: insert a translated clone **below** the original table; translate cells individually, copying numeric cells unchanged.
- only: hide the original, show the clone.
- No side-by-side translation within cells.
- **Cells are segments within a block; their translation units do not become separate blocks** (2026-09-05): extractor does not descend into tables. Protector must therefore descend through cell `.ltx_p` / headings as ordinary paired nodes, rather than treating them like void nested paragraph units. Otherwise an entire cell becomes one placeholder and loses all text (38 cells of Table 1 in 2410.00260; Codex #5).
- **Nested tabulars**: inner cells also belong to the outer block (`tableCells` selects any depth). Outer cells containing only a nested table have no own text and are copied as numeric cells. Before replacing each rendered cell, relocate it in the cloned table: an outer-cell translation includes a nested-table clone, so replace outer cells before inner cells.
- **Partial failure counts as failure**: if any cell fails, still display successful cells and count the failure so users distinguish partial from complete translation (Codex #9). Keep the original table **`translated`** and add `data-axt-partial` for a warning line; marking it `failed` would expose the original beside the partial clone in only mode (Codex #30).
- Numeric-cell classification (calibrated against 5,487 real cells in Phase 0, RESEARCH.md §2.6): copy unchanged if **visible text after excluding protect / skip subtrees** matches any condition below. Do not use raw `textContent`: MathML `annotation` adds TeX source; count `.ltx_p` text inside cells.
  - `^(?=.*\d)[\s\d.,+\-±×^%()/*eE−–—:;~<>=≤≥∼]+(\s*[a-zA-Zμ°%]{1,4})?$` — require a digit so E-initial words such as `ERROR` are not mistaken for exponent notation.
  - `^[✓✗✔✘–—−\-·×*]+$` — symbol-only cells.
  - `^N/A$`
  - Copy empty and equation-only cells directly; leave uppercase enum values (`TRUE` / `FALSE` / `UNKNOWN`) to the provider, with no special case.

### 5.4 Bibliography [Decided]

- Translate by default; allow disabling in settings.
- **Translate segments within entries** (revised 2026-09-04): LaTeXML splits entries into `.ltx_bibblock` segments (authors / title / publication, one line each). Use `.ltx_bibblock`, not the whole `.ltx_bibitem`, so each translation follows its corresponding line without duplicating the entire entry.
- **Translate author segments; treat all entry segments equally** [Decided, 2026-09-06, user decision]: `isBibAuthorBlock` previously skipped the first segment (author list) in multisegment entries. This caused a **visible inconsistency**: in single-segment styles (natbib, AMS, AAS, etc.), author names were already translated within the full citation. Seven of 12 fixtures use that form; five use multiple segments, so behavior differed between papers. §5.2 enabled paper author names the same day, leaving even less reason for this exclusion. Remove the skip; `.ltx_bibblock` rules handle it naturally. Delete `isBibAuthorBlock` and the `bib-authors` rule ID.

  **It hid more than names** (2609.03896, user feedback): positional detection **skipped the entire citation** in templates where the first segment is the full citation and the second is DOI. Twelve of 13 entries translated only the DOI line, leaving all citation content untouched; [3] alone translated because it had no DOI segment and thus only one segment. Codex #18 anticipated templates placing authors elsewhere and misclassifying titles; this is that risk, worse than expected: **all** content was skipped. Removing the positional assumption eliminates this template failure.

  **Measured cost** (12 fixtures): 285 additional blocks, 25609 characters, **+5.7% blocks / +2.2% characters** overall. Every added side-mode block **connects** to the translation root (snapshot numerator and denominator increase equally, `blockedBy` unchanged); no extra container overrides needed.

  **Translation-quality measurements** (google-web, worst-case free engine): standalone author segments are **more likely to be transliterated** than full citations. Google tends to preserve names in full citations (`W. Arendt 和 AFM ter Elst`, `Agha, G., Palmskog, K.:`), but transliterates separate segments (`史蒂文·阿兹特、齐格弗里德·拉斯托弗…`). Two specific defects: institutional authors treated as common words (`Anthropic.` → `人类学。`), and initials losing periods (`V. I.` → `VI`, `M. D.` → `MD`, resembling Roman numerals). **The LLM path does not have this problem**: the default instruction “Keep author names, journal names, conference names, dataset names, code identifiers and URLs in the original language” returns author segments unchanged.

  **These defects are known and accepted; do not add rules for them** [Decided, 2026-09-06, user decision]: translating names inherently loses accuracy; it is not a bug that rules can fix. Fixes drift into name dictionaries, engine-specific handling, or special prompts, imposing ongoing maintenance for one bibliography line. **The criterion is broadly recognizable, not exact**: recognizable transliteration or meaning suffices; readers use other mechanisms to locate the original.

  **Placeholders ensure traceability independently of name accuracy** (real pipeline, 2609.03001v1): an author segment reaches the engine as `<t id="1">L. A. Anchordoqui, …, and A. Westphal</t><t id="2"> (2026)</t>`. The year is `.ltx_bib_year`, **inside its own paired placeholder**; DOI/arXiv links (`.ltx_bib_external`) and cross-references are void (`Cited by: <x id="1"/>.`). The protocol requires unchanged placeholders; invalid translations cannot even enter cache (§8.2). Thus numbers, years, and links cannot be rewritten by any engine, and bilingual modes keep original names alongside. Neither route to the original depends on translated names.
- only mode no longer exempts entire entries (§7.4): untranslated author segments remain naturally visible; title/publication segments show only translations.
- DOI / URL values are `<a>` elements, automatically preserved through placeholders.
- Always add an LLM prompt instruction to preserve personal, journal, and conference names in the original language.

### 5.5 Rule Versioning

- Export `RULES_VERSION` from the rules file and include it in cache keys.
- Fixtures span fields and structures (`tests/fixtures/arxiv/README.md`), each recording its generator version. Every rule change must pass all fixture tests.
- arXiv regenerated all historical papers with LaTeXML oxide 0.7.6. No older output remains live, even at versioned URLs; **year is not a proxy for generator version**. Re-fetch fixtures when the generator changes (RESEARCH.md §1).
- If versions differ enough to require separate rules, use `rules/latexml-v1.ts`, `rules/latexml-v2.ts`, and detection; do not accumulate conditionals in one file.

### 5.6 Rule Interface and Precedence [Decided]

`src/core/rules/latexml.ts` exports only data tables and pure functions. Traversal belongs to extractor (§4.1):

- Tables: `UNIT_RULES` (§5.1), `TABLE_RULES = { root: '.ltx_tabular', cell: '.ltx_td' }` (§5.3, outermost root), `SKIP_RULES` (whole-block exclusions from §5.2), and `PROTECT_RULES` (§6.1 void nodes, optionally with `descend`). `math` appears only in PROTECT: `.ltx_equation` already skips display equations as blocks. Phase 2 protector adds paired-node rules (§6.1) to this file.
- Functions: `documentRoot(doc)`, `classify(el) → { kind: 'skip' | 'table' | 'unit' | 'protect'; rule: string } | null`, `isNumericCell(visibleText)`.
- **Precedence**: when multiple categories match, `skip > table > unit > protect`. A skip match inside a translation unit (e.g. paragraph `.ltx_ERROR`, one fixture case) acts as void for that unit.
- Increment `RULES_VERSION` whenever any table/function behavior changes; it is part of cache keys.

## 6. Placeholder Engine

Location: `src/core/protector/`. The project's hardest and most valuable module, implemented originally in Phase 2 (an explicit porting exception in CLAUDE.md). Integrity validation draws on Read Frog `html-attribute-markers.ts`.

### 6.1 Node Classification

| Type | Placeholder | Nodes |
|---|---|---|
| void | `<x id="n"/>` | Inline `math`, `.ltx_ref` (including `.ltx_ref_tag`), `.ltx_cite`, `.ltx_tag`, `code`, `.ltx_font_typewriter`, entire `.ltx_note` (body is a separate block), `.ltx_note_mark`, `.ltx_note_type`, `.ltx_contact_name`, inline images, `svg`, `br`. **Must be in `latexml.ts` as `PROTECT_RULES`**: Phase 0 found that §5.2 skip rules alone let `.ltx_ref` / `.ltx_cite` / `.ltx_note_mark` count as paragraph text (3,500+ fixture elements, RESEARCH.md §2.5). |
| paired | `<t id="n">…</t>` | Text-bearing `a`, `.ltx_text.ltx_font_italic/bold/...`, `em`, `strong`, other `span` with translatable text |
| text | Appears directly in text | Text nodes |

### 6.2 Serialization

```ts
interface ProtectedBlock {
  blockId: string
  text: string                       // Text with placeholders
  slots: Map<number, Node>           // id → original node reference
  paired: Set<number>                // IDs of paired placeholders
}
```

- Placeholder IDs start at 1 within each block.
- Preserve `&nbsp;` and thin spaces (`\u2009`) beside equations; do not trim internal whitespace during serialization.
- Above the void-placeholder threshold (initially 40), treat the block as equation-dense: still use markup, but batch it separately.

### 6.3 Validation

A translation fails unless:
- Its void-ID set exactly matches the original, each occurring once.
- Paired tags are matched and legally nested.
- No IDs absent from the original appear.

Failure handling: retry the block once (append emphasis that placeholders must remain unchanged) → downgrade to runs if still invalid → if runs also fails, mark the block untranslated and show it in the UI.

### 6.4 Rehydration

- Replace placeholders with **clones** of `slots` nodes (`cloneNode(true)`).
- Strip all `id` attributes throughout cloned subtrees to avoid duplicate IDs breaking anchors; retain `href`.
- All modes use clones; originals never move (only hides original blocks, rather than relocating nodes).

### 6.5 Runs Path

- **Preserve functional elements whole** [Decided, 2026-09-05, issue #44]: losing style remains readable; losing links removes interaction. Fallback must not turn clickable content into plain text. Treat `a[href]` (`FUNCTIONAL_INLINE`) as void here: retain the whole node and do not translate its text. When skipping, count nested `</t>` depth so an inner closing tag cannot end the skip early. **Measured: zero such links in 4221 translation blocks across 12 fixtures**; arXiv body links are `.ltx_ref` cross-references or mailto, already protected by rules. This is a structural guarantee that fallback loses style, not behavior, rather than a fix for an observed failure; it also protects other paper sites in v2.

Used by `preservesMarkup: false` engines and as fallback after markup validation fails. All three v1 free engines preserved placeholders in tests (RESEARCH.md §5 / §6), so runs is mainly a fallback, but still must be implemented:
- Split blocks into text segments at void nodes (merge paired-node text into its surrounding segment, losing paired styling).
- Translate segments separately, reassemble in order, and clone void nodes back into place.
- Known cost: equation-interrupted sentences translate as separate fragments; acceptable degradation.
- Cache keys include `renderPath`; the two paths do not reuse each other's translations.

## 7. Three-Mode Rendering

Location: `src/core/renderer/` + `src/styles/modes.css`.

### 7.1 DOM Invariants [Decided]

1. A translation is the original block's **next sibling**, with the same tag, **original classes plus `axt-t`** (`p.ltx_p` → `p.ltx_p.axt-t`), and `data-axt-for="<blockId>"`. Copy classes to retain site styling: main-title alignment/size, bibliography grid columns, and heading sizes depend on `ltx_*` classes (2026-09-03: without them, the main title shifted left and `li.axt-t` occupied the bibliography's 12em first column with bullets). Strip `id` and all `data-axt-*` from every element cloned into translations, including tables and rehydrated `.ltx_note`.
2. Original nodes may only receive `data-axt-id`, `data-axt-state`, and `data-axt-inline`; **never modify their subtrees**.
3. Global state lives only on `<html>`: `data-axt-on`, `data-axt-mode="side|stack|only"`.
4. Restoration removes all `.axt-t` **and `.axt-img`** (image overlays, §15.2), all `data-axt-*` attributes, and injected `<style>`. The resulting DOM must equal the pre-translation DOM node for node (test-enforced).

### 7.2 side (Side-by-Side)

- Core technique [rewritten 2026-09-04; revised 2026-09-05]: structural pairing. **Every block marked `data-axt-id` occupies the left column, reserving the right for translation**. Unmarked nodes immediately followed by `.axt-t` (mirrored originals) also occupy the left. All block markers are written at session start (§10), so the page becomes two columns at once and does not shift horizontally afterward. Previously only `.axt-t` siblings counted: blocks beyond preload distance stayed full-width, then shrank left as scrolling approached them, producing horizontal jumps (user feedback). Layout depends on session membership, not translation arrival. Define the two column lines **once on `.ltx_document`**; all other containers span both columns and inherit `grid-template-columns: subgrid`. Children default to full-width; paired originals go left and `.axt-t` right:

  ```css
  container > *              { grid-column: 1 / -1 }
  container > :has(+ .axt-t) { grid-column: 1 }
  container > .axt-t         { grid-column: 2 }
  ```

  This pairs headings, captions, and bibliography segments without individual rules. No wrappers; anchor IDs remain intact.

  Pipeline now reports DOM-changed blocks per batch (`RunOptions.onRendered`, synchronous with `onProgress` but outside serializable `Progress`). A coalescer accumulates a dirty set (`createCoalescer<T>`; no-argument `schedule()` requests a full pass). `renderer/prep.ts` derives each dirty root: block parent ∪ parent of every ancestor block (inner footnotes may arrive first) ∪ parent of the outermost containing `figure` (`splitFigures` scans descendants only). Run stages in stage-major order over these roots. **Invalidation table**: `localizeNotes` / `splitFigures` / `alignPairMargins` use dirty roots; `fitTables` likewise, but full scan on width change (width-invalidated cache); `createMirrors` **once per session**, on the first full pass after block marking (otherwise whole blocks clone, issue #67); reentering side runs full prep because leaving it clears margin alignment. ### 7.3 stack (Stacked Bilingual)

Default layout: translations immediately follow originals. No extra layout CSS, only translation styling.

- **Short headings share a line** [Decided]: for `title` units other than the document title with visible text ≤60 characters, add `data-axt-inline` to original and translation. CSS sets both to `display: inline-block` (retaining vertical heading margins) and gives the translation 0.5em start margin, producing “Abstract 摘要” on one line. Reference projects achieve this by inserting translations inside originals; our subtree invariant requires attributes + CSS. Keep the main title stacked: its `text-align: center` no longer centers it when inline.

  **Do not restrict this rule by mode; it already has no effect in side** [Measured, 2026-09-07, issue #68 / Codex #13]: side containers are `display: grid`, and headings are direct grid children; **grid items always blockify**, overriding inline-block behavior. All 69 short headings in 2609.00246 are `inline-block` in stack and share a line (“Abstract” 0–90, “摘要” 90–157). In side, **zero** remain inline-block: all become block, original 0–648 left, translation 672–1320 right, same row. Adding `html[data-axt-mode="stack"]` changes no output and adds a mode check to maintain; do not add it. `modes.css` already has a dedicated side `[data-axt-inline]` translation rule clearing the 0.5em start margin, confirming intent. `e2e:layout` asserts block display, left/right placement, and equal rows.

- **Write all block markers synchronously, without slicing** [Decided, 2026-09-06, issue #67]: side-prep `needsMirror` gates inspect `data-axt-id`; they cannot distinguish not-yet-marked translation units from permanently static content. Sliced marking lets prep run midway and clone whole `.ltx_para` / `.ltx_proof` / `.ltx_theorem` containers right, leaving extra English once inner translations arrive. happy-dom reproductions with prep at 25% / 50% / 75% yielded 36 cases in 2312.17141, 23 in 2609.04056, and 87 in 2609.00245; after marking completed, all were zero.

  **This path is unreachable in the measured browser** (2312.17141, Chromium): marking 828 blocks in slices takes **2ms**, while first prep runs at **1140ms** (150ms debounce + progress timing), a 570× gap. This turns an **implicit timing assumption** into a structural guarantee, not a fix for an observed browser bug. Without documenting it, nobody knows safety depends on marking being two orders of magnitude faster than debounce.

  Slicing originally guarded against hundreds of attribute writes freezing the page (Read Frog #1881), but measurements refute the premise: the loop writes attributes without layout reads; Chromium marked 979 blocks in **1.2ms**, with 0ms subsequent forced layout. Synchronous marking also removes the `halted()` race: no intermediate `await` means restore cannot interleave. State attributes (`data-axt-state`, including pending-spinner styles) remain sliced; they do not affect prep decisions.

- **Visibility thresholds must apply without locking out oversized blocks** [Decided, 2026-09-06, Codex #32 / #36]: `IntersectionObserver.isIntersecting` means intersection ratio **>0**, not ≥threshold. Browsers immediately send an initial observation, so a 10%-visible block still reports intersecting at `threshold=0.5`; callback code must compare `intersectionRatio` itself.

  Conversely, a **block taller than root (viewport + top/bottom margins) cannot reach a high threshold**; maximum ratio is root height ÷ element height. Since giant tables are explicitly not split (§7.2), `threshold=1` could prevent a table from ever translating. Clamp effective threshold to the attainable maximum. Register **5% interval thresholds** (`observerThresholds`, plus the user's exact configured value if off-grid). Registered thresholds determine when callbacks occur; callback code decides eligibility. `[0, threshold]` is insufficient, as below.

- **Do not display exact-match translations twice** [Decided, 2026-09-06, Codex #74]: the default “Keep author names, journal names, conference names … in the original language” instruction returns name-only bibliography segments unchanged, but unconditional sibling insertion in `renderText` duplicated each author line in stack. This applies to any identical translation. Compare after whitespace normalization, mark `data-axt-identity` on matches, and **hide the copy with stack-mode CSS**. Keep it in side to fill the right column and in only because the original is hidden.

- **Registered visibility points must cover clamped thresholds** [Revised, 2026-09-06, Codex #76]: the previous `[0, threshold]` registration only triggered on those values. Oversized blocks whose maximum is below threshold cross 0 and never trigger again, so their clamped condition **never passes**. Chromium test: element 3000px, root 900px, max 0.3, threshold 1; `[0, 1]` produced only one callback at 0.267; a 5% grid reached 0.3.

  **Eligibility must use the same grid** (Codex #81, remaining form of the same bug): callbacks report the **actual ratio at that moment**, so a maximum between registered points may never be reported exactly. A 2700px element / 900px root has max 0.3333, between 0.30 / 0.35; scrolling by 10px gave 0.30000001 on crossing 0.30, then no further callbacks. Comparing to 0.3333 never passes. When the configured value is unreachable, **round the clamped threshold down to a registered point**, plus 1e-6 floating-point tolerance. Fake observers call callbacks directly and cannot reproduce browser semantics; both cases are guarded in `pnpm e2e:layout`.

### 7.4b Accessibility: Our Responsibility [Decided, 2026-09-06]

A colleague's DevTools audit of the rendered page reported four issues: skipped heading levels (`h6.ltx_title`), missing `<main>`, unlabeled `<object>`, and tables using `<td>` without `<th>`. **None was introduced by us**: the same 2410.00260 without the extension already had one `h6`, one `h5`, zero `main` but one `div.ltx_page_main`, and 8 of 12 tables without `th`. All originate in LaTeXML / ar5iv.

**We should not repair them either**: changing heading levels, adding `role="main"`, labeling `<object>`, or converting headers to `<th>` modifies the original document, violating §7.1 (original nodes may only gain `data-axt-*`; restore must be node-for-node equal). We assist reading on someone else's page, not repair it. Raise changes upstream with arXiv / LaTeXML. Bilingual rendering duplicates these elements (`h6` 1 → 2), an inherent comparison-reading cost.

**What is ours, and was missed by that audit, is translation-node attributes**:

- **Translations require `lang`**: `<html lang>` describes the original (`en` on arXiv), while we insert Chinese. Without a label, screen readers use English speech for Chinese; all 14 measured translation nodes inherited `lang="en"`. At `enable()`, store BCP-47 translation language from `toBcp47(target)` on `<html data-axt-lang>` (global state belongs here, §7.1); `renderText` sets each translation's `lang`. **Never change `<html lang>`**, which would also mislabel English originals.
- **Hide decorative copies from screen readers**: side mirrors (`.axt-mirror`) duplicate left-column content without translation, so otherwise it is read twice. Loading rings (`.axt-spinner`) are likewise decorative; popup progress communicates waiting. Give both `aria-hidden="true"` **and `inert`** [added 2026-09-07, A/B audit on 2401.00596]: `aria-hidden` does not prevent Tab focus. Bibliography mirrors contain DOI/arXiv links, so keyboard users can enter silent decorative copies (axe `aria-hidden-focus`). `inert` controls focus and the accessibility tree, supported since Chrome 102, below our 131 minimum. These are **our injected nodes**, so added attributes do not violate §7.1. Real translations remain accessible because they convey information.

**Attribution is automated** [Decided, 2026-09-07, issue #72]: repeatedly comparing against the extension-free page by hand invites the same misunderstanding in any injection-based extension audit. `tests/e2e/a11y.mjs` (`pnpm e2e:a11y`) runs axe twice on the same paper; the original page is baseline, and only the difference gates results.

The difficulty is **computing the difference**: inserted siblings shift `:nth-child`, making raw axe selectors yield false positives. Give each violation a cross-run comparable key. For injected content, follow `data-axt-for` to the original block and a relative path to the **corresponding original element**, using its key. Host elements use their own key: `#id` when available, otherwise ancestor tags and same-tag sibling indexes **excluding `.axt-*`**. Thus `h6` 1 → 2 is inherited automatically, while translation-specific problems absent on originals (missing `lang`, low contrast) have no baseline violation key and remain reported.

Compare two categories by rule ID, rather than element:

- **Document-level rules** (`region` / `landmark-*` / `page-has-heading-one` / `bypass`): axe reports the outermost element outside landmarks; translations change which element it reports. The cause is a host page with no landmarks; adding them modifies the document, disallowed by §7.1.
- **`scrollable-region-focusable`**: axe checks for `tabindex` on scroll containers, but Chrome 127+ natively gives sequential focus to scroll containers without focusable children; our minimum is 131. On 2026-09-07, all six side-mode scroll containers in Chrome 153 passed focus → Shift+Tab → Tab round trips, **6/6**. Three are original nodes (`#alg1.4`, `#S2.T1.2`, `#S2.F2`), where adding `tabindex` also violates §7.1. **Still print** this rule; do not fail on it.

First measurements, 2026-09-07 (2410.00260, Chrome 153): baseline 45 violations / 6 categories (`empty-table-header`, `heading-order`, `landmark-*`, `region`); extension stack 56, side 544, only 399; **all three differences empty**. Mutation check: build with low-contrast `.axt-t` `color`; stack gained 441 and side 569 `color-contrast` violations, all attributed to `translation`. Mapping does not misclassify translation defects as inherited.

### 7.5 Translation Styles [Decided, implemented 2026-09-05]

- Translation nodes copy original classes (§7.1), inheriting corresponding site fonts, sizes, line height, alignment, and grid placement. Presets **add decoration only**. Injected `<style>` follows site styles; **do not** put `font: inherit` or similar equal-specificity overrides on `.axt-t` (measured: abstract heading 1.4rem and bibliography fonts became parent defaults). `presets.test.ts` guards against `font` / `display` / `margin` / `line-height` / `width` in presets via regex.
- **Port all KISS presets; remove unused ones later** [Decided, 2026-09-05, user decision, replacing the same-day four-preset draft]: the initial selection kept four because papers require sustained reading and animation distracts. After seeing it, the user requested all presets first, then removal based on actual use. This follows the criterion of porting unless there is a negative impact: independent presets, each only a few CSS lines, impose no extra burden. There are 20 presets plus a custom slot, grouped as basic (`none` / `muted` / `green`), underlines (`underline` / `dotted` / `dashed` / `dashed-bold` / `wavy` / `wavy-bold`), borders (`quote` / `box` / `box-dashed`), backgrounds (`marker` / `marker-gradient` / `highlight` / `tint`), effects (`gradient` / `colorful` / `glow` / `blink` / `blur`). `green` and `tint` come from Read Frog `custom-translation-node.css`; green is its default `oklch(0.693 0.17 162.48)`, easiest to distinguish in bilingual reading. `blur` reveals on hover for self-testing/memorization. **Keep only compositor animations** [Decided, 2026-09-05, measured, Codex #52]: with 600 translation blocks over 4 seconds, breathing `glow` `text-shadow` consumed **1028ms** main-thread tasks (549 style recalculation, 144 layout), moving `gradient` `background-position` **573ms**, versus 2ms static. Sustained reading does not justify a quarter-core decoration load. Make both **static**, retaining gradient fill/glow; both returned to 1ms. `blink` changes compositor `opacity`, with no style recalculation (3ms measured); retain animation and `prefers-reduced-motion: reduce`. FPS is not a useful measure: all four presets held 60fps before the change, fitting frame budgets while continuously burning CPU. Use CDP `TaskDuration`.
- **Draw underlines explicitly on atomic inline elements** [Decided, 2026-09-05, user-reported gaps]: CSS `text-decoration` **does not propagate into inline-block, inline-table, or MathML atomic boxes**, so equations/inline boxes interrupt lines (`.axt-t math` computed `text-decoration-line: none`). `text-decoration: inherit` also fails because `text-decoration-line` is noninherited; one intervening ordinary span breaks it (same measurement). Underline presets set only `--axt-deco`; a shared rule applies it to `.axt-t` and `.axt-t :is(math, .ltx_inline-block, svg, img)`. Explicitly list **only underline preset IDs**, never wildcard `html[data-axt-style]`, which would set `text-decoration: none` on other presets and erase site link/reference decoration. All 51 translated inline equations in 2609.04056v1 received `underline/dashed`.
- **Style and mode share the same state level**: `<html data-axt-style>` sits beside `data-axt-mode`; switching changes one attribute without DOM changes.
- **Decorate only real translations**: `.axt-pending` rings and `.axt-error` retry widgets also carry `.axt-t` for side pairing, but are not translations. So do structural `.axt-mirror` equation/image copies and `.axt-split` whole-figure copies; blur would obscure mirrored equations and other presets decorate wrappers twice. Use `.axt-t:not(.axt-pending, .axt-error, .axt-mirror, .axt-split)` for all presets; real nested translations still match. - **Document titles/subtitles never share a line with translations** [Decided, 2026-09-06, Codex #13]: `.ltx_subtitle`, like `.ltx_title_document`, is centered frontmatter; inline-block shrinks it and aligns it left. ### 8.0 Requests Run in Background [Decided, revised 2026-09-06; supersedes the 2026-09-04 content-script decision]

Provider `fetch`, engine chain, queues, and cache **all run in background**. Content scripts send only `axt:translate` / `axt:cancel-scope` / `axt:provider-status`. Options connection tests and page translation thus share one `TranslationTransport`, preventing connection-test success with page-translation failure (issue #42).

Measurements on 2026-09-05 / 06 refuted both reasons for moving requests to content on 2026-09-04:

- **“Workers suspend while waiting; cold-start messages take tens of seconds” did not hold**. RESEARCH §6.7: after three 40s idle periods (beyond MV3's 30s idle timeout), real Chrome reloads had content → background round trips of 77–81ms; the 1.5s cache budget never expired, and popup Translate was immediately available after cold start. §6.5's 6.7–77s could not be reproduced in current code (those measurements predated removing full-cache scans on writes). §6.8 separately tested survival while awaiting a response, the actual §6.5 concern: a background-forwarded request delayed 90s still returned, **without keepalive**, ports, or heartbeats.
- **“Content can make cross-origin requests” holds only when the endpoint provides CORS headers**. RESEARCH §6.7: content fetch uses the **page origin** and preflights, failing `TypeError: Failed to fetch` without CORS headers. Background fetch uses extension origin, no preflight, and reaches both endpoint types. `host_permissions` does not remove this Chrome-85+ restriction. **Local Network Access** is stricter: an `https://arxiv.org` page **cannot reach local endpoints at all**; requests never leave the browser, making the explicitly supported Ollama (`http://localhost:11434`) unreachable from content. This was initially called mixed content, an incorrect attribution (Codex #57): loopback is potentially trustworthy, so HTTPS-page requests to it are not mixed content. The §6.7 control also blocked `https://127.0.0.1`; **certificates do not bypass the gate**, only background works.
- Also correct §6.5's reference-project claim: Read Frog **executes requests in background** too (`entrypoints/background/translation-queues.ts` queues and calls models). The earlier claim that it fetches in content was disproved against the reference snapshot.

After moving back:

- API keys no longer enter content-script isolated-world memory, improving separation (the rest of hard rule 7 is unchanged).
- Content no longer bundles three providers and AI SDK: 428.95kB → 152.47kB, reducing parsing on every arXiv HTML load.
- Two fewer message round trips per batch: background accesses Dexie directly instead of `axt:cache-get` / `axt:cache-put`.
- **Direct evidence**: `pnpm e2e:local-endpoint` starts an `http://127.0.0.1` OpenAI-compatible endpoint with **no CORS headers and 405 for every preflight**, translating a real arXiv page. Run identical e2e before/after with `AXT_EXT_DIR` pointing to each build:

  | | Options connection test | Page translations from local endpoint | Page-translation requests received by endpoint | Requests from page itself |
  |---|---|---|---|---|
  | Before move (main) | Pass | **0 / 12 segments** | **0** | **21** (all blocked by Local Network Access) |
  | After move | Pass | 12 / 12 segments | 7 | 0 |

  The before column reproduces issue #42: **same endpoint passes testing but fails page translation**, **silently**, because fallback to google-web still produces fluent Chinese. Users cannot tell their endpoint was never used. Therefore e2e asserts the local endpoint's translation prefix, not merely Chinese output.

```ts
/** Translation execution-location abstraction (src/providers/transport.ts). Two implementations, one interface. */
export interface TranslationTransport {
  translate(call: TranslateCall): Promise<TranslateMessageResponse>
  /** Cancel queued/in-flight requests for this scope; return the canceled count. */
  cancel(scope: string): Promise<number>
  status(): Promise<ProviderStatus>
}
```

- `createLocalTransport(config)` (background): `buildChain` → per-engine `createTranslateService` sharing local Dexie cache port → `createFallbackService` composition.
- `createMessageTransport()` (content / options, `src/shared/transport.ts`): one runtime message per method. **Separate file** for bundle size: `transport.ts` imports three providers and AI SDK, while content should receive only the proxy.
- **Cancellation is best effort**: `axt:cancel-scope` reaches the **current** chain. If configuration or `axt:engine-ready` rebuilt it, in-flight requests on the old chain cannot be canceled; content rejects their results by session ID (`run.ts` `halted()`), wasting a few requests without DOM writes. Not actively canceling old chains is intentional: failing all in-flight batches on configuration changes would show a screen full of retry buttons, worse than letting them finish.
- **Explicit-provider calls bypass fallback**: if `TranslateCall.providerId` is set, dispatch directly to that step's service. Options “Test connection” asks whether the configured endpoint works; reporting free-fallback success would repeat issue #42 in reverse, misleading users about their key while pages use Google. Report an error if the named engine is absent; never substitute silently (`pnpm e2e` guard).

### 8.2 LLM Call Contract

- Use AI SDK 7 `generateText` + `Output.object({ schema })` (`generateObject` is superseded) and zod `{ segments: { id, text }[] }`; let SDK validate structure. Set SDK `maxRetries: 0`; the ported retry policy owns retries.
- **Two prompt layers** [Decided, 2026-09-05]: ported Read Frog `prompt-library.ts` controls **how to translate**: variables `{{targetLanguage}}` `{{input}}` `{{paperTitle}}` `{{abstract}}` `{{sectionTitle}}` `{{glossary}}`, built-ins `default` / `precision-rewrite`, custom `patterns`, `promptId` selection with default fallback. `prompt.ts` appends a **protocol block** (JSON segments, placeholder rules, output shape) after every system prompt, governing transport; custom prompts cannot change it. Our AI SDK structured-output + zod protocol is more robust than Read Frog text-delimiter batching; keep it. Read Frog generates web summaries with another LLM call; papers already supply abstracts.
- **Put metadata in the user message inside `<document_metadata>`, explicitly untrusted reference data**: Read Frog puts it in system prompts. Author-written titles/abstracts, especially prompt-injection papers, may contain instruction-like text that would gain system-level authority (Codex #28). The protocol declares both metadata and segments to be data, not instructions.
- **Send glossary with every batch** [Decided, 2026-09-05]: configuration `glossary: { term, translation }[]` since v6; options text editor uses one entry/line, comma or tab delimiters, `#` comments. `providers/glossary.ts` parses/deduplicates (KISS `parseAITerms` shape plus tabs, comments, and line-numbered errors instead of silent dropping). **Semicolons do not separate records**: KISS splits `a, 甲; b, 乙`, but legitimate translations can contain semicolons (`kernel, 核; 统计学中称核函数`); splitting silently corrupts one valid mapping into unrelated records (Codex #52). **200 entries maximum**: every batch carries them, roughly 2–3KB / 700 tokens, comparable to an abstract. Larger glossaries need per-paragraph matching, deferred to v2. Per-entry limits: source 120 characters, translation 200; total 6000, preventing an entire pasted document being accepted as one entry. Define limits in `GLOSSARY_LIMITS`; **migrations must run `normalizeGlossary`**, as v6 had no limits and blindly copying into v7 makes `getConfig()` reject the whole configuration and revert to defaults, appearing to lose keys, engines, and prompts (Codex #52). **Automatically append `{{glossary}}` when custom prompts omit it**, like `{{input}}` / `{{targetLanguage}}`; new templates otherwise omit it and configured glossaries have no effect. This changes model input, so `PROMPT_VERSION` becomes 4 (hard rule 6). **Omit the field for empty glossaries**, rather than sending `[]`: `contextPayload` keys empty and absent identically, preserving existing cache on feature introduction while changed translations invalidate affected entries. LLM-only: free engines ignore context; `translate-service` includes context in cache keys only when `provider.promptKey` exists.
- **Include paper context in every batch**: `paperContext()` extracts title/abstract once at page load (remove “Abstract” heading, skip TeX source in MathML `<annotation>`, cap at 1200 characters). Extract before translation or previous output contaminates context. Pass via `RunOptions.context` into every `request.context`, merged with batch `sectionTitle`; about 300 input tokens per batch.
- Version prompts with `PROMPT_VERSION` (2 for prompt library, 3 for English language names in `{{targetLanguage}}`) in cache keys. Also include **`promptKey` identity** (built-in ID; custom full text with both parts separately encoded) and **raw context** (title / abstract / section / glossary, structured serialization; omitted for context-free engines) in SHA-256 payload. A changed prompt or the same segment in another paper must miss cache. **Do not first compress to a 32-bit hash**: outer SHA-256 cannot distinguish DJB2 collisions (Codex #28 examples `19k04n01vcr73f` / `1efm0uaep90s9`). Configuration v1→v2 adds `prompts` and retains API keys.
- **Use English language names in `{{targetLanguage}}`, not codes** [Decided, 2026-09-05, following Read Frog `translate-text.ts`]: “professional zh-CN native translator” is worse than “Simplified Mandarin Chinese”. Names come from `config/languages.ts`, ported from `@read-frog/definitions` ISO 639-3 table; unknown codes pass through.
- **Prompt and thinking controls** (cleanup item 3, 2026-09-05): options manages prompts (built-ins read-only with duplicate/customize; custom create/edit/delete; variable buttons insert at cursor; JSON import/export compatible with Read Frog) and thinking toggle (unknown endpoints show that no field is sent). Popup prompt selection persists immediately and applies next run. Read Frog UI depends on base-ui, jotai, Tailwind, and its i18n; importing an entire stack for roughly a dozen fields is not worthwhile. Port logic by file (`prompt-file.ts`), rewrite UI in existing plain React. Read Frog now uses AI SDK `reasoning` levels none…xhigh; ours retains KISS-style endpoint-specific toggle fields, revisiting levels after SDK verification.
- **Batch by capacity, not engine kind** [Decided, 2026-09-06, observed]: `BatchQueue` originally existed only for `kind: 'llm'`, copied from Read Frog `shouldUseBatchQueue`. That assumes **single-item free engines**, unlike ours: translateHtml accepts 150 (RESEARCH §6.6), built-in declares 20. Copying the condition discarded free engines' main advantage. Every provider now gets `BatchQueue`; `maxItemsPerBatch` set to 1 naturally degenerates to one request/item, removing the extra `enqueueWhole` path.
- **Exclude context from batch keys for engines that ignore it**: `batchKey` previously included `request.context` unconditionally, including the `sectionTitle` supplied by `run.ts`. This split free-engine batches at every section and effectively disabling batching. Cache keys already used `context: provider.promptKey ? request.context : undefined`; align batch keys.
- **One browser-wide chain and queue set** [Decided, 2026-09-06, issue #43]: limits apply per API key, not tab; separate tab queues create tabs ×8 actual concurrency and invite 429. Keep the chain in background; rebuild only when **chain-changing fields** change (`provider` / `openaiCompat` / `prompts` / `targetLanguage` / `fallback`). Content persists each mode switch, often during translation; rebuilding indiscriminately would reset token buckets and fallback history. `CHAIN_CONFIG_FIELDS` / `VOLATILE_CONFIG_FIELDS` classify fields, with a test requiring every field explicitly classified. Two simultaneous papers sharing throughput is an intentional tradeoff.
- Split batches by section (headings start batches); cap at `maxBatchChars` (Read Frog defaults: 1000 characters / 4 segments, token bucket 8 requests/s, burst 20, 100ms accumulation per batch key for small concurrent batches and fast first screen). Include `sectionTitle`; isolate equation-dense blocks; one whole-table batch (`renderTable` needs all cells together).
- Batch failure: split in half and retry → single block → mark failed.

- **Bound each request; timeouts are retryable** [Decided, 2026-09-05; moved to ported request-queue the same day]: without limits, one hung connection leaves a paper translating forever. Real API, 2312.17527: 152/153 blocks completed; the last (1600 characters, 32 placeholders) waited 220s, never logged `translation done`, popup kept spinning. Timeout scales as 20s +15ms/character, capped at 120s (Read Frog constants: 1000-character batch 35s, that 1600-character block 44s). Request-queue uses `Promise.race` and aborts in-flight work; timeout still resolves even if provider ignores signal. Classify as retry-policy `timeout`, retry twice by default, then fail only that block.

### 8.3 Free-Engine Contract

- **Two independent throttles: concurrency limits in-flight requests; token buckets limit requests/second** [Decided, 2026-09-06, observed]. `google-web` originally used p-queue `concurrency: 2`, with no rate limit. Porting `RequestQueue` on 2026-09-05 mistakenly made it `rateLimit: { rate: 2 }`. Google median latency is **63ms**, but the bucket forced 500ms spacing. `TranslationProvider` now separately declares `maxConcurrent`; Google returns to `maxConcurrent: 2`, with `rate: 20 / capacity: 8` **only guarding pathological bursts**. An intermediate `rate: 4` immediately bottlenecked 24 requests at 5.3s; rate must not constrain normal traffic.

  Combined measurements of three defects (2410.00260, google-web, fresh empty cache, scrolling screen by screen):

  | | Before | After |
  |---|---|---|
  | Whole-paper duration | 31 615 ms / 213 blocks (**148 ms/block**) | 2 959 ms / 190 blocks (**15.6 ms/block**) |
  | Requests | 65 | **21** |
  | Segments/request | Median 2, mean 4.2 | Median 11, mean 11.2 |
  | Request spacing | Median 500 ms (= 1/rate) | — |
  | HTTP status | 200 | 200 (no throttling) |

  **9.5× faster**, with one third the requests, reducing load on the unofficial endpoint. Two `pnpm e2e` assertions: average ≥5 segments/request and ≤2 in flight.

- **Do not retry systemic failures at batch level** [Decided, 2026-09-06, Codex #61]: `BatchQueue` retries `BatchCountMismatchError` three times then individually; `asBatchError` converts provider `invalid-response` to it. Appropriate for LLMs (one segment often derails output, isolation helps), wasteful for free-engine responses that are wholly non-JSON: a 100-segment batch wastes 104 requests to an endpoint we should conserve. Add `isolatable` to `ProviderError` (default true); providers mark systemic failures false, preventing conversion and immediately reporting to fallback. Google non-JSON/invalid format are false; count mismatch stays true because individual requests usually resolve it.
- **Distinguish transient and permanent HTTP statuses** [Decided, 2026-09-06, Codex #17]: Google formerly classified every non-429 failure as `network`; retry-policy `isRetryableRequestErrorMeta` checks kind before status, so network is always retryable. Permanent 400s were retried three times then split/retried by BatchQueue, amplifying 100 segments into dozens of useless requests. Map 429 → `rate-limit`, 401 /403 → `auth`, other 4xx except transient 408 /409 → new `bad-request` (no retry, but fallback allowed because another engine may succeed); only 5xx and connection failures remain `network`.
- Treat free engines as **liable to fail at any time**: separate files/error types, automatically advance fallback on failure.
- Default fallback: selected provider → `chrome-builtin` → `google-web`.
- `google-web` batches multiple items (default 100 items /8000 characters); limit to 2 requests/s, burst 2 (`rateLimit`) because the free endpoint cannot tolerate default 8/s. No accumulation batching (Read Frog `shouldUseBatchQueue` allows only LLMs). Request-queue handles 429/timeouts as in §8.2.
- **429 pauses the entire queue through ported request-queue** (2026-09-05): concurrency/rate are only ceilings; while one throttled task sleeps, others can keep hitting the endpoint (Codex #6 /#10). Pause for max(Retry-After, backoff 5s ×2^consecutive windows with 10% jitter); multiple 429s within one window count once. Dispatch nothing during pause; reschedule affected work for its end. Retain at most one old token at resumption, replenishing others at rate. At default 8/s a 5s pause fills capacity 20, so a single probe only holds at low rates; preserve ported behavior (delete #30's stricter custom probe gate under directory-porting rules). Drain after 5 consecutive windows or 8 per-task 429s. Mark `no-key` / `auth` access-denied and drain; `aborted` / `invalid-response` nonretryable. Set metadata by kind in `ProviderError` construction (no-key and ID mismatch throw outside try); the ported policy otherwise mistook no-key as unknown, retrying four times and wasting 7s.
- **Thinking defaults off** (KISS `THINKING_API_REGISTRY`): choose fields by endpoint domain: OpenRouter `reasoning: { effort: "none" }`, official DeepSeek `thinking: { type: "disabled" }`, Bailian / SiliconFlow `enable_thinking: false`; omit for unknown endpoints. Send via AI SDK `providerOptions` (`src/providers/thinking.ts`).
- **Instant engine**: when Chrome model is ready (`availability() === 'available'`), offline single sentences take 10–20ms. Render viewport blocks first with it, then replace in place when selected LLM output arrives. Provider-keyed caches remain separate. Allow disabling in options.

Trigger `create()` for language downloads only in popup click handlers, otherwise `NotAllowedError`. Once ready, `create()` needs no gesture (1ms).
- During initial download, availability never changes to `downloading` and monitor emits no `downloadprogress` (67s observed as `downloadable`). Show indeterminate “Downloading language pack”. Only a subsequent `create()` after download emits 0→1 progress, during ~8s local loading.
- Language pairs download independently (en→zh and en→ja separately).

Per-translation cancellation still applies. **Concurrency gate is per provider** (same review): pipeline sizes batches for the **preferred** engine and fallback forwards the same call. Google-first (8000 characters /100 items) would launch 100 simultaneous local inferences precisely when fallback is needed. Use an instance-shared semaphore for `BUILTIN_MAX_ITEMS = 20`, **not batching within one call**, because multiple calls may dispatch concurrently (Codex #50). **Session creation has its own timeout** (60s, measured loading ~8.6s): without batch signals it needs independent expiry, or a hung `create()` remains cached and all retries await the same dead Promise. Remove entries on create failure. Errors: `NotAllowedError` / `NotSupportedError` → `no-key` (gesture/pair support absent; retries useless, permanently downgrade); `AbortError` → `aborted`; others → `unknown`. Normalize surplus spaces after CJK punctuation as measured in §6.2.
- **Not covered end to end**: headless Chromium language packs are downloadable, requiring a gesture and ~1 minute, unsuitable for regressions. Inject fake `Translator` for all unit-test branches; manually validate the real path. `pnpm e2e` only ensures unchanged chain behavior when built-in is unavailable.
- Normalize extra spaces after full stops (“。 ” → “。”).
- Content-script isolated worlds also expose `Translator` (2026-09-05, Chrome 153, RESEARCH §6.3): `'Translator' in self` true, availability matches main world; direct content calls are possible.

### 8.5 Engine Fallback Chain [Decided, 2026-09-05]

Hard rule 4 requires recoverable failures that trigger fallback without breaking the extension. Previously expired keys, exhausted quotas, or network faults made `run.ts` hit `no-key` / `auth`, call `scheduler.disconnect()`, and strand readers with half a paper.

- **Chain shape**: configured engine first, then nonduplicate free engines `chrome-builtin` → `google-web` (built-in is offline, 10–20ms/sentence, unthrottled; unavailable language packs make `isAvailable()` false and skip it). `providers/index.ts` `buildChain` filters unavailable engines, except **retain an unavailable first engine** so popup can report missing API key rather than silently switching to free translation.
- **Keep it outside `translate-service`** [Decided]: that closure already owns one provider's queue/cache/batching with `providerId | model | promptKey` keys, naturally separating engine output. Use a thin outer `providers/fallback.ts` (~110 lines), each step a complete service; pass the **same call** onward on failure. Embedding engine selection inside would couple three independent concerns.
- **Two downgrade durations**: `no-key` / `auth` are configuration faults, permanent for the session; `network` / `timeout` / `rate-limit` / `invalid-response` / `unknown` cool down for 60s, with success immediately clearing history. Queue retries finish before fallback; the chain adds no retries. Cooldown avoids repeatedly waiting through up to 120s batch timeouts during persistent faults. `aborted` never downgrades or records failure: session cancellation is not engine failure, and another engine would simply be canceled again.
- **When all are downgraded, retry the final step**: another honest failure to `run.ts` (which stops and shows error widgets) is preferable to a no-engine state.
- **Capability invariant**: `preservesMarkup` controls rendering, but `run.ts` reads `capabilities` once at start. Switching paths midway creates inconsistent block shapes. Require all chain steps to agree; filter and warn on mismatches at assembly. All three v1 providers are true; this guards future additions.
- **Visibility**: `axt:provider-status` field `engine` carries actual engine and downgrade reason (since 2026-09-06 background owns the chain; no longer in `PageStatus`). Popup polls alongside progress and explains that free terminology is less accurate than LLMs (§8.1 “weights → 重量”) and that repairing settings then restoring/retranslating returns to the preferred engine. Also `console.warn` on downgrade for e2e and user diagnosis.
- **Return to preferred after configuration repair**: popup sends `axt:engine-ready` after language download; background **rebuilds the entire chain**. Clearing downgrade state cannot recover engines excluded as unavailable during assembly, especially with a long-lived chain built before downloads. Thus `FallbackService` has no `reset()`.
- **Toggle**: config v5 `fallback.enabled`, default true. Disabled means only the selected engine, matching pre-chain behavior. Two e2e cases guard enabled and disabled paths.

## 9. Cache and Configuration

- Translation cache: IndexedDB via **Dexie**, ported FluentRead `services/translation/cache.ts` (key normalization, TTL, limits, in-memory hot layer), replacing crypto-js with Web Crypto SHA-256 (v0.4 revision; originally idb-keyval).
- Key: `sha256(providerId | model | PROMPT_VERSION | RULES_VERSION | target | renderPath | normalizedText)`. **Use `provider.cacheId ?? provider.id` for `providerId`** [Decided, 2026-09-05, issue #45]: `openai-compat` is shared across endpoints; ID + model would mix same-named OpenRouter and local Ollama output. Providers declare identity as `openai-compat:<origin><path>`. **Include path**: distinct gateway routes on one origin may target different backends; normalize trailing slashes. **Never include API keys** (hard rule 7). `normalizedText` = NFC + collapse consecutive whitespace + trim; placeholder text participates in hashing.
- Value: `{ text: string; ts: number; paper: string }`; arXiv ID `paper` supports per-paper cleanup/export. TTL 30 days, 20,000 entries /50MB total, 256KB/entry, 256-entry memory layer. Background exclusively owns/accesses cache (extension-origin IndexedDB shared across papers). Translation also runs there, so content never touches cache, saving two round trips/batch (§8.0, 2026-09-06).
- **Options provides global cache clear only** [Decided, 2026-09-05]: `axt:cache-stats` reports count/size; `axt:cache-clear` without paper clears all. Refresh statistics when returning to options because other tabs translate. Both responses use `{ ok: true, … } | { ok: false, message }`; **failure must not appear as empty cache or 0 deleted**, especially when IndexedDB is unavailable (Codex #52). Run `cleanup()` before stats: `get()` treats expired entries as misses without deleting, otherwise useless entries remain counted. This is the sole runtime cleanup call, so propagate errors rather than falsely reporting uncleared expired entries as success. **No clear-current-paper here**: options is standalone with no current paper; asking content is unnecessary complexity. Retranslating a poorly translated paper is a better popup action, deferred. Engine/model/prompt/glossary changes already miss old cache; manual clearing is fallback, not routine.
- **Eviction never scans the full database** [Decided]: maintain counts/bytes incrementally in memory (`byteSize` index, Dexie schema v2; initialize with `orderBy(index).keys()`, not record deserialization). Fetch/delete oldest `lastAccessedAt` entries in batches only when over limits. FluentRead originally read/summed every record on every set; hundreds of writes per paper with thousands of entries repeatedly deserialize the database, blocking single-threaded MV3 messages for tens of seconds. fake-indexeddb: 2000 entries gave 5.5ms/set, growing linearly; afterward stable 0.11ms/set.
- **Bound cache reads; translate on timeout** [Decided, 2026-09-05, issue #45]: the service awaits cache before requests, so a hung read stalls the page (worker cold start/suspension or lost messages). Use service-level 2s `CACHE_READ_BUDGET_MS` for all `CachePort` implementations. Timeout **or wrong result count** becomes all misses, costing only extra requests; 2s far exceeds measured ~36ms hit round trips. Since 2026-09-06 both cache/translation are in background; remove the content-side 1.5s message gate with `cache-port.ts`.
- **No cache writes after cancellation** [Decided, 2026-09-06, Codex #33]: calls span batches; some fulfill before `cancel(scope)` cancels the rest, then `Promise.allSettled` would still write them, violating no-render/no-cache-after-restore. Recheck `cancelledScopes` before writes.
- **Invalid translations never enter cache; retries bypass reads** [Decided, 2026-09-05; derive expectations from request text since 2026-09-06]: `translate-service` caches only placeholder-valid output (Codex #30). The old caller `accept` callback cannot cross messaging boundaries; derive expectations via `expectationsFromText(request text)`. `serialize` escapes literal `<` / `>` (§6.1), so every request `<x>` / `<t>` is a real placeholder; one scan reconstructs `slots` / `paired`. No protocol expansion, validation moves next to cache writes, and runs is protected too (previously no accept callback meant all output was cached). Single-block resends after validation failure set `cache.bypass` (write only), avoiding old invalid cached entries repeatedly forcing runs (Codex #9); successful retry overwrites them.
- Configuration: WXT storage, versioned zod schema and migrations (Read Frog `config/storage.ts` + `migration.ts` pattern). v1: `{ version, provider: 'openai-compat' | …, openaiCompat: { baseURL, apiKey, model }, targetLanguage: 'zh-CN', mode: 'stack' | 'side' | 'only' }`. v2 adds `prompts`, v3 `preload`, v5 `fallback: { enabled }` (default true, §8.5), v6 `glossary` (empty default, §8.2), v7 `style` (default none, §7.5); **v4 changes targetLanguage to ISO 639-3** (`cmn` / `cmn-Hant` / `jpn`…, 179 codes in `config/languages.ts`, matching Read Frog). Migration reverse-maps BCP-47: exact → primary subtag → `cmn`; LLM uses English names, Google converts back to BCP-47. API keys remain local, never in cache keys/logs/fixtures.

- **Make configuration fallback visible** [Decided, 2026-09-06, observed]: `getConfig()` correctly falls back to `DEFAULT_CONFIG` after validation failure, preserving extension operation, but a mere `console.warn` left stored keys unused and silently switched translation to free engines. Observed with v7 stored config and a v6 build: WXT rejects downgrade migration (`Version downgrade detected`), silently ignoring all config including keys. Record the fallback reason (newer config version or specific invalid field), expose `configFallbackReason()`, and show a red popup warning that key/engine selection did not apply. Store reasons per execution context; popup already calls `getConfig()` itself and reads its own result. Same principle as glossary migration normalization (§8.2): normalize what can be normalized; explicitly report what cannot.

## 10. Scheduling [Decided, rewritten 2026-09-05: Read Frog loading model, user decision; PR 2a implemented in `scheduler/lazy.ts`, `renderer/pending.ts`, `scheduler/title.ts`, and `pipeline/run.ts` `startTranslation`]

**Translate as the reader scrolls**: only viewport blocks and a distance below it; unreached blocks send no requests or consume resources. This is Read Frog's **only** page-translation mode (`PageTranslationManager`, no translate-whole-paper toggle). Port the approach and whole reusable modules; its decoupled modules and behavior are proven (§12 `feat/lazy-loading`).

- At start, only mark all blocks (`data-axt-id`, `pending`) and register each with one `IntersectionObserver`; **send no requests**. Slice marking to avoid freezing on hundreds of writes; **check session liveness before each block write** because restore may occur while yielding. Checking only outside the loop lets marking resume after restore, leaving orphan `data-axt-*` and violating §7.1 (issue #45 experiment 1). Use Read Frog `pageTranslation.page.preload` defaults: `rootMargin` **1000px**, `threshold` **0**. Options expose preload distance 0–10000px, step 100, and visible threshold 0–1, matching Read Frog names/semantics. Retire FluentRead's earlier 600px /0.01.
- **Seed and observer use the same visible threshold** [Decided, 2026-09-06, Codex #35]: synchronous startup seeding previously checked rectangle intersection only, ignoring threshold; one visible pixel triggered immediate translation while later viewport entry required the configured ratio. Seed with intersection height ÷ element height ≥threshold, matching `intersectionRatio`. Default 0 is unchanged.
- Request a block only on its **first** entry into viewport + margin, then `unobserve`; outside blocks are never requested. No background whole-paper queue; enlarge preload distance for the whole paper, as Read Frog does.
- **Batch blocks entering in the same IO callback**: scrolling may admit dozens at once; split by §8.2 1000 characters /4 items, preserving whole-table batches. `planBatches` handles only this newly visible group, not the whole paper. Initial IO callback is asynchronous, so synchronously seed from `getBoundingClientRect` at creation for immediate first-screen work.
- Insert pending/ring beside originals during requests (§7.6), then fill with translation; failures become error/retry, cancellation removes them.
- **Cancellation**: restore/disable cancels queued and in-flight requests by session ID (Read Frog `translation-session` + `cancelPageTranslationRequests`: abort local `AbortController`s and remove pending nodes/rings). Even if canceled results arrive, never render or cache them.
- Do **not** port Read Frog `MutationObserver` for dynamic content or giant-paragraph splitting (observe subparagraphs for blocks taller than three screens): arXiv is static and paragraphs do not exceed three screens; revisit for other sites.
- Popup progress becomes an enabled state rather than a finite job: show translated / entered viewport / failed; `total` is reference only. Translating means requests remain in flight; idle otherwise, resuming on scrolling.

Unchanged:

- **No JS scroll anchoring or layout reads during translation insertion** [Decided, 2026-09-05]: rely on Chrome native scroll anchoring (`overflow-anchor: auto` default). Inserting 600px above viewport produced automatic 575px compensation and 0 anchor displacement. Early FluentRead JS anchoring (`elementFromPoint` + `getBoundingClientRect`) forced two full layouts per batch, 130–150ms in side /90–100ms in stack (15644 nodes, ~700 subgrids). Eight workers and 100+ batches made 826 fully cached blocks take 16.5s, with 52 back-to-back ~90ms long tasks. Removing it leaves network/cache round trips as the constraint.
- **Coalesce progress with a maximum wait, not pure debounce** [Decided, 2026-09-05]: dozens of callbacks/second continuously reset 150ms debounce, postponing side prep until the entire paper finished (413 mirrors appeared at the last moment; until then equations spanned columns). `createCoalescer(fn, { delay: 150, maxWait: 1000 })` prepares at least once/second regardless of event density. **Since 2026-09-07 it accumulates dirty sets** (issue #46): `schedule(item)` collects deduplicated items; no-argument `schedule()` requests full work; callback receives items or null, avoiding repeated whole-paper scans.
- **Mirrors do not wait for translations** [Decided, 2026-09-05]: equations/images have none; waiting for containing paragraphs is pointless. Mark blocks at translation start and use `:has(.axt-t, [data-axt-id])` for mirror containers, creating all mirrors on first prep. Gate 2 (no marked blocks or block-containing elements) still prevents whole-block duplication. **Because decisions depend entirely on block markers, mirror only once per session** (2026-09-07, issue #46): arrival changes no decision, later scans waste work (840ms total in 2312.17141); `prep.ts` flags the first full pass.
- **Concurrency and total deadlines** [Decided, 2026-09-05, issue #43]: token buckets constrain **rate, not concurrency**; slow responses still let tokens replenish/dispatch, so in-flight count is bounded only by queued work (three never-resolving requests all became concurrent even at `rate=1 / capacity=1`). A 220-block paper can produce 50+ batches, triggering 429/browser connection limits if all hit one endpoint. Add optional `maxConcurrent` (service default **8**, matching rate; inactive for responses under 1s) and `maxTotalMs` (per-task enqueue-to-final-failure deadline, service default **180s**). Defaults belong in `translate-service`, not the queue, preserving ported behavior.

  Actual `provider.translate` calls by failure type (2 queue retries, 3 batch retries):

  | Failure | Calls | Duration | Outcome |
  |---|---|---|---|
  | network | 3 | 9 ms | Failed |
  | auth | 2 | 3 ms | Failed (queue drained) |
  | invalid-response | 6 | 7.0 s | Failed |
  | rate-limit | 4 | **Still pending after >60s** | Pending |

  Attempts were already bounded (`MAX_CONSECUTIVE_RATE_LIMIT_PAUSES = 5` for 429); the missing bound was **total time**. Each rate-limit pause can be long, and callers need a definite point at which a batch is considered failed. Fail then and allow user retry instead of waiting indefinitely.
- One queue pair/provider (`translate-service`, replaced 2026-09-05 with whole Read Frog `utils/request/` directory): `request-queue` (token bucket 8 requests/s, burst 20; provider `rateLimit` override) + `batch-queue` (1000 characters /4 items /100ms accumulation; dispatch gate accumulates during throttling; LLM-only accumulation) + `priority-queue` + `cancellation`, including tests. Remove p-queue and #30 custom pause/probe. Batch key: provider, model, prompt, target, render path, context (including section title; no cross-section batching). Provider ID mismatch is a batch error: 3 batch retries, then individual fallback; request-queue does not retry it. Scope cancellation uses one ID/run; restore cancels batch-queue before request-queue (matching `translation-queues.ts`), aborting fetch and rejecting late render/cache writes.
- Failed-block Retry lives inside the error widget (§7.6); popup no longer lists individual failed blocks.

## 15. Image Translation [Decided, added to scope 2026-09-07]

Match Safari image translation: recognize text and overlay translated labels in place, with no additional features. **Scope**: bitmap `img.ltx_graphics` only (SVG still skipped in v1, §15.1); Mac only (Vision OCR), non-Mac fallback deferred. **No per-image entry point**: whole-page translation schedules images with text through the same viewport lazy loading (§10), canceled with the session. Options provides a side /stack /only multiselect for enabled image-translation modes, all on by default, gated by effective mode. Switching to a disabled mode hides overlays, switching back shows them, and switching to an enabled mode schedules untranslated images, consistent with no repeat requests on mode changes. If helper detection (`ping`) fails, disable the setting and silently skip the image path; page translation is unaffected.

### 15.1 Rationale

- Safari image translation combines Live Text (Vision OCR) and Translation frameworks, both accessible to third parties.
- **Helper handles OCR only; translation and overlays remain in the extension**. macOS 15 Translation sessions require SwiftUI `.translationTask`; UI-free `TranslationSession(installedSource:target:)` arrives in macOS 26 and still requires installed packs. The extension already has a complete pipeline, and LLMs can use captions as context. A thinner helper minimizes platform-specific surface.
- Non-Mac fallback uses multimodal LLMs to read image text/coordinates (lower coordinate accuracy, acceptable).
- arXiv SVGs are TikZ `svg.ltx_picture` (164 across 10 fixtures, mostly drawn equations). No `<text>` found; rare text appears in `foreignObject` (one text node across all fixtures). Skip SVG entirely in v1 (§5.2); OCR only targets bitmap `img.ltx_graphics` (13 fixture images, RESEARCH.md §2.9).
- **Use the existing contextual pipeline, not Safari's isolated line translation**. In the user's Safari comparison of a physics diagram, “Dressed sites” became “打扮的网站”, “Even sites” “甚至网站”, “String Extension” “特林扩展名”, and a lone **B** was labeled “字母b”. That is the result of sending lines without captions/sections. Send each image's lines together in one batch with caption and section context through existing providers; skip single letters, pure numbers, and identifiers using existing §6 preservation rules.
- **Follow Safari overlay appearance**: white, rounded, translucent boxes cover source text; font size follows box height. Merge vertically adjacent left-aligned lines into one box (two-line “Pair / Production”). Hover reveals original text. Start with fixed translucent white; add background sampling only after encountering dark images (ImageTrans `detectBackgroundColor` approach).
- **Reuse existing implementations**: port helper core from `bytefer/macos-vision-ocr` (MIT, single Swift file, Vision revision 3, per-line text + normalized quad + confidence, already §15.3's shape), wrapping Native Messaging stdio frames. Port DOM overlay portions of GPL-3.0 `xulihang/ImageTrans_chrome_extension` `getImage.js` (font fitting `fitBoxFontSize`, background sampling `detectBackgroundColor`, wrapping, rounded boxes), plus viewport-scheduling ideas. **Do not port img-src replacement**, which violates §7.1.

### 15.2 Architecture

```
content script                       background (service worker)          axt-helper (Swift, helper/)
  fetch <img> (same-origin, HTTP cache) axt:ocr {imageHash, image, scope}    Vision VNRecognizeTextRequest
  → SHA-256 → base64 ─────────────►   lookup imageHash|helper version ──►  length-prefixed JSON on stdio
                                       connectNative only on cache miss ◄── {lines:[{text, quad, conf}]}
  ◄── {lines} ──────────────────────  write cache
  lines → boxes (merge neighbors, filter numbers / single letters)
  → existing axt:translate (plain-text path, caption in the same batch)
  → insert .axt-img sibling after <img>; position labels by normalized coordinates
```

- **Two cache layers**: OCR by `imageHash | helper version` in the same Dexie database (deterministic recognition, rerun only after helper version changes). Line **translations use normal text cache**, **without** imageHash: “Dynamical charge” means the same regardless of image, enabling cross-image reuse.
- Follow §7.1: **siblings only** (`.axt-img`, `data-axt-for` points to image ID), never wrap `<img>` because that changes original parent-child relationships. **No `.axt-t` on overlay or `data-axt-id` on image** [Decided, 2026-09-07, verified during planning]: those markers would put overlays in the right pairing column instead of over images, remove images from split copies as paired originals, suppress mirrors, apply twenty presets, and receive margin-alignment inline styles. This is a third injection marker, recognized by `marks.ts` `isInjected` /`stripInjected`, `restore()`, and `splitFigures` real-translation detection.
- **Use CSS anchor positioning** (Chrome ≥131 for `anchor-scope`; built-in translation already needs 138+): `img:has(+ .axt-img)` declares anchor name; overlay `anchor()` /`anchor-size()` follows image box. Parent `position: relative; anchor-scope` isolates scope; `grid-column: auto` removes pairing-grid placement. Zero JS geometry reads or ResizeObserver; split-copy structure automatically reestablishes anchors. Compute font-size strings once from box height/text length using container units `cqh` /`cqw`, without layout reads. Do not use ImageTrans's JS binary search, which forces 12 layouts per box.
- **No pending/failure overlay DOM nodes**: figure splitting would clone pending overlays and `stripIds` would strip state attributes. Insert only on success (as Safari does). Record failures in image run; popup counts/retry handle them. Visibility CSS uses structure and `<html data-axt-img-modes>`, not overlay-local attributes.
- Side splits whole figures (§7.2); overlays belong in the translation-only copy, hidden in original **only during side**. Stack shows original, only shows copy; overlays follow the visible figure. Include overlays in split-rebuild signatures or final copies omit them. Once-per-session mirroring runs before OCR and can insert between image/overlay; `mirror.ts` gates recognize `isInjected`, and overlay insertion removes the immediate mirror. If OCR arrives after side → only, overlay enters hidden original and copy becomes stale; non-side prep removes stale copies in dirty roots, rebuilding on side return.
- **Configuration errors stop scheduling** (Codex #89): first `auth` /`no-key` invokes `fatal()` like text translation; later viewport images no longer fetch bytes or OCR. Popup repair-configuration/restart guidance also applies. Ordinary network/helper failures affect one image; retry includes images.
- **Concurrency maximum 2** (Codex #89): fetches, base64, and message payloads consume memory, while helper is sequential; launching everything only stockpiles 6MB images.
- **Use the nearest figure's own caption** (Codex #89): multipanel figures each have captions; taking the outermost first `figcaption` gives (a)'s caption to (b), contaminating prompts/cache keys.
- **Remove the previous mode gate before a new session** (Codex #89): restarting after fatal error without restore leaves old overlays. If helper disappears, image translation is disabled, or target changes, old overlays must not show; replace them when the new run reaches each image.
- **Clear old overlays even with no labels** (Codex #89): a new language may return every line unchanged, requiring old overlay removal. Animated images (`frames > 1`) likewise complete without overlays.
- **Enforce 6MB while reading the response** (Codex #89): inspect Content-Length, then stream and cancel immediately on overflow; `arrayBuffer()` first allocates the entire response.
- **Unsupported anchor-positioning browsers**: place baseline `.axt-img { display: none }` outside `@supports`, preventing overlays turning into text below images. `wxt.config.ts` has no minimum Chrome version, so old Chromium installs must not break pages.
- **Do not translate images inside blocks**: target `img.ltx_graphics` outside every translation block, matching split-figure free-media detection. In-block images are cloned through placeholders, and only hides their entire original block, leaving no overlay attachment point. All 16 bitmaps across 12 fixtures are in figures/flex cells, none inside blocks.
- **Cancellation**: `axt:ocr` carries session `scope`. Helper client separates queued/in-flight work (one in flight, matching sequential helper execution so cancellation removes actual work). Cancel scope rejects queued requests and discards eventual in-flight results. Both `axt:cancel-scope` and tab closure invoke this via sessions `onDrop`. Content rechecks session ID after every await for DOM safety, as text pipeline does.
- Helper lives in this repository's `helper/` (Swift Package, no third-party dependencies), evolving in the same PRs; split repository only when distribution requires it.

### 15.3 Native Messaging Protocol

Request (extension → helper):
```json
{ "v": 1, "cmd": "ocr", "id": "req-1", "image": "<base64 png/jpeg>", "langs": ["en"] }
```
Response (helper → extension):
```json
{ "v": 1, "id": "req-1", "width": 1200, "height": 800,
  "lines": [ { "text": "Accuracy (%)", "quad": [[0.12, 0.05], [0.32, 0.05], [0.32, 0.08], [0.12, 0.08]], "conf": 0.98 } ] }
```
- `quad`: normalized `[top-left, top-right, bottom-right, bottom-left]`, top-left origin (helper flips Vision's bottom-left y). Quads, not `[x, y, w, h]`, preserve rotated axis labels; extension chooses axis-aligned enclosing boxes or angled rendering.
- Capability detection: `{ "cmd": "ping" }` → `{ "ok": true, "version": "..." }`.
- Size: helper → extension ≤1MB/message, Chrome's hard cap; exceeding disconnects the whole connection and invalidates queued work. If serialized output exceeds 250KB (matching 256KiB per-cache-entry limit, avoiding repeated recognition of large uncachable results), drop lowest-confidence lines until it fits and return `truncated: true`, forwarded unchanged. Normal images yield a few KB; only extremely dense text hits this. Smoke tests cannot construct such images; inspect code for this guard. Extension → helper can be much larger, suitable for images.
- Handshake requires nonempty `version`, used in OCR cache keys. Unversioned helper is unavailable; options asks to reinstall. Version = program version + Vision model revision (`0.1.0+vision3`), so system model changes naturally invalidate old OCR.
- Read all 4 length-prefix bytes: pipes can return short reads; treating them as EOF invalidates queued recognition.
- Return `frames` (`CGImageSourceGetCount`): helper recognizes frame 0 only. GIF /APNG /animated WebP boxes do not match later frames; extension completes `frames > 1` images without overlays.
- Error: `{ "v":1, "id":"...", "error": { "code": "...", "message": "..." } }`.

### 15.4 Helper

- Swift, ~100–200 lines: read length-prefixed stdin JSON, decode image, run Vision, write stdout.
- User-level host manifests live at **`<user-data-directory>/NativeMessagingHosts/<name>.json`** (measured 2026-09-07: not fixed `Google/Chrome/…`, merely Chrome's default data location; Dia uses `Dia/User Data/NativeMessagingHosts`). Installer writes Chrome/Chromium defaults. Playwright sets a temporary profile via `--user-data-dir`; e2e must copy manifest to `<profile>/NativeMessagingHosts/`, as Chrome for Testing cannot find it in system-level Google/Chrome. `allowed_origins` binds extension ID. **Do not pin `key`** [Decided, 2026-09-07]: it changes ID and loses local config. Unpacked ID derives from path and is locally stable; Playwright loading the same `.output/chrome-mv3` path gets the same ID. Installer accepts ID argument; revisit for distribution.
- **Defer distribution** [Decided, 2026-09-07]: first support developer installation only, `swift build` + registration script, verifying value on the author's Mac. Signing/notarization/pkg/Homebrew become a later project. Startup ping failure disables settings and silently skips images.
- **Require `nativeMessaging` for now** [Decided, 2026-09-07, Codex #87 suggested optional]: required permission triggers store install/update warnings about communicating with local applications, including for non-Mac users, and may disable installed extensions until update permission is accepted. These occur only during **distribution**, not unpacked loading. With signing/pkg work, change to `optional_permissions` + options authorization button (`permissions.request` needs gesture; Save supplies it). e2e should copy builds and add permission to copied manifest like local-endpoint tests because Playwright cannot operate native permission dialogs.
- **Protocol versioning**: requests include `v`; unknown versions return `unsupported-protocol`. Extension checks handshake response `v`; mismatch rejects queued work, disconnects, and asks to reinstall helper. Separately installed extension/helper versions can diverge.
- **First OCR timeout**: allow 120s for this worker's first recognition (machine-first Vision preparation measured 26.6s, so 30s can falsely fail healthy helpers); after one success use 30s.
- Later: helper enables an `apple-translate` provider (`preservesMarkup: false`, Mac-only/offline). macOS 15 requires a transparent SwiftUI host window workaround (SystemTranslation library); macOS 26 permits direct initialization.
