## 1. Goals and scope

**What it does**: a Chrome translation extension made for arXiv Experimental HTML pages (`https://arxiv.org/html/*`). It provides stable, reversible, full-text translation suited to long reading sessions while preserving the paper's structure, formulas, code, links and interactivity.

**v1 scope [decided]**
- Chrome only, `https://arxiv.org/html/*` only
- Three reading modes: side by side (side), stacked (stack), translation only (only), switchable at will, with a lossless restore of the original at any time
- Translation engines: LLM (OpenAI-compatible; for Anthropic / Gemini see the not-yet-implemented note in §8.1) + free engines (Chrome's built-in Translator API first, `google-web`'s translateHtml as the fallback; the gtx originally planned has been replaced by it, see §8.1)
- A local cache: the same paper reopened shows instantly
- Translation style presets + a glossary
- Image translation [decided, 2026-09-07]: the text inside bitmaps `img.ltx_graphics`; on a Mac the local Vision OCR is called through Native Messaging and the translation is overlaid on the image (after Safari's image translation, see §15)

**Non-goals [deferred]**: other sites, PDF, subtitles, TTS, a vocabulary book, Firefox/Safari support, DeepLX, the image-translation fallback path for non-Mac platforms (§15.1). The architecture does not rule them out, but none of them is in v1. (**Microsoft's free channel has been removed from this list**: it was excluded because its auth endpoint returned 404, but that flow has been replaced by an unauthenticated successor, re-tested working on 2026-09-08, see RESEARCH §5.1; wired in by issue #98.)

## 2. Core judgements

arXiv HTML is generated by LaTeXML; the DOM is highly regular and every element carries an `ltx_*` class name. Therefore:

1. **No need for a general-purpose translator's heuristic DOM walker and site-rule subscription system**. A set of deterministic rules aimed at LaTeXML does the block splitting and the skip decisions; the rules live in one file and can be versioned.
2. **The three modes share one DOM, and a mode switch changes a single CSS attribute**. A translation node is always inserted as the adjacent sibling of the original block and never modifies the original node's subtree. This is the foundation of reversibility.
3. **The render path is negotiated from the provider's capability set, not decided by engine type**. The `tags` path translates whole blocks with tag placeholders; the `markers` path translates whole blocks with plain-text markers (void only, paired placeholders flattened); the `runs` path cuts the block into segments at the untranslatable inline nodes. A provider declares which wire formats it can preserve with `wireFormats` (**a set ordered by preference, not a boolean** — Google preserves both); the chain takes the intersection when it is assembled, and one session uses one format only (§8.5). The Phase 0 / Phase 3 measurements showed that LLMs, Google translateHtml and Chrome's built-in Translator all preserve tags, so the negotiation gives `tags` by default; `markers` is for the free engines that tear tags apart (measured on #104: Microsoft's Edge endpoint keeps 0% of tags and 98% of markers), and `runs` is the fallback after a failed validation (RESEARCH.md §5 / §6).

## 3. Terms

| Term | Meaning |
|---|---|
| Block | One translation unit, corresponding to one LaTeXML element such as `.ltx_p`, `.ltx_title`, `.ltx_caption` |
| Protected node | An inline node inside a block that is not translated and must be kept as it is: formulas, citations, code, footnote marks and so on |
| Placeholder | The token that stands in for a protected node when sent to the model. In the `tags` format void `<x id="n"/>` and paired `<t id="n">…</t>`; in the `markers` format void `@a#` only |
| Wire format | The syntax of placeholders in the request text: `tags` or `markers`. A provider declares which it can preserve with `wireFormats`; the chain takes the intersection and negotiates exactly one (§8.5) |
| Render path | `tags` (whole-block translation with tag placeholders), `markers` (whole-block translation with markers) or `runs` (cut at the protected nodes and translated segment by segment). **The values share their names with `WireFormat`**, with `runs` as the one extra; it enters the cache key |
| Mode | `side` / `stack` / `only`, controlled by `html[data-axt-mode]` |
| Provider | One translation engine adapter implementing the common interface |
| Fixture | A real arXiv HTML page kept in the repository for tests |

Prefix convention: every class, data attribute and CSS variable the extension injects starts with `axt-` / `data-axt-` / `--axt-`.

> Corrected 2026-09-13: the `[cache?]` step drawn in the content script does not exist — the cache lives in the background beside the queues (§8.0); the diagram predates the move of 2026-09-06.

**Data flow (a single block)**
1. `extractor` collects every Block by the rules and marks it with a stable id (`data-axt-id`)
2. `scheduler` translates only the blocks that enter the viewport (plus the preload distance); blocks not scrolled to send no request and take no resources (§10, after Read Frog)
3. The cache is checked first (cache and requests both live in the background; content never touches IndexedDB); a hit is rendered directly
4. On a miss: `protector` serialises the block into `{format, text, slots}` in the negotiated wire format; the render path decides between `tags` / `markers` (the whole block with placeholders) and `runs` (cut into segments)
5. In the background the ported `request-queue` sends requests at the provider's rate (token bucket) and concurrency cap, and `batch-queue` batches them (§8.0: since 2026-09-06 requests run in the background); failures back off, retry, pause on 429, and switch to the fallback provider when needed
6. `validator` checks the placeholders are complete; on failure → one retry of the single block → fall back to the runs path
7. `rehydrator` swaps the placeholders back for clones of the protected nodes (with the `id` attribute stripped)
8. `renderer` inserts the translation node as the original block's next sibling and writes the cache
9. Mode switches and restoring the original go through none of the above; they are pure DOM/CSS operations

### 4.0b Five entry points [decided, implemented 2026-09-10, issue #146; the keyboard shortcut 2026-09-10]

Translation is only ever started by the user (nothing happens before step 1 of §4), but “starting” has five roads, all landing on the same pair of messages `axt:translate-page` / `axt:restore-page` — **one implementation of the action, five doors into it**:

- **popup**: translate / restore, mode, engine, progress. The most complete one
- **Keyboard command** `axt-toggle` (manifest `commands`, suggested Alt+T): the same toggle as the context menu, sharing `toggleTranslation()`. The popup's translate button shows the key as Chrome actually reports it (`commands.getAll()`), so a rebound or removed key is never advertised wrongly (UI.md S-P-50)
- **Context menu**: one item `翻译本页 / 显示原文` (the same wording as the popup's main button), `documentUrlPatterns` limited to `https://arxiv.org/html/*`. Clicking it asks `axt:page-status` once before deciding which message to send. **The label does not follow the state**: `contextMenus.update` is global, not per tab, and following the current page would be wrong the moment the tab changes (Immersive Translate's item is static too)
- **`#axt-translate` in the URL**: the content script starts translating as soon as it sees it on entering the page. Originally a hook for debugging and automation, now a product interface
- **The bilingual entry on the abstract page**: a separate content script on `arxiv.org/abs/*` inserts one line after arXiv's own HTML link inside “Access Paper”, pointing at **the href arXiv gives** plus `#axt-translate`. Reading a paper used to take “click HTML → wait → open the popup → click translate”; now it is one step. **The href is arXiv's, not built by hand**: it carries the version (`/html/1706.03762v7`), and building it by hand would point at the wrong version of a paper with several; **a paper without an HTML version (no `#latexml-download-link`) gets nothing inserted**. This content script loads no part of the translation pipeline

### 4.1 Block model [decided]

```ts
interface Block {
  id: string        // the value of data-axt-id: the element's own id (LaTeXML's S3.p1.1 etc., stable across loads) first, otherwise axt-b<n> in document order; a suffix on duplicates
  kind: 'text' | 'table'
  el: Element       // the original node; its subtree is never modified
  unit: string      // the id of the rule matched (p / title / caption / note / bibitem / ack / keywords / table)
  cells?: { el: Element; numeric: boolean }[]   // table only: every .ltx_td at any depth inside the outermost .ltx_tabular (cells of nested tabulars included); numeric decided by §5.3
}
```

- `extract(doc): Block[]` is read-only and writes no DOM; only `markBlocks(blocks)` writes `data-axt-id`. **On page load only extract runs**; marking happens on `#axt-debug` or when translation starts, and the page is untouched before a translation. The popup's statistics come from the `Block[]` in the content script's memory, not from the DOM.
- **Traversal strategy and classification are decoupled**: a DFS from the translation root decides “emit or not” and “descend or not” separately by the category `classify(el)` returns — `skip` neither emits nor descends; `table` emits a table block and does not descend (an `.ltx_p` inside a table belongs to its cell and is no block of its own); `unit` emits a text block when it holds translatable text and **keeps descending** to find nested units; `protect` emits nothing and does not descend by default, except for rules carrying `descend: true` — `.ltx_note` is the first protect-but-descend case: to the enclosing paragraph it is a void, while the `.ltx_note_content` inside it must still be found as a block of its own (of the 56 footnotes in the fixtures, 51 are inside an `.ltx_p` and 3 inside an `.ltx_caption`).
- Translatable text = the text left after excluding the protect / skip subtrees contains a Unicode letter (`/\p{L}/u`); an `.ltx_p` holding only formulas, numbering or punctuation is no block. Tables likewise: a table with no cell that is “non-numeric and holds a letter” (an empty layout tabular inside a paragraph, a pure-formula table) is no block.

## 5. Block model and rules

The selectors below were calibrated on 10 fixtures (RESEARCH.md §2, body text-node coverage 99.97%). Every arXiv page online today is generated by LaTeXML oxide 0.7.6. The rules live in `src/core/rules/latexml.ts`.

**Translation root [decided]**: `article.ltx_document`. Everything outside the root — `.ltx_page_navbar` (the table of contents), the header and footer arXiv injects, the “report an issue” dialog, the announcement bar — is never extracted, with no need to list selectors one by one (RESEARCH.md §3.1).

### 5.1 Translation units

| Selector | Notes |
|---|---|
| `.ltx_p` | Body paragraphs. `.ltx_para` is the container carrying the anchor id; `.ltx_p` is the text block. Paragraphs inside the abstract, list items, theorems and proofs are all covered by this row, with no separate rules (the Phase 0 measurements showed those rules fully contained, and listing them separately would break “every text node under exactly one rule”); context such as “abstract / theorem” is passed to the provider as a hint only. Note that `.ltx_p` may be a `<span>` (inside tables and inline-blocks); extraction and rendering go by class name, not tag name |
| `.ltx_title` (excluding `.ltx_title_acknowledgements` / `.ltx_title_keywords`), `.ltx_subtitle` | Headings of every level and subtitles. An `.ltx_tag` inside (the section number) has to be a void placeholder; a theorem's run-in heading (“Theorem 1.”) belongs here too |
| `.ltx_caption` | Figure and table captions. The `.ltx_tag` inside (“Table 1: ”, with `.ltx_text` nested in it) has to be a void placeholder |
| `.ltx_note_content` | The footnote body, as a block of its own. A footnote is a **nested block**: the whole `.ltx_note` (the mark + `.ltx_note_outer > .ltx_note_content`) sits inside a paragraph, and the enclosing paragraph treats `.ltx_note` as a void placeholder; the second `.ltx_note_mark` and the `.ltx_note_type` inside `.ltx_note_content` are voids |
| (tables) | Not through this table: the whole outermost `.ltx_tabular` is handled as one unit by the TABLE rule of §5.3; the cells `.ltx_td` (those of nested tabulars included) are segments inside the table block, not blocks of their own; the `.ltx_p` inside a cell is walked into by the protector when it serialises (§5.3) |
| `.ltx_bibblock` | A fragment inside a bibliography entry (authors / title / venue); an entry without fragments falls back to `.ltx_bibitem`, see 5.4 |
| `.ltx_acknowledgements` | Acknowledgements. The body is bare text inside the container, so the container itself is the unit; its run-in heading is **not a block of its own** (revised 2026-09-04), or the enclosing unit would clone the heading as a void placeholder in English, and the page would show two English headings above a Chinese paragraph (measured on 2609.00095). Not being a block, the heading is a paired placeholder, translated with the enclosing unit and restored in place. `.ltx_keywords` likewise |
| `.ltx_keywords` | Keywords |
| `.ltx_personname` | Author names (since 2026-09-06, see the decision in §5.2). It is a `<span>` inside `.ltx_creator`; the translation follows the original name as a sibling span, inline by nature; a `<sup>*</sup>` footnote mark inside a name goes through a paired placeholder and is restored in place |
| `.ltx_contact`, `.ltx_role_affiliation`, `.ltx_role_address`, `.ltx_dates`, `.ltx_date` | The authors' affiliations, contact details, dates. **Revised 2026-09-04**: the author area went from “skipped whole” to “translated by default”, excluding only names and email addresses. The old policy missed author notes of an acknowledging nature (such as “†Equal contribution. Listing order is random…” in *Attention Is All You Need*, which sits in `.ltx_creator > .ltx_note`)|
| `.ltx_role_dedicatory`, `.ltx_item`, `.ltx_marginpar`, `.ltx_indexentry`, `.ltx_cv_item_label`, `.ltx_cv_item_content`, `.ltx_cv_entry_date` | Dedications, bare text of list items, margin notes, index entries, CV fields. None of these appeared in the real papers fetched; they are guarded by `tests/fixtures/arxiv/synthetic-structures.html` (RESEARCH.md §2.12)|

### 5.2 Skip rules (whole blocks left untranslated)

| Selector | Notes |
|---|---|
| `math`, `.ltx_Math` | MathML formulas (inline ones become placeholders, block-level ones are skipped whole)|
| `.ltx_equation` | Display formulas: single-equation tables and the equation rows inside a group. **The equation group itself is not here**, see `\intertext` below |
| `.ltx_tag` | Equation numbers, section numbers, figure and table numbers, list markers, code line numbers |
| `.ltx_listing`, `.ltx_listingline`, `.ltx_listing_data`, `.ltx_verbatim`, `pre`, `code` | Code, verbatim, hidden listing data. Inside an algorithm box `figure.ltx_float.ltx_algorithm` / `.ltx_float_algorithm` the lines are `.ltx_listingline`, covered by this row; the `.ltx_caption` inside the box is translated as usual |
| `.ltx_text.ltx_font_typewriter` | Monospace text (treated as code)|
| `.ltx_author_before`, `.ltx_author_after` | The conjunctions between authors (“ and ”, “, ”); as blocks of their own they would break the name list |
| `.ltx_classification` | MSC / ACM classification codes, such as “Primary: 11L07” |
| `.ltx_ERROR`, `.ltx_FATAL`, `.ltx_WARNING`, `.ltx_INFO` | LaTeXML's conversion errors and notices, not paper content |
| `.ltx_pubnotes` | Publication metadata (the ACM template's CCS / DOI / journal / volume and issue)|
| `svg`, `.ltx_picture` | TikZ pictures: skipped by the text pipeline; the labels inside are HTML in `foreignObject`s and are overlaid by the image pipeline (§15.6). Corrected 2026-09-13 — it read “measured to hold no translatable text, see §15.1”; §15.6 found 199 labels with words |
| `.ltx_ERROR` | LaTeXML conversion error blocks (they also appear on failed-conversion pages titled "Untitled Document", which the extension must handle quietly)|
| `.ltx_page_navbar`, `.ltx_TOC` | The navigation bar and the table of contents. Outside the translation root; listed only so the renderer can hide them |

> Corrected 2026-09-13: the first three rows — `math` / `.ltx_Math`, `.ltx_tag`, `.ltx_text.ltx_font_typewriter` — are not skip rules in the code but PROTECT rules: inline formulas, tags and monospace text become placeholders inside the enclosing block (§5.6, §6.1; `PROTECT_RULES` in `rules/latexml.ts`), and only block-level formulas are skipped whole (`equation`). The table kept the pre-implementation grouping.

- **Author names are translated too** [decided, 2026-09-06, the owner's call]: the rest of the author area (affiliations, contact details, dates, author notes) was opened up on 2026-09-04 already, and only names were still held back, on the grounds that “a transliteration breaks citation lookup”. That argument does not hold in a **bilingual** reader: in stack and side mode the original name sits right next to the translated one, and whoever wants to copy it for a search has the original; only `only` mode hides the original, and that is the mode's inherent trade-off for all content, not one names should carry alone. Once opened, `.ltx_personname` moved from the skip rules to the translation units.

  **Fixture measurement** (30 `.ltx_personname` across 12 papers): all inside `.ltx_creator` within `article.ltx_document`, **none in the bibliography** — the citation author paragraphs are `.ltx_bibblock`, opened up later the same day by §5.4. The structure is uniform: plain text, a few with a `<sup>*</sup>` footnote mark (through a paired placeholder); a few templates put two authors into one element (`Matías Blaña and Marcelo D. Mora`), which translates correctly as a whole.

  **Translation quality measurement** (google-web, the worst case among the free engines): 28 of 30 are ordinary transliterations, and Chinese names even come back as characters (`Yuan Xia` → 袁霞, `Haipeng Cai` → 蔡海鹏, `Fumihiro Imoto` → 井本文宏; the exact characters are guesses). One failure: **`Brian Street` → 布莱恩街**, the surname taken for a common noun. About a 3% error rate, and the errors are conspicuous with the original right beside them. An LLM has the paper's title and abstract as context and should do better. **The prompt was not changed for this**: adding a constraint to every batch for a few names does not pay, and bumping `PROMPT_VERSION` voids every cached translation; this waits for real feedback.

  Changing this rule bumps `RULES_VERSION` (it enters the cache key), now 0.7.0. The conjunctions between names, `.ltx_author_before` / `.ltx_author_after`, are still skipped — as blocks of their own they would break the name list.

- **The contact label `.ltx_contact_name` is not translated** [decided, 2026-09-06, met in measurement]: LaTeXML generates a label element for every `.ltx_contact` with the content `Affiliation: ` / `Email: ` / `E-mail `, and **arXiv's style sheet sets it `display: none`** (measured on three online pages: computed style `none` throughout, box 0×0). It is generated by the template, not written by the author, so it is a void placeholder.

  Not doing so has a consequence **the reader can see**: in the email `.ltx_contact` the only translatable text is this hidden label (the address itself is a protected `mailto`), so the whole block is judged “has translatable content” and gets a translation, in which the “电子邮件：” is hidden by the site just the same — and the page shows two identical lines of email address (the reader saw it in the author area of 2507.00150). The affiliation line does not duplicate (it has real content), but it kept translating this invisible label for nothing, and google-web even rendered `Affiliation:` as “联系：”.

  Measured on 12 fixtures: all 43 `.ltx_contact_name` sit inside `.ltx_contact`; 12 of them belong to `ltx_role_email` and have **no translatable text at all** once the label is gone, so those 12 blocks disappear (the duplicated lines are gone); the 29 of `ltx_role_affiliation` and the 1 each of `ltx_role_note` and `ltx_role_correspondent` still have real content, and the blocks stay, only without translating a hidden label.

  **This was not made a general “skip hidden elements by computed style” mechanism** — the reasoning was revised once after measurements on 2026-09-11. It was first called a “performance trap”, and measured it is not: reading `display` / `visibility` once for every element inside the translation root costs **12.3 ms** on 2312.17141 (31987 elements, our heaviest fixture), 6.2 ms on 2607.24653v2 (18941), around 1 ms on a small paper; extraction happens before any write, the layout is clean, and only one style recalculation is paid. The two real reasons are: (1) **it would catch nothing today** — in the same measurement every hidden subtree root holding letters fell under an existing rule (`.ltx_contact_name`, `.ltx_nodisplay`, `.ltx_author_before`), and the remaining 107–141 were MathML `<annotation>`s, kept out long ago by the `math` protect rule; (2) it would make the extractor **depend on layout and style sheets**, whereas today it is pure DOM — 1400-odd unit tests run the whole extraction chain in happy-dom precisely because of this, and happy-dom's `getComputedStyle` does not agree with Chrome. Read Frog takes the other road (a general walker with one computed style per element, `filter.ts`), at the price of 484 site rules to correct it; we are a single-site adapter, and the rule table is the domain model. Changing this rule bumps `RULES_VERSION`, now 0.7.1.

- **What LaTeXML marks as not displayed is never translated** [decided 2026-09-11, reported on 2509.10652v3]: the ACM template's `\Description{}` — the accessibility text a figure or table points at with `aria-describedby` — comes out as `<span class="ltx_nodisplay ltx_acm_description">`, which ar5iv hides with `display: none`. Our translation is our own node and carries no such class, so the caption's translation **printed the description**: several hundred words of prose, `\par` macros and all (LaTeXML leaves them unexpanded), under a one-line caption in the translated column — the user's report was "the middle of the page grew a screen of text out of nowhere". The same shape as `.ltx_contact_name` above and the same fix: a void placeholder, so it never reaches the engine and is rebuilt hidden. That paper has six of them, one per figure and table, 1.5–3k characters each — also the tokens they were spending. Translating the description properly (for a reader using a screen reader in Chinese) would mean placing a translation *inside* a hidden node, which the sibling-insertion invariant (§7.1) has no room for; not worth it for text no one sees. `RULES_VERSION` → 0.10.1, so the cached blocks that carry the description do not survive.
- **The `\intertext` of an equation group is body text, yet the group is still one atom to the enclosing unit** [decided, 2026-09-12, issue #152, the owner's report on 2609.09360v1]: `\intertext` is explanatory text between aligned formulas; LaTeXML renders it not as a `<p>` but as a cell spanning **a whole row** of the equation group's table (a `tr.ltx_eqn_row` without `.ltx_equation`, the cell carrying the group's `colspan` and `white-space:normal`). `.ltx_equationgroup` used to be a block-level skip, so the whole group vanished together with these notes: in side mode the right column showed the same English (that paper has 5 of them).
  - **The group moves from SKIP to PROTECT + `descend`**, the same shape as footnotes (`.ltx_note`): **a void to the enclosing unit**, **but the extractor keeps descending**. Both halves are necessary — removing it from SKIP alone would change what **other** blocks send out: in the 39 equation groups of 12 fixtures, 5 sit inside units such as `.ltx_item`, and the group would then be sent to the engine as a run of paired `<table><tbody><tr>` tags, spending tokens and adding risk to the placeholder protocol. With protect+descend, the wire text of 4691 blocks in 13 fixtures is **unchanged byte for byte**, and so is the block count.
  - **The unit is the row, not the cell**: the translation is the next sibling per §7.1, and a cell's sibling is the second cell of the same row — two `colspan`s would stretch the table to twice the columns and squeeze every formula flat; a row's sibling is a new row. The translated row's content sits in **a shallow clone of the original cell** (`eqnProseCell`) — text hung directly under a `<tr>` is not laid out by table layout at all, and the shallow clone carries the `colspan` and the alignment class.
  - **The spacer rows in a group need no special case**: they match the selector too, but the cell is empty, and `extract`'s “a block only with letters” keeps them out by itself.
  - **The protection of `.ltx_equationgroup` is not limited to `table`** (Codex on #168, P1): LaTeXML also emits groups in span form (measured: 2 of the 26 groups of 2312.17141 are `<span class="ltx_equationgroup …">`, both inside translation units). Narrowing to `table.` would strip them of their whole-block protection — the enclosing unit would serialise the whole group as one paired wrapper plus a run of independent voids, and since the provider **may reorder placeholders**, equation rows could swap places in the translated clone. Only the rendering and the split are limited to the table form (`EQUATION_GROUP_TABLE`: only it has `<tr>` rows, and only it is worth splitting in two whole).
  - **A group nested inside another unit gets no intertext blocks** (Codex on #168): the enclosing unit has already cloned the whole group into its own translation as one void atom, and an intertext row as a block of its own would show twice on the page — once in English inside the outer clone, once in Chinese inside the group — and the split would produce yet another copy under the original. Footnotes meet the same shape and get by with `localizeNotes` moving the translation into the copy and hiding the original; equation groups have no such step, so they simply form no block, byte for byte as before the change. **The criterion is “the enclosing unit really became a block”, not “an ancestor matches a unit selector”** (Codex on #168, two rounds): an `.ltx_item` holding only a nested `.ltx_p` and an equation group has no ownText and is no block at all, nobody clones that group, and judging by selector would wrongly suppress the intertext rows with it and leave the passage untranslated. So this step is left to the extractor — only it knows which units really emitted blocks: the traversal is pre-order, an ancestor is always finished before its descendants, and the `emitted` table is complete for the ancestors when this step consults it. The rule side keeps only a table of “which units give way” (`YIELDS_TO_OUTER_BLOCK`). Measured: of the 39 groups in 13 fixtures, 5 are nested and none of those has an intertext row — this plugs a hole, not a road.
  - **The translation, the skeleton and the failure widget share one shell** (`translationShell`; Codex on #168 pointed out the latter two were missed): with a special case for translations only, the waiting ring would hang directly under the `<tr>` and the failure widget would become a `<span>` child of `<tbody>`, neither fitting the table content model. The failure widget's pairing mark moves to the outer row accordingly, the widget itself staying in the cell.
  - **On a partial failure the retry button stays on the original's side** (Codex on #168): when one row of a group succeeds and another fails the split still happens, and the copy strips `.axt-error`; the original's copy is then hidden by side's styles, the reader sees the retry button in neither column, and that block is stuck failed for good. So that rule became `.axt-t:not(.axt-error)`. **In only mode this half cannot be fixed** (Codex on #168, fourth round): there the whole original is `display: none`, CSS cannot make a descendant of a `display: none` subtree visible again, and the copy cannot hold a live widget — `cloneNode` carries no shadow root, and **moving** the original's widget in would break `failedOf()` (which looks for “the block's next sibling”). The reader still has a way out: the popup's “{n} 处翻译失败 · 重试” retries the whole page in any mode. Recorded in issue #170. **The widget cannot be left in the copy instead**: `renderFailed`'s `attachShadow` is not `clonable`, and `cloneNode` copies neither the shadow root nor the event listeners, so what stays in the copy is an empty span. Two other long-standing defects of the split mechanism (no right-column copy while waiting / failed, so the layout jumps; the copy lacks `aria-hidden` / `inert`, so duplicated content is announced twice) **affect figures today as well**, are recorded in issue #170, and are outside this item.
  - **No second shell when rehydration already gives a cell** (Codex on #168, P1): on the placeholder path the whole cell is one paired placeholder, and the top-level element `rehydrate` hands back **is already a `<td>`**; wrapping it again gives `<tr><td><td>…</td></td></tr>`. The runs fallback path flattens the markup and hands back plain text, which still needs the shell, so the criterion is “is the fragment exactly one cell” rather than a branch by path. **The first version of the test used a bare text fragment and so did not catch it**; that case now goes through a real `serialize → rehydrate` round trip.
  - **A group with intertext rows is split rather than mirrored** (`SPLIT_ROOTS` grew from `figure` to `figure, table.ltx_equationgroup`): once a group holds a block mark, `needsMirror` no longer mirrors it, and letting the whole group span both columns would change the existing layout of “the formula once in each column” — visible to the reader. The same road as figures: clone once, delete the source member of each pair, the original group in the left column and the same group with the Chinese notes in the right. The split's deletion logic was general already (a next sibling carrying `.axt-t` is deleted); only the search root was hard-coded to `figure`. Measured on 2609.09360v1: table width and start unchanged (468px / x=240), the formulas still once per column, only the right column's notes turned from English to Chinese.
  - **`RULES_VERSION` is not bumped** [decided, 2026-09-12, the owner's call]: hard rule 6 says “a rule change bumps the version”, and a bump means **the whole site's cache voided** — every reader retranslates every paper they reopen (real money for LLM users). Not needed this time: the measured wire text of the existing blocks is unchanged byte for byte, and the cache key carries `normalizedText` anyway — should some uncovered shape change a block's content, its key changes **by itself** and cannot hit a stale entry. `RULES_VERSION` guards against “the same text should now be translated differently” (prompt / protocol changes); a purely additive rule change is not of that kind. **The criterion**: after the change, run the wire text of every fixture; only when it is identical byte for byte may the bump be skipped.
  - Performance: `splitFigures` enumerates the equation groups on every pass. On 2312.17141 (26 groups, 392 formula tables, the paper the long-task budget guards) the split went from 0.50 ms/pass to 0.67 ms/pass, the longest main-thread task 236 → 221 ms (within noise), budget 600 ms.


- **The terms of a description list are translated too** [decided, 2026-09-06, Codex on #18]: LaTeXML puts the term of `\item[Compactness]` into `.ltx_tag.ltx_tag_item`, and since tags are protected the whole `.ltx_item` has no text of its own and **is no block at all**, so the term is never translated. `.ltx_tag_item` joined `NAMED_TAGS`, routed by the existing content check: 371 in 12 fixtures, only 8 holding words (`Markov categories:`, `CD categories:`, `Compactness.`, `RQ1`–`RQ5`), the other 363 being markers like `(1)` `•`, voids as before. Measured with google-web: `RQ1` comes back as it is, `Markov categories:` becomes “马尔可夫分类：”; identifiers are not rewritten. The snapshot delta is exactly these 8
- ~~**The author paragraph of a reference looks at semantic markup first** (2026-09-06, Codex on #18)~~ **Withdrawn, 2026-09-06**: author paragraphs are no longer skipped (§5.4), and `isBibAuthorBlock` was deleted together with this check. What it solved was “which paragraph is the author paragraph”; that question no longer exists — every paragraph is translated
- **An `.ltx_tag` with an environment name is translated** [decided, 2026-09-05, the owner's feedback]: LaTeXML puts the **names** of theorem environments, figures, tables, algorithms and appendices into `.ltx_tag` too, so `Definition 1.1.` was protected whole as a number, and the Chinese reader still saw English. Split by subclass: `ltx_tag_theorem` / `ltx_tag_figure` / `ltx_tag_table` / `ltx_tag_float` / `ltx_tag_appendix` / `ltx_tag_part` / `ltx_tag_chapter` take part in translation; the rest (equation, section, subsection, ref, item, note) stay voids. **The class name alone is not enough**: LaTeXML uses `.ltx_tag_figure` for subfigure panel labels too, whose content is a bare identifier `(a)` `(b)` `(c)` (5 of the 387 named tags, Codex on #53); translated, the model would rewrite them and the link to the panel would break. So a content check `isNamedTag` is added: the class is on the list, and **after removing the parenthesised parts that hold only identifiers** two or more consecutive letters remain (a word other than a Roman numeral inside the parentheses is kept: a label parenthesised whole like `(Figure 1)` must not lose its environment name with the parentheses; Codex on #53). Counting letters alone is not enough — panel identifiers can be multi-letter Roman numerals like `(ii)` `(iii)`; and parentheses are precisely the shape LaTeXML gives identifiers, while an environment name never carries them (`Definition 1.2 (Hall set)` still has Definition once the parentheses are removed and is translated as it should be). The basis is the measured distribution of the 1241 `.ltx_tag` across all 12 fixtures: all 246 theorem tags look like "Definition 1", all 43 table tags are "Table 1:", 58 of the 63 figure tags are "Figure 1.", all 20 appendix tags "Appendix A", all 13 float tags "Algorithm 1"; conversely only 13 of the 344 equation tags carry letters (LaTeX labels like `(let.lin)`, not to be touched), the lettered ones among the 439 section / subsection / ref tags are all Roman numerals (II, III.1), and the 54 note tags are footnote marks. **Roman-numbered ones are never translated**: measured with google-gtx on 2026-09-05 (Codex on #53), `Table IV:` → `表四：`, `Table X:` → `表十：`, `Part I` → `第一部分`, while the `.ltx_ref` pointing at them is protected source text, so once translated the body and the cross-references no longer match; Arabic numbers (`Table 4:` → `表 4：`), letter numbering (`Appendix A` → `附录A`) and parenthesised panels (`Figure 1(a)`) were all measured to come back as they were. Google itself treats only I / V / X / L / M as numerals and a lone C or D as a letter, and `ROMAN_ID` judges the same way; a compound number is judged by its first segment (`Table IV.1` measured → 表四.1; `IV.1` / `IV-A` both count as Roman numbering), in either case (LaTeX's `\roman` gives `Table iv:`, measured → 表四：). The audit script `fixtures-stats.ts` counts rule hits through `classify()` too, not by selector, or it would record these released tags as protect/tag. A paper's numbering style is consistent, so a reader never sees “表 4” and “Table IV” together. The result on the fixtures: of 387 named tags 368 are translated and 19 protected (5 panel labels + 13 Roman-numbered tables + `Part I`). Changing this rule bumps `RULES_VERSION` (it enters the cache key), now 0.6.2. Measured on 2609.04056v1: theorem heading blocks went from 34 to 75, `Definition 1.2 (Hall set).` → `定义 1.2（大厅布置）。`

### 5.3 Tables [decided]

The whole **outermost** `.ltx_tabular` is handled as one unit (of the 58 tabulars in the fixtures 15 are not inside an `.ltx_table`, so the root cannot be `.ltx_table`; 3 are nested inside another tabular, and the inner one belongs to the outer cell; every `th` carries `ltx_td`, so the cell selector `.ltx_td` suffices; 239 `.ltx_td` belong to formula alignment tables, already skipped by `.ltx_equation`):
- side / stack mode: a translated clone table is inserted **below** the original, translated cell by cell inside the clone, numeric cells copied as they are
- only mode: the original table is hidden, the clone shown
- No side-by-side comparison inside cells
- **A cell is a segment inside the block; translation units inside a cell form no block of their own** (2026-09-05): the extractor does not descend into tables, so when the protector serialises a cell it walks into the `.ltx_p` / headings inside as ordinary paired nodes rather than treating them as voids the way nested units inside a paragraph are — otherwise the whole cell is one placeholder and all its text is lost (measured: the 38 cells of Table 1 in 2410.00260; Codex on #5)
- **Nested tabulars**: the inner cells are cells of the outer block too (`tableCells` takes any depth); an outer cell holding only a nested table has no text of its own and is copied as a numeric cell. When rendering, the cell in the clone table is located afresh before each replacement — the outer cell's translation carries a clone of the inner table, so the outer cell is replaced first, then the inner ones
- **A partial failure counts as a failure**: when one cell of a table cannot be translated, the translated cells still show and the block counts as failed, so the reader can tell “half translated” from “translated” (Codex on #9). The original table **stays `translated`** and gets `data-axt-partial` for the hint line — marking it `failed` outright would make only mode reveal the original together with the half clone (Codex on #30)
- The numeric-cell test (calibrated in Phase 0 on 5,487 real cells, RESEARCH.md §2.6): the **visible text with the protect / skip subtrees excluded** (not `textContent` directly, since MathML `annotation`s would mix TeX source in; the text of an `.ltx_p` inside the cell counts) is copied as it is when it satisfies any of:
  - `^(?=.*\d)[\s\d.,+\-±×^%()/*eE−–—:;~<>=≤≥∼]+(\s*[a-zA-Zμ°%]{1,4})?$` — a digit is required, so that words starting with E like `ERROR` are not taken for an exponent
  - `^[✓✗✔✘–—−\-·×*]+$` — pure symbol cells
  - `^N/A$`
  - Empty cells and pure-formula cells are copied directly; upper-case enumeration values (`TRUE` / `FALSE` / `UNKNOWN`) go to the provider, with no special case

### 5.4 Bibliography [decided]

- Translated by default. Corrected 2026-09-13: there is no switch for it — `config/schema.ts` has no references field and the settings page offers none (it read “can be turned off in the settings”)
- **Translated by the fragments inside an entry** (revised 2026-09-04): LaTeXML splits one reference into several `.ltx_bibblock` (authors / title / venue, one paragraph each, one line each on the page); the translation unit is `.ltx_bibblock` rather than the whole `.ltx_bibitem`, so the translation follows only the matching line and the entry is no longer repeated whole
- **The author paragraph is translated too; every paragraph of an entry alike** [decided, 2026-09-06, the owner's call]: the first paragraph (the author list) of a multi-paragraph entry used to be skipped alone by `isBibAuthorBlock`. That rule produced an inconsistency **the reader could see directly** — in single-paragraph entries (natbib, AMS, AAS and similar styles) the whole paragraph is the citation, and the author names mixed into it **were being translated anyway**; 7 of 12 fixtures are of that kind and the other 5 are multi-paragraph, so the same extension behaved oppositely on different papers. §5.2 opened up author names in the body the same day, and holding them back here had even less ground. With the skip removed, the `.ltx_bibblock` unit rule takes over by itself; `isBibAuthorBlock` and the `bib-authors` rule id were deleted with it.

  **What it hid was not only names** (measured on 2609.03896, the owner's report): judging by position, on a template whose “first paragraph is the whole citation, second is the doi” it **skipped whole entries** — in 12 of 13 references only the doi line was translated and the body untouched; the one translated, [3], happened to be the one without a doi paragraph and so with a single paragraph. Codex had raised this risk on #18 (“when some template puts the authors in another paragraph, a pure position check skips the title as the author paragraph”); this is it, and harsher than expected: what was skipped was **all** the content, not only the title. With the position assumption gone, this kind of template can no longer go wrong.

  **The cost, measured** (12 fixtures): 285 more blocks, 25609 more characters, **+5.7% blocks / +2.2% characters** of all translation units. In side mode the new blocks **all connect** to the translation root (numerator and denominator in the snapshot grow alike, `blockedBy` unchanged), so no extra container coverage is needed.

  **Translation quality, measured** (google-web, the worst case among the free engines): an author paragraph sent alone is **more readily transliterated** than one mixed into the whole entry — sent whole, Google tends to keep it (`W. Arendt 和 AFM ter Elst`, `Agha, G., Palmskog, K.:`), sent alone it transliterates (`史蒂文·阿兹特、齐格弗里德·拉斯托弗…`). Two concrete defects: an institutional author taken for a common word (`Anthropic.` → `人类学。`), and the periods of initials eaten (`V. I.` → `VI`, `M. D.` → `MD`, which read like Roman numerals). **The LLM path has no such problem**: the default prompt's line “Keep author names, journal names, conference names, dataset names, code identifiers and URLs in the original language” makes the author paragraph come back as it is.

  **These defects are known and accepted, and no rule may be added for them** [decided, 2026-09-06, the owner's call]: a translated name inevitably loses accuracy — that is the nature of translation, not a bug rules can fix. Trying to fix it slides toward name dictionaries, engine special cases and dedicated prompts — a long-term maintenance cost carried for one line in the bibliography, which does not pay. **The criterion is “roughly right on the whole”, not “accurate”**: a transliteration or a gist that matches is enough; the reader locates the original by other means.

  **Traceability is guaranteed by the placeholders and does not depend on how accurately a name is translated** (measured on the real pipeline, 2609.03001v1): the author paragraph is sent to the engine in the shape `<t id="1">L. A. Anchordoqui, …, and A. Westphal</t><t id="2"> (2026)</t>` — the year is `.ltx_bib_year`, **in a void placeholder of its own** (corrected 2026-09-13: it was a paired placeholder when this was measured, hence `<t id="2"> (2026)</t>` in the shape above; Codex on #74 showed that a paired placeholder's content still gets rewritten, and `bib-year` is a void in `PROTECT_RULES` now); the DOI / arXiv link (`.ltx_bib_external`) and the cross-references are void placeholders (`Cited by: <x id="1"/>.`). The placeholder protocol demands they come back as they were, and a translation that fails validation does not even enter the cache (§8.2). So the numbers, years and links are rewritten by no engine, and in the bilingual modes the original name is always beside — neither of the reader's two ways of locating the original depends on the name
- only mode no longer exempts whole entries (see §7.4): the author paragraph, untranslated, stays as it is by nature; the title and venue paragraphs show the translation only
- A DOI / URL is itself an `<a>` and is kept automatically through the placeholders
- The LLM prompt always carries one line: personal names, journal names and conference names stay in the original

### 5.5 Rule versioning

- The rule file exports `RULES_VERSION`, written into the cache key
- The fixtures cover several fields and structures (`tests/fixtures/arxiv/README.md`), each recording its generator version; any rule change must pass every fixture test
- arXiv has regenerated its whole history with LaTeXML oxide 0.7.6, so no older-version output exists online (versioned URLs included) and **the year is no proxy for the version**; the fixtures are fetched again when the generator version changes (RESEARCH.md §1)
- Should LaTeXML versions differ enough to need a fork, handle it as `rules/latexml-v1.ts`, `rules/latexml-v2.ts` + a detection function, not by piling ifs into one file

### 5.6 Rule interface and precedence [decided]

`src/core/rules/latexml.ts` exports data tables and pure functions only, no traversal (the traversal is in the extractor, see §4.1):

- Tables: `UNIT_RULES` (§5.1), `TABLE_RULES = { root: '.ltx_tabular', cell: '.ltx_td' }` (§5.3, the root being the outermost), `SKIP_RULES` (the block-level parts of §5.2 left untranslated whole), `PROTECT_RULES` (the void nodes of §6.1, each rule may carry a `descend` flag). `math` appears in PROTECT only — display formulas are skipped whole by `.ltx_equation` already. The paired node rules (§6.1) are added to this file by the Phase 2 protector
- Functions: `documentRoot(doc)`, `classify(el) → { kind: 'skip' | 'table' | 'unit' | 'protect'; rule: string } | null`, `isNumericCell(visibleText)`
- **Precedence**: an element matching several kinds takes `skip > table > unit > protect`. A `skip` hit inside a translation unit (such as an `.ltx_ERROR` inside a paragraph; one case in the fixtures) is equivalent to a void for that unit
- `RULES_VERSION` is bumped with any behavioural change of a table or function, and enters the cache key

## 6. Placeholder engine

Location: `src/core/protector/`. This is the hardest and most valuable module of the project, implemented from scratch (Phase 2; CLAUDE.md's porting boundary lists it as an exception); the idea of the completeness check is borrowed from Read Frog's `html-attribute-markers.ts`.

### 6.1 Node classification

| Kind | Placeholder | Nodes |
|---|---|---|
| void | `<x id="n"/>` | inline `math`, `.ltx_ref` (with the `.ltx_ref_tag` inside), `.ltx_cite`, `.ltx_tag`, `code`, `.ltx_font_typewriter`, the whole `.ltx_note` (the footnote body is a block of its own), `.ltx_note_mark`, `.ltx_note_type`, `.ltx_contact_name`, `.ltx_nodisplay`, inline images, `svg`, `br`. **Must be written into `latexml.ts` as `PROTECT_RULES`** — the Phase 0 audit found that with the skip rules of §5.2 alone, `.ltx_ref` / `.ltx_cite` / `.ltx_note_mark` would be treated as paragraph text (3,500+ elements in the fixtures in all, RESEARCH.md §2.5)|
| paired | `<t id="n">…</t>` | an `a` with text, `.ltx_text.ltx_font_italic/bold/...`, `em`, `strong`, other `span`s holding translatable text |
| text | appears directly in the text | text nodes |

### 6.2 Serialisation

```ts
interface ProtectedBlock {
  blockId: string
  format: WireFormat                 // 'tags' | 'markers'; validation / rehydration / cutting tokenise by it
  text: string                       // the text with placeholders
  slots: Map<number, Node>           // id → reference to the original node
  paired: Set<number>                // which ids are paired (always empty under markers)
}
```

- Placeholder ids count up from 1 within a block; the `markers` format encodes the id as bijective base-26 letters (1→a, 27→aa), because MT engines reorder and merge digits
- **`markers` has no paired placeholders** (measured on #104: paired markers survive Google at only 70.6%, unusable): apart from “elements with a function”, kept whole as voids to stay clickable (the same judgement as issue #44 in §6.5), every other paired element is flattened to plain text. What is lost is the styling of inline wrappers, not content
- **A block's leading label is put back at rehydrate time** [decided 2026-09-10, issue #150]: of the styling that flattening loses, the one a reader meets on every page is the run-in label a block opens with — `Keywords:`, `Note.`, `Contributions.`, an italic theorem statement (reported on 2608.14896v1: Microsoft's "关键词：" was not bold). These can be put back safely: when the original block opens with a formatting-only element (bold / italic / small caps / `\emph`, ≤ 8 words, only whitespace before it, carrying its separator nowhere but at its end) that ends in or is followed by a colon, ends in a period, or is the whole block, the first matching separator in the translation ends the label's translation; the prefix goes into a shallow clone of the element if it is no longer than the label plus a slack that depends on its script (Han / kana / hangul run shorter: + 4; scripts that run longer, such as French or German: × 2 + 4), holds no sentence terminator, and carries exactly the label's own placeholders (by slot identity — the engine may reorder them). Separators are recognised in the target's own script (`。．`, the danda `।`, `۔`, `։`, `።`, `။`, `།`), and a separator of the other kind before the candidate means the engine changed the label's — left alone. **A period label additionally needs the engine's own sentence boundaries as evidence**: a period is the one separator a body sentence ends with too, and a translation that drops the label's period leaves `注意 好。` (label plus a short body sentence) indistinguishable from a label translated long. The engine's first sentence must end at the label on the source side and at the cut on the target side; every way of merging the label into the body moves a boundary or changes the sentence count (which fails verification upstream). Replayed over the 59 period labels the rules restore, all 59 carry this evidence; a block without a verified alignment gets no period-label restore. **It under-wraps, never mis-wraps**: any failed condition leaves the translation as it is. The wire text is untouched, so translations and cache keys do not change. Measured by replaying 115 such blocks from 12 fixtures and the reported paper through the Edge endpoint on the real `serialize(…, 'markers')` output: colon labels 46/46 boundaries correct; of the period labels, 9 carry an inner abbreviation and are refused, the rest wrap 58 of 59 with the one miss (`..` rendered as an ellipsis) rejected by the bound. The text node the cut lands in is split together with its `WireSpan` (anchors re-based at the cut), or the hover highlight's offsets on that block would be wrong
- **Plain-text round trips** (the title §10, OCR lines §15.2) have no tokeniser and go `escapeText` → translate → `unescapeText`. The placeholder path must not use `unescapeText`: on that path `@@` is already restored inside `tokenize`, and a second pass would eat a literal `@@` down to `@`
- **Unforgeability**: the correctness of validation and rehydration rests on “every placeholder that appears on the wire must have been written by us”. `tags` relies on unconditionally escaping `& < >`; `markers` on **unconditionally** doubling every `@` — after escaping, the number of `@` in every run of literal text is even, the decoder consumes `@@` in pairs from left to right, and a lone `@` left over is necessarily the start of a marker.
  **The escaping must be context-free**: serialisation escapes text node by text node and concatenates, and the ambiguity of conditional escaping arises at the joins (the `@` of `<p>@<math/></p>` needs no escaping on its own, but joined with the placeholder it becomes `@@a#`, and the placeholder is read as a literal and vanishes). The cost, measured: of the 779160 marker-format wire characters in 12 fixtures only 5 are `@`, so doubling adds 5 characters in all
- `markers` **escapes `& < >` too**. It once did not, on the grounds that “this line is plain text” — an assumption about the engine, not a fact: `google-web` goes through `translateHtml`, which parses the request body as HTML. Measured: the markers wire text holds 102 `&`, 1 `<` and 3 `>`, spread over 80 of 5992 blocks, all genuine content (`Springer science & business media`, `Very long (>1k words) … (<500 words)`). Escaped, this line holds for HTML and plain-text transport alike, and no provider needs a codec layer of its own. Entities are decoded **after tokenising**, so an `&#64;abc#` coming back from the engine is not read as a marker
- The positions of `&nbsp;` and thin spaces (` `) around formulas are kept; inner whitespace is not trimmed when serialising
- A block whose void placeholders exceed a threshold (initially 40) counts as formula-dense: it still takes the tags path but forms a batch of its own

### 6.3 Validation

A translation must satisfy the following, or it counts as failed:
- the set of void ids equals the source's exactly, each appearing exactly once
- paired tags are matched and nested legally
- no id absent from the source appears

Failure handling: one retry of the single block (the prompt gains an emphasis that “placeholders must be kept as they are”) → still failing, fall back to the runs path → runs failing too, the block is marked untranslated and shown in the UI

**The survival rate is measured, not assumed** [2026-09-11]: `pnpm e2e:placeholders` feeds a synthetic paper (12 sentence shapes × a placeholder at the start / middle / end of the sentence / against punctuation / two adjacent / a number between operators / three in one sentence / a citation / a cross-reference / paired tags / seven in one sentence) to real engines and judges pass or fail by **counting `math` / `.ltx_cite` / `.ltx_ref` in the translation**. The page fakes `arxiv.org/html/<id>` with `page.route`, never touching arXiv, yet runs the whole pipeline. First round: Google Translate (`tags`) and Microsoft Translate (`markers`) × Simplified Chinese / Arabic / Japanese, **60/60 all came back as they were**, including the only loss shape Read Frog ever saw, `256×256` (on their side deepseek-v4-flash writes the `×` out itself instead of copying the placeholder). The methodology is borrowed from their PR #2155 — that probe made 739 live requests and concluded that the tolerant decoder should be **tightened** to strict matching. The LLM path needs a key of one's own; the tool accepts an engine name argument.

### 6.4 Rehydration

- A placeholder is replaced by a **clone** of the node in `slots` (`cloneNode(true)`)
- Cloning strips every `id` attribute in the subtree, so duplicate ids do not break anchors; `href` is kept
- **A clone carries no behaviour** (2026-09-11, the independent audit's B17 + Codex on #163): `stripInjected` also removes `on*` event attributes, and the script-running URLs (`javascript:`, `data:text/html`) in `href` / `src` / `action`. The copy inside a translation is for reading and must not be a second control that can fire. The scheme is judged after normalising by the URL standard — tabs and newlines removed anywhere, C0 controls and spaces stripped from the front — or a scheme with control characters inside, like `href="java&#10;script:…"`, would not match while the browser still runs it as `javascript:` once parsed. `data:image/...` stays: real inline images exist in papers. arXiv's LaTeXML emits no event attributes today; this pins the invariant, it does not fix a known fault
- All three modes use the clone; the original node is never touched (only mode hides the original block, it does not move the node)

### 6.5 The runs path

- **Elements with a function are kept whole** [decided, 2026-09-05, issue #44]: lost styling is still readable, a lost link can no longer be clicked — the fallback must not turn clickable content into plain text. `a[href]` (`FUNCTIONAL_INLINE`) is treated as a void on this path: kept whole as it is, the text inside untranslated, the `</t>` counted by nesting depth when skipping so an inner closing tag does not end it early. **Measured: of the 4221 translation blocks in 12 fixtures, 0 hold such a link** — the links in arXiv body text are all `.ltx_ref` cross-references or mailto, kept as protected nodes by the rule layer already — so this fixes no fault in progress; it turns “the fallback loses styling only, never behaviour” into a structural guarantee, and covers v2's other paper sites

Reserved for engines with `wireFormats: []` (none of the placeholders survive), and also the fallback after a validation failure on the tags / markers paths. The three free engines of v1 were all measured to keep placeholders (RESEARCH.md §5 / §6), so in v1 runs exists mainly as a fallback, but the implementation cannot be skimped:
- The block is cut into text segments at the void nodes (the text inside a paired node joins its segment, losing the styling)
- Each segment is translated on its own and joined back in the original order, with clones of the void nodes inserted back in place
- The known cost: a sentence interrupted by a formula is translated in pieces; an acceptable degradation
- The cache key carries `renderPath`; the translations of the two paths are not reused for each other

## 7. Rendering in three modes

Location: `src/core/renderer/` + `src/styles/modes.css`.

### 7.1 DOM invariants [decided]

1. The translation node is the original block's **next sibling**, with the same tag name as the original block, the class being **the original block's classes plus `axt-t`** (`p.ltx_p` → `p.ltx_p.axt-t`), and `data-axt-for="<blockId>"`. The classes are copied to inherit the site's styles: the main title's centring and size, the grid columns of bibliography entries, the font size of every heading level are all set by `ltx_*` classes, and without copying they are all lost (measured 2026-09-03: the main title misaligned left, an `li.axt-t` dropping into the 12em-wide first column of the bibliography with a bullet). Any element cloned into a translation (a whole table, an `.ltx_note` rehydrated from a placeholder, and so on) has its `id` and every `data-axt-*` stripped
2. The original node may only gain attributes prefixed `data-axt-` — `data-axt-id`, `data-axt-state` and `data-axt-inline` at first, later `data-axt-partial` (§5.3), `data-axt-note` (§7.2), `data-axt-split` (§7.2), `data-axt-fit` (§7.2) and `data-axt-identity` (§7.3); **its subtree is not changed** (corrected 2026-09-13: the list of three had gone void; the rule is the prefix, and `restore()` strips every `data-axt-*`)
3. Global state lives on `<html>` only: `data-axt-on`, `data-axt-mode="side|stack|only"`, `data-axt-lang`, `data-axt-dir`
   - **A translation node has to carry `dir`, not `lang` alone** [decided, 2026-09-11, after Read Frog's `setTranslationDirAndLang`]: `lang` says “which language this is”; a paragraph's **base direction** is set by `dir`. arXiv's `<html>` is ltr, and once a translation inherits that, the final punctuation, digits and Latin words in Arabic all sit on the wrong side — measured on 2509.10652v3 translated into Arabic: `مساهمات متساوية.` rendered as `مساهمات .متساوية` (the full stop before the word), and the whole passage still left-aligned. The target-language table has 13 right-to-left languages (`RTL_LANGUAGES`, of which `prs` / `pbu` / `skr` have no two-letter code and fall back to 639-3 when sent to the engine, so the check has to recognise both spellings). **When the tag carries a script subtag, the script decides, not the primary language** (Codex on #163): the tag sent for `zlm` (Jawi Malay) is `ms-Arab`, while `ms` is also Latin-script Malay — judging by the primary subtag alone would miss Jawi as ltr, and treating `ms` as an RTL primary subtag would misjudge Latin Malay as rtl. So `RTL_PRIMARY` holds only the tags without a script subtag, and those with one go to `RTL_SCRIPTS` (`arab` / `hebr` / `thaa` / `syrc` and so on, 11 in all); the reverse cases like `ur-Latn` come out correctly as ltr too. `enable()` records it once on `<html>`, and `renderText` and the image overlay copy it one by one — **only onto real translations**: the skeleton and the failure widget are in the interface language, and the mirror holds the original. Measured after the fix: punctuation back in place, the two columns still equal (548 / 548, the original still in the left column), zero `dir` on skeletons / failure widgets / mirrors
   - **A translated table's `lang` / `dir` go on the cells, not on the table** [decided, 2026-09-11, Codex on #163]: tables go through `renderTable` (the whole table cloned, the content replaced cell by cell), not `renderText`, and on that path neither attribute was written — a screen reader would read the Chinese in the table in an English voice, and under RTL the punctuation inside cells was misplaced too. They go on **the cells whose content was replaced**: `dir` on the `<table>` would flip the column order with it, and the untranslated numeric columns in the clone are still the original, so a flipped order would no longer line up with the original table above; on a cell it changes the base direction of that cell's text only. Cells whose content was not replaced stay as they are — they still hold the original.
   - **The source atoms inside a translation still run left to right**: MathML Core applies `direction` straight to the row layout, and inheriting rtl would lay `a+b` out as `b+a`; the inline code, typewriter identifiers, citations, URLs rehydrated from placeholders and the English original inside a margin-note copy (`.axt-note-s`) likewise, and something ending in a neutral character like `f(x)` has its parenthesis moved to the other side by the bidi algorithm (Codex on #163 pointed out that only formulas were covered). `unicode-bidi: isolate` is added as well, so each atom is embedded in the rtl paragraph as a whole. Written in the style sheet (`html[data-axt-dir="rtl"] .axt-t :is(math, .ltx_Math, .ltx_ref, .ltx_url, .ltx_listing, code, .ltx_font_typewriter, .axt-note-s)`) rather than attribute by attribute — what is rehydrated into a translation, what sits in a mirror and what sits in a split copy is one and the same thing, inserted by three different code paths (measured on 2512.02012v1 translated into Arabic: all 20 formulas in the translation `direction: ltr`)
4. Restoring the original = deleting every `.axt-t` **and `.axt-img`** (the image overlay, §15.2), deleting every `data-axt-*` attribute, removing the injected `<style>`; after the restore the DOM must equal the pre-translation DOM node by node (guarded by tests)

### 7.2 side (side by side)

- The core trick [redone 2026-09-04; revised 2026-09-05]: pairing is structural — **a block carrying the block mark `data-axt-id` always takes the left column, the right column waits for its translation**, and one without a block mark but followed directly by an `.axt-t` sibling (the original of a mirror) takes the left column likewise. The block marks are set the moment the translation session starts (§10), so the whole page turns two-column at once when translation begins and never jumps sideways afterwards; before, only `.axt-t` siblings were recognised, and under lazy loading the blocks beyond the preload distance stayed full-width, shrinking to the left column only on entering the margin, so the page jumped sideways as it scrolled (the owner's feedback). The layout is decided by “this block is in the translation session”, not by “its translation has arrived”. The two column lines are **defined once, on `.ltx_document` only**; every other container inherits the same lines with `grid-template-columns: subgrid` and spans both itself; inside a container the default is full width, a paired original takes the left column and `.axt-t` the right:

  ```css
  container > *              { grid-column: 1 / -1 }
  container > :has(+ .axt-t) { grid-column: 1 }
  container > .axt-t         { grid-column: 2 }
  ```

  So headings, captions and bibliography fragments are all paired side by side without a rule each. No wrapper is needed, and anchor ids are unaffected
- **An exclusion may only be an element that forms no grid of its own** [decided]: excluding an ancestor does not stop its **descendants** from `subgrid`ding that foreign grid. ar5iv's `.ltx_enumerate` was once on the exclusion list, and the `.ltx_para` inside the list items subgridded its numbering grid (`12px | 780px`): the English straddled the divider and the Chinese was squeezed into a 39px strip (measured on 2609.00097). Every element ar5iv itself sets as a grid (`.ltx_enumerate`, `.ltx_item`, `.ltx_biblist`, `.ltx_bibitem`) must be **taken over**; taken over, the same fixture's connectivity rose from 750/826 to 820/826
- **Multi-panel figures are not taken over** [decided, 2026-09-04]: ar5iv puts the panels side by side with the flex of `.ltx_flex_figure` / `.ltx_flex_cell`. The subfigure captions inside them are translatable blocks, so the whole figure satisfies `:has(.axt-t)` and is taken over as a grid, and `> *` then gives every panel `grid-column: 1 / -1`: the panels go from side by side to one row each, filling the whole article column (measured on 2410.00260: originally left 321 / 721, 398 wide each; taken over, both at 321 and 798 wide; the three panels of 2312.17141 likewise). **A flex container can safely be excluded** — a descendant has to be a grid item before it can subgrid, and with a flex parent it cannot reach the outer tracks, so the `.ltx_enumerate` accident of “excluded yet still subgridded” cannot recur; the cost is that pairs inside the cells must be explicitly degraded to stacking (next item), or each grows an implicit two columns of its own. Measured after the exclusion: the three panels back side by side (225 / 551 / 877), connectivity 820/826 → 817/826, the 3 missing pairs being exactly the subfigure captions moved into the cells and shown stacked
- **Stacked areas** [decided]: inside `.ltx_td`, `.ltx_inline-block` and `.ltx_flex_cell` there is no two-column split; pairs degrade to stacking — they are either containers nested inside a paragraph or only half a column wide. The inner rule is written `:is(.ltx_para, .ltx_abstract, :has(.axt-t))` rather than `:where(...)`, since its specificity has to beat the (0,2,1) container rule
- **List markers have to leave the grid flow, and each column gets one** [decided, 2026-09-04]: ar5iv lays markers out three ways — itemize hangs them with `li.ltx_item > .ltx_tag { margin-inline-start: -2.5rem }`, enumerate uses its own two-column grid with `grid-area: 1/1`, description uses `dt { float: inline-start }`. Once a list item is taken over as a grid, all three are **blockified as grid items**: the marker becomes a full-row block, sitting on a row of its own above the text (measured on 2312.17141: all 89 list items, the marker stretched to 388px wide). An absolutely positioned child is no grid item and is not blockified, so the markers are made absolutely positioned; **the mirror marker has to land in the right column's slot** (`inset-inline-start: calc(50% + var(--axt-gap) / 2)` — the item spans both columns, its width = 2 × column width + gap, so 50% + gap/2 is always column width + gap), or it stacks on the original marker at the same spot in the left column and the right column has no number (the owner's measured feedback)
- **List indentation may only go on the cell content** [decided, 2026-09-04]: **a subgrid container's own inline padding eats the first track**. When the list container (the UA's `padding-inline-start: 40px` on `ul`) or the list item carries padding, the left column is squeezed narrower and the right column is flush, hence “the English is indented, the Chinese is not” (measured on 2312.17141: left column content 444px, right 484px). The inline padding of list containers and list items is zeroed and 2.5rem added to the **cell content** instead (`:has(+ .axt-t)` and `.axt-t` each): the cell content's padding affects only itself and leaves the tracks alone. Measured: 89/89 items symmetric across the two columns — markers 224 / 732, text 264 / 772, column width 484 / 484
- **A footnote appears once at the page's right edge, the original above and the translation below** [decided, 2026-09-05, the owner's call]: arXiv renders footnotes as margin notes hanging at the **page's right edge** (permanent at viewport ≥ 96rem: `.ltx_note_outer` uses `float: inline-end` plus a negative `margin-inline-end` to push it outside the article; narrower, it collapses and pops up on hover). **That position is right; leave it**. What has to be solved is the same footnote appearing twice: the paragraph translation is rehydrated by the placeholder protocol, the footnote is a protected node, and so the translated paragraph rebuilds a copy of the source footnote. `localizeNotes` (`src/core/renderer/notes.ts`) moves the footnote's translation **from the original into that copy** (the copy thereby becoming source + translation stacked), and the original gets `data-axt-note="moved"` and is hidden by the style. Before moving it in, **ar5iv's footnote frame has to be shed**: the translation node is itself an `.ltx_note_content`, and nested into the copy it becomes a “frame inside a frame” — an extra `double` top rule, an extra 9.6px indent, and its own number, absolutely positioned, flies into the body text (measured; the owner's feedback was “the position is a mess”). Hung on our own `.axt-note-t` instead (`display: block` + 0.35em top margin), the border goes to zero and the surplus numbers 2 → 0. Measured on 2312.17141: document 522→2026, margin notes 2042→2522 (at the page's right edge outside the document), one copy left in both side and stack. **A footnote that can never be translated (body all URL / formula) gets this mark too**: its copy is identical to the original byte for byte and the translation will never come; unmarked, it is the same margin note painted twice (the 6 in the introduction of 2509.10652v3, the owner's feedback of 2026-09-11). But **it is not marked when some mode hides the copy whole** (Codex on #163, three rounds, completed one by one: identity copies, split and mirror copies, and the branch where the translation has arrived — the guard had grown only on the “unregistered footnote” branch, while a registered footnote vanishes together with its translation just the same, because that margin box in the original holds exactly source + translation): a `data-axt-identity` copy and a split copy `.axt-split` are `display: none` in stack, a mirror `.axt-mirror` is `display: none` outside side, and the copy is the only one of this footnote left — marking the original hidden too takes the whole footnote off the page. The cost of keeping the original is that in side mode this footnote shows twice, the same trade-off as “when the engine changed the text, both stay”: a duplicate beats lost content.
  **The two detours avoided** (both rejected by the owner in real reading): (1) pulling the margin note into the column (`margin-inline-end: 0` + a width cap) — the body text gets squeezed, and ar5iv hard-codes `height: 0; overflow: visible` on footnotes inside list items (hanging outside the article they need no room), so pulled into the column the content covers the next list item (measured: box 32 high, content 90 high, covering 2 elements); (2) copying the translation into the copy and hiding the translation inside the original with a style — splitting one thing into a CSS half and a JS half, and whenever that pass did not run (a mode switch, a pair count mismatch) the Chinese vanished into thin air, and switching to stack made three copies.
  The present approach avoids both: the position is left entirely to arXiv; the relocation is a **move** and idempotent, and when it has not run it falls back to the old “source + translation side by side” look without losing content; only the copy that **was really moved** is hidden. Copies and originals correspond one to one in document order, and when the counts differ the whole passage is skipped
- **A note's box does not size the grid row** [decided 2026-09-10, reported on 2609.09360v1]: in side mode every paragraph is a grid item and so a BFC, which contains the note box ar5iv floats to the page's edge — in the original layout the paragraph is an ordinary block and contains no float, hence no blank. Measured: the translation's grid item was 1321px for 54px of text, leaving both columns 1300px blank. `.ltx_note_outer` is zero-height with `overflow: visible` in side mode (ar5iv's own device for notes inside list items) — body footnotes only, since a frontmatter note with a translation is put back into the article's flow as a two-column grid and must keep its height (Codex on #154); the item drops to 56px. The cost: two adjacent long notes can overlap in the margin, which beats a blank row. The peek's margin check (§7.7) therefore measures `.ltx_note_content`: a `.ltx_note` root is an inline anchor a few pixels wide, and the box itself is now zero-height
- **…which is also what makes one float step aside for another, so the notes are stacked by hand** [decided 2026-09-11, reported on 2509.10652v3 and 2609.10326v1]: a float only avoids another float inside the same formatting context, and zeroing the height cancels that avoidance along with the row sizing. Two notes anchored a line apart then draw on top of each other — 2509.10652v3's opening sentence carries six, whose boxes came out 32px apart with 50px of text in each. Giving the height back (only where a block holds more than one note) was tried the same day and is exactly the blank row again: on 2609.10326v1 two long notes turned a 162px row into a **1442px** one. One number cannot serve both, and CSS offers no second knob — `max-block-size` only buys a worse version of each (at 12em, that row is still 326px and the two notes still overlap by 300px). So the height stays zero and the position is measured: `renderer/margin-notes.ts` reads every margin note in document order once per pass and pushes each below the previous one with `transform: translateY()`, which no box's height can see — no row grows, nothing reflows, and the result is the rhythm arXiv's own page has. Measured at 1600px: 2509.10652v3's six notes go from 32px apart (28–69px of overlap) to 99px apart with none, its row staying 395px; 2609.10326v1's note 2 is pushed 406px clear of note 1, its row staying 162px. It runs as its own coalesced task after the prep pass, never a read-after-write inside one (§10): the whole document has to be measured at once (what a note must clear depends on every note before it) and what it measures is what that pass just wrote — the translation that made the note taller, the table that moved the block. Only the copies are moved: the original is not ours to restyle (§7.1), so an untranslated note stays where it is and the ones after it step around it — and the immovable ones are obstacles **in both directions** (Codex on #163, in two rounds): the floor only ever moves down — an original sitting above it would otherwise pull it back up and the next copy would land on the copy before it — and a copy also steps around any original it would cover, including ones later in the document, since a long note spills past the next block's original and that original cannot be asked to move. Copies therefore give way generously while blocks are still untranslated; each original disappears as its own block is translated, and the next pass takes the room back. Leaving side mode clears the shifts (`clearMarginNotes`), since every other mode lets the floats size themselves and avoid each other the ordinary way

- **A note that will never be translated is deduplicated too** [decided 2026-09-11]: the original is hidden once the copy in the translation reproduces it, not only once a translation has arrived. A note whose content is a bare URL or a lone formula has no letters in it, so the extractor never registers it as a block and no translation is ever coming; waiting for one left the original showing beside a copy saying exactly the same thing — one note painted twice, the boxes 24px apart (the six URL footnotes above, which is half of what that pile was). A *registered* note keeps waiting: hiding it early would take its skeleton with it, and after a failure the widget the reader retries from (Codex on #153). The text must match word for word; against a copy the engine mangled both stay on screen, since a duplicate beats a note gone missing
- **Footnotes are excluded with their whole subtree** [decided, 2026-09-05]: ar5iv keeps the collapsed state on `.ltx_note_outer`'s `display: none`. With only `.ltx_note` itself on the exclusion list, the moment a translation is inserted inside a footnote, `.ltx_note_outer` / `.ltx_note_content` satisfy `:has(.axt-t)`, are judged containers and turned into `display: grid` — **the collapsed footnote is unfolded**, 165px high and 781px wide across the body text, interfering with the middle column's translation (measured on 2312.17141, the owner's feedback). The style sheet adds `.ltx_note *` to the exclusion list; on the TS side it cannot be folded into `SIDE_CONTAINER`, because **happy-dom's `:is(.ltx_note *)` is always false** (native `.ltx_note *` works), and folding it in would make the tests disagree with the live behaviour — the check is `closest(SIDE_DENY_SUBTREE)` inside `isSideContainer()` instead, and the runtime always goes through that function. After the fix the footnote collapses again (height 0), the translation still inside it, and both source and translation show when unfolded
- **What floats to the page's outer edge is not mirrored** [decided, 2026-09-05]: publication metadata (`.ltx_pubnotes`: DOI / journal / CCS) and footnote contents are both floated out of the article by ar5iv with `float: inline-end` and a negative margin. They have no translation, and mirrored as “unpaired content”: the right column's copy's floated content lands at the page's right edge (correct), **the left column's lands on the right column** (measured on 2312.17141: the content floated to 1320→1752, over the right column), plus a whole duplicated block of metadata on the page (the owner's feedback). Unmirrored, it spans naturally (the default placement of `& > *`), and the floated content lands back at the page's right edge 2084→2516, as in the original layout. The list `MARGIN_ASIDE` lives in `rules/latexml.ts` (`ltx_*` may be written there only)
- **No mirrors inside stacked areas** [decided, 2026-09-04]: the point of a mirror is “do not leave the right column empty”, and a stacked area (`.ltx_td` / `.ltx_inline-block` / `.ltx_flex_cell`, see `SIDE_STACK`) has no right column at all; a mirror only adds a duplicate in the same column. Measured on the three-panel figure of 2312.17141: every panel's formula was copied, and each panel's content appeared twice on the page (the owner's feedback “the layout is strange”). `createMirrors` therefore skips containers with `closest(SIDE_STACK)`
- **The `\resizebox` wrapper is no inline context** [decided, 2026-09-07, the owner's feedback on the tables of 2606.07636v2 crossing the divider]: LaTeXML gives `\resizebox` a `div.ltx_inline-block.ltx_transformed_outer > span.ltx_transformed_inner > table`. `.ltx_inline-block` is on the exclusion list (`atomicContext`) and in the stacked areas (`stack`), so the wrapper is no pairing container: it spans by `& > *`, the inner is squeezed to `display: block` by the stacking rule, and the source and translated tables inside are two `inline-table`s, **centred in one row** inside the full-width shell — straddling the divider (measured on 5 tables: source 91–721, translation 721–1229, the column line at 648), while a wide table wraps and each takes the full width. **The wrapper is exempted** (`.ltx_inline-block:not(.ltx_transformed_outer)`): it is no inline context to begin with; ar5iv's own style sheet flattens its width, height and the inner `transform` with `!important` (`.ltx_table > .ltx_transformed_outer > .ltx_transformed_inner { width: initial !important; transform: none !important }`), so it is only a shell holding one thing. Exempted, the wrapper and the inner both become subgrid containers, and the table pair falls back onto the two column lines (measured: 5/5 pairs exactly on 0–648 and 672–1320). **Not a regression**: `.ltx_inline-block` has been on both lists since the structural container refactor (2026-09-04); fixture `2608.29808` has 13 tables of the same structure (13 pairs blocked by `ltx_inline-block` in the snapshot, all 437/437 connected after the fix), but `e2e:layout` never ran that paper, so it was never found
- **The scale step is set by the wider of the source and translated tables** [decided, 2026-09-07]: `fitTables` used to measure the source table alone and write the same step to both. When the Chinese header is longer the translated table is wider — measured on Table 4 of 2606.07636v2: the source at the 0.75 step fits the column at exactly 648, the translation at the same step is 827 and overflows the right column by 179px. Both must share one step (or the row heights disagree and the two sides do not line up), so both are measured and the max taken. The reads still all sit in the same phase and trigger one layout; the cache key (column width + translation node) is unchanged
- **Graphics inside an inline shrink-wrap are exempt from `max-width`** [decided, 2026-09-04]: `.ltx_inline-block`'s width is set by its content, while the content's (the image's) `max-width: 100%` refers back to it — the cycle resolves to a pathological narrow value: measured on 2312.17141, a chord diagram with viewBox 68.3×97.88 was squeezed to **10.5×97.9**, an illegible speck on the page. With `max-width: none` written back for `img` / `svg` inside `.ltx_inline-block`, all 6 `.ltx_picture` on the page match the original layout one by one
- **Figures are split in two whole** [decided, 2026-09-05]: the graphics and formulas inside a figure have no translation, so paired by block the right column stays empty; a figure spanning both columns gives up the comparison. Therefore a `figure` holding a pair **and** holding media (`img/svg/math/canvas/video/.ltx_picture`) is cloned whole: the clone deletes the source member of every pair and keeps only the translations, and the original hides the translations inside it in side mode (`[data-axt-split] .axt-t { display: none }`). The two copies are structurally identical and their rows align by nature (measured on the 8 figures of 2312.17141: left column 224→708, right 732→1216, top offsets all 0, leftover source blocks in the copy 0, visible translations in the original 0). The test uses the HTML tag `figure`, not a class name (avoiding “class names are an open set”); table floats do not take this road — their table has a translation clone already, so the requirement “holds **loose** media” keeps them out — loose meaning inside no translation block and no translation: an inline formula in the caption is `math` too, and “has media” alone would misjudge a table float as a figure (measured: both table floats of 2312.17527 were split, Codex on #26). Whether the copy is rebuilt is decided by a signature of the translation content; counting alone would keep a stale copy for good when retranslating into another target. Both copies enter `SIDE_DENY_SUBTREE`, their insides left entirely to ar5iv, and `alignPairMargins` skips them too (inside the clone a translation's previous sibling is no source)
- **Split figures are not scaled** [decided, 2026-09-05, the owner's call]: when the column narrows, ar5iv reflows on its own — `.ltx_flex_figure` is `flex-flow: wrap` already, and the panels stack vertically by themselves (measured: full column 342px high → half column 546px, no overflow; another 311 → 772). What does not fit and cannot reflow (a wide formula, a wide SVG; measured 3 of 8 overflowing by 78 / 102 / 209px) degrades to **horizontal scrolling inside the column** (`overflow: auto hidden`), the font size never touched. Two roads given up: (1) feeding the column width into ar5iv's `--main-width` (it computes panel widths as `.33/.5 × --main-width`) — measured worse, the panels shrinking to 160px and still overflowing by 555px; (2) scaling by steps like tables — the owner explicitly asked not to break the original type-size ratio
- **Mirrors are decided structurally too** [decided]: every direct child of a container that is neither paired nor holds a translation gets a mirror, instead of enumerating `.ltx_equation` / `.ltx_graphics`. Otherwise bibliography numbers and author paragraphs, author names and list numbering — content equally without a translation — leave the right column empty and the left column's content spanning both (measured on 2609.00097). A mirror has three gates, and missing any one duplicates the whole page: the translation root itself has to “hold a translation inside” to count as a container (or a call **before** translation starts copies the abstract and sections whole into the right column — a measured accident); a block carrying `data-axt-id` and an element **still holding blocks inside** are not mirrored (once the translation arrives there would be a copy and a translation); and mirrors are recomputed, debounced, as translation progresses, not once on entering the mode
- **Containers are decided by structure, not enumerated by class name** [decided, redone 2026-09-04]: the containers taking part in pairing = `:has(.axt-t, [data-axt-id])` (holding a translation or a block mark; the same selector as the mirror's container check) minus a handful of explicit exclusions (translations themselves, the inside of tables, ar5iv's own two-column grids `.ltx_enumerate` / `.ltx_description`, inline and preformatted contexts, the pair members themselves). Early versions enumerated container class names in CSS, but that is an **open set**: `.ltx_theorem` (variant names generated by author macros), the `\resizebox` wrapper `.ltx_transformed_inner`, `.ltx_proof`, `.ltx_author_notes` were each added only after a reader found them on the page, one fixed and one missed — the same lesson as “class names cannot be enumerated” in §2.12. Measured after the switch to structure: 2609.00097 right-column elements 250→254, unpaired 5→1; 2609.00095 108→111, with no new overflow. `tests/renderer/side-layout.test.ts` records in a snapshot, for every fixture, the share of “pairs that reach the translation root” and how many each exclusion blocks; adding to the exclusion list changes the snapshot, which turns this kind of hole into a build-time failure
- **Only the translation of an inline short heading clears its left margin**: zeroing it on every translation would remove the auto margins of `.ltx_centering`, and mirrored images would hug the column start instead of being centred like the original
- **Unpaired content inside a bibliography entry stays in the left column**: the number and the author paragraph, spanning by default, would straddle the divider and read like broken formatting
- **The column width is the translation root's first grid track**: every container is its subgrid, so the column width is the same everywhere, more reliable than halving the parent's width (a table's parent is not necessarily a container we set)
- **Table scaling has to be recomputed as translations keep arriving**: `fitTables` acts only on tables with a translation sibling, and translations are inserted block by block as translation proceeds. A debounced recomputation is scheduled in the progress callback, or on the path “switch to side first, then translate” tables would never be scaled (a hole in the early implementation)
- **Display formulas are scaled into one column by steps like tables** [decided, 2026-09-05]: a display formula cannot wrap, and once the column narrows it runs into the neighbour — measured on 2609.04056v1 in a 436px column, (1.8) is 800px wide and (1.15) 900px, the left column's formula covering the right column and the equation number landing on the start of the mirror (the owner's feedback “formulas out of bounds”). `fitTables`' targets grew from `.ltx_tabular` to `table.ltx_eqn_table` (both single equations and align groups; the `tr.ltx_equation` inside a group is not counted on its own; the selector is `FIT_TARGETS` in `rules/latexml.ts`): min-content is measured against the column width, dropped to discrete steps from 0.95 to 0.7, and what still does not fit degrades to horizontal scrolling inside the column (ar5iv itself does `display: block; overflow-x: auto` inside `.ltx_td` / `.ltx_inline-block`). **This is no new problem**: in the old version (before the width change) the same paper at 1440px had 53/145 formulas over the column, 6 of them not fitting even at 0.7; the old version merely happened to fit the widest one (734px) at ≥ 2000px with 740px per column, and nobody saw it. The finalised width contract restores 740px per column on wide windows, so at ≥ 2000px 0 formulas need scaling; at 1440px there are still 57 (48 scaled, 9 scrolling), where the old version pressed all 53 straight into the neighbouring column — not fitting in a narrow window is an inherent constraint, and the difference is only whether it is caught now. This does not contradict “split figures are not scaled”: a figure is pixels or vectors and scaling distorts the type-size ratio; a formula is text, still clear at 5–30% smaller, and unscaled it can only scroll — and reading a formula needs it in one view more than reading a figure does
- **The acknowledgement / corresponding-author notes of the frontmatter: with a translation they always stay in the article column, laid out in two columns** [decided, 2026-09-06, the owner's feedback + measurement]. Each of the two width bands breaks in its own way, for different reasons pointing at one conclusion:

  - **1280–1535px** (side in effect, the gutter rules not yet): ar5iv leaves it in the body flow and hard-codes `.ltx_note_outer` at 800px. The original page's article happens to be 800px too, so nothing shows; in side mode the article column at 1280px is only 652px, and this note **overflows the article's right edge by 156px**, its translation can only stack right under the original, while the names and affiliations beside it are paired side by side — it looks as if the translation fell into the left column.
  - **≥1536px** (the gutter band): ar5iv positions these notes absolutely in the gutter at a fixed rhythm of 160px per author, **the height computed for the original alone**. With the translation put in, each grows from 26–50px to 148–194px, and the first presses onto the second — measured at 1800px: the original page's 5 notes overlap 0 pairs, with the extension the same 5 overlap **1 pair**; and the gutter is only 192px wide, so the line breaks are ugly too (`giangnh@huce.edu.vn` broken in the middle).

  So the ones with a translation always go back to the article column in two columns (measured at 1800px: original 248–880, translation 904–1536, the centre line 900, 0 pairs overlapping), and **those without a translation keep the gutter as it is** — while the translation has not arrived or has failed, arXiv's own layout is left alone. In the implementation mind the specificity: the gutter's `width` rule and the override have the same specificity and the gutter rule comes later in the file, so source order wins (measured: the note box squeezed to 192px, original and translation 76px each), so the change is `:not(:has(.axt-t))` added to the gutter rule, not an override written after it. Frontmatter notes are always visible and have no collapsed state, so the concern of “the whole `.ltx_note` subtree excluded from pairing” does not apply — that rule is for body footnotes.

  Side effect: the assertion “right-gutter elements land within [the article's right edge, the viewport]” on 2609.04056v1 lost its subject (those 4 elements are all acknowledgement notes) and was removed; the gutter geometry is covered by the body-footnote assertion on 2312.17141 instead, where there are real gutter elements and coordinates.
- **A grid disables margin collapsing, so the spacing that relied on collapsing has to be put back** [decided, 2026-09-06, the owner's feedback]: `.ltx_document` is a grid container in side mode (the two column lines are **defined once, on it alone**, the other containers inheriting by subgrid — otherwise each container halves its own width and the dividers drift apart), and **a grid container disables margin collapsing between its children**. Every spacing the original page gets from adjacent margins collapsing becomes a sum in side mode:

  - arXiv puts two `.ltx_pagination` of **height 0** (the product of `\newpage`) between the abstract and the body, each with a 32px top margin. In block layout they collapse with the abstract's 32px bottom margin into one; in the grid the three add up. Measured on 2609.03001v1: from the bottom of the abstract block to the top of the first section, untranslated 32px, **side 96px**. These two markers show nothing on screen, and their margins exist only through collapsing, so they are zeroed in side mode.
  - Likewise, the bottom margin of a container's **last row** merges into the container's own bottom margin in block layout, and in the grid shows as real blank space (the abstract block grew 24px taller). The pairing rule zeroes the bottom margin of “the last child” and of “the original before the translation when the translation is the last” — the last row is two cells, and clearing one alone does nothing (the row height takes the larger).

  Measured after the fix: the spacing 96 → **32**, identical to untranslated; the bottom of the abstract block and the bottom of the taller cell of the last row differ by 0px. `pnpm e2e:layout` guards it, mutation-verified (removing the pagination rule brings the spacing straight back to 96).

- **Column fitting measures read-only, with no cloning and no DOM writes** [decided, 2026-09-05]: earlier `fitTables` cloned every table, inserted it into body at `width: min-content` to measure and deleted it again. That is a “write once, read once” loop forcing a full-page layout per table; invisible with a few `.ltx_tabular` as targets, but extended to display formulas 2312.17141 has 392, and measured, one side prep pass was **a 45-second long task**, Chrome showed “page unresponsive”, and 134 seconds translated only 6 blocks (the owner's feedback). Now it reads the existing layout only: a table cannot be pressed below min-content, so **when overflowing, box width ÷ the current zoom is the exact natural width**; in the scrolling-inside-the-column state `scrollWidth` is the content width; only the one state “a formula table fits with room to spare” cannot be measured (it is `width: 100%`) and is estimated from the sum of each row's non-padding cells (a padding cell counted at ar5iv's `min-width: 2em`), the estimate 1–2% below the truth (measured over 145 tables, the largest difference 28px). The estimate **is never used to tighten**, and loosening re-judges with a 5% margin added to the width, or it flips back and forth between “loosen → overflow → tighten”. On the same page the read-only measurement takes 1ms, the cloning method 15,483ms; after the fix 2312.17141's longest task is 252ms, 569ms in all, 34 blocks in 18 seconds, level with the baseline before the change (175 / 625 / 35). `pnpm e2e:layout` guards the long-task budget on this paper (longest ≤ 400ms, total ≤ 1.5s)

  **Reads and writes batched, and what was measured is not measured again** [revised, 2026-09-07, issue #46]: the “1 ms” above is the number with a few tables as targets. Extended to 392, the old loop was still “read geometry → write `data-axt-fit` → read the next” table by table, re-measuring every table on every pass; side prep runs 30-odd passes per session, and on 2312.17141 `fitTables` added up to **991 ms**. Now a pass has three phases: collect first (no layout touched), then read every table not in the cache at once, and finally **write only the attributes that changed**; a measured table is cached by “column width + translation node” — every render path (`renderTable` / `renderPending` / retry) swaps that sibling node, and mirrors are built once per session, so **the node's identity is the content version** and no hashing is needed. `resetFitCache()` stays as the hook for reopening a session and for a future font-size change.

  **The measurement turned the attribution around**: the cache hit fully (29 passes, hits 5180 / misses 188), yet the total fell only to 882 ms, of which **`measureColumn` alone is 840 ms** — it reads the resolved value of `gridTemplateColumns`, which forces layout, and it is the first geometry read after the three DOM-writing steps of prep, so the whole page's forced layout is charged to it (130–158 ms on passes with upstream writes, 0.0 on passes without). The `marginTop` that `alignPairMargins` reads needs only a style recalculation, so it is cheap. In other words those 991 ms **were never the cost of measuring widths** but the structural cost of prep writing before reading on every pass; the width measurement itself occurred only 188 times in 388 calls. The column width should be read once by prep before writing, cached across passes and injected through `FitDeps.columnWidth` — that is the business of the next step, incremental prep.

- **Tidying is incremental by changed area, and the mirror runs once per session** [decided, 2026-09-07, issue #46]: before, every batch of arriving translations ran the five tidying steps (footnote placement, figure split, mirror, table fit, margin alignment) over the whole document. Measured on 2312.17141 (880 blocks, 392 formula tables, 730 subgrid containers): one session **31 passes, 1912 ms in all**, while a single pass takes only 34 ms — the cost is all repetition. Three probe conclusions: (1) `createMirrors` is pure waste after the first pass — the block marks are written when the session starts (§7.3), every gate of `needsMirror` looks only at them and at `.axt-t` siblings, and an arriving translation **changes no mirror decision**, yet every pass still scanned 50 thousand nodes with a bare `:has()` and re-ran the same `:has()` over the 730 containers already matched (840 ms in all); (2) the 991 ms of `fitTables` are not width measurement (see the previous item); (3) all five tidying functions narrow their root in the signature, and the caller always passed `document`.

  Now the pipeline hands over the blocks whose DOM just changed with every batch (`RunOptions.onRendered`, in step with `onProgress` but not stuffed into the serialisable `Progress`), the coalescer collects them into a dirty set (`createCoalescer<T>`, a bare `schedule()` meaning full), and `renderer/prep.ts` computes each dirty block's root — its parent ∪ the parents of the enclosing blocks (an inner footnote arrives before its outer block) ∪ the parent of the outermost `figure` it sits in (`splitFigures` scans descendants only) — and tidies only those roots, in the phase order. **The invalidation table**: `localizeNotes` / `splitFigures` / `alignPairMargins` by the dirty blocks' roots; `fitTables` the same, full when the column width changes (the cache is keyed by column width); `createMirrors` **once per session** (the first full pass, and only after the block marks are written, or whole blocks are cloned — issue #67); re-entering side is full (the aligned margins are cleared on leaving). The cross-area dependencies were checked one by one: the adjacent-sibling margin rule (`p + p`) does not cross parents, so taking the parent covers both its own pair and the next; when the inner footnote arrives first the outer has no translation and `localizeNotes` skips it, and when the outer arrives its root holds the outer's parent and the copy can be filled in; when a figure with a mirror inside is then split, `splitFigures` deletes the mirror itself first, and afterwards the whole subtree is in the deny list.

  **The first measurement exposed three things, all fixed in the same PR**: (a) `alignPairMargins` 38 → 818 ms — the cost did not vanish, it **moved one layer**: once `fitTables` no longer read geometry, the style recalculation after the DOM writes landed on its `getComputedStyle` (`:has()` invalidated, 90 ms per pass). Split into `readPairMargins` / `writePairMargins`, **the read at the start of the pass, before anything is written** (the previous frame has just rendered and the style is clean), read once more after the mirror pass has inserted its mirrors, the writes at the end of the pass — after the fix the margins total **0.0 ms**. The column width likewise is read at the start of the pass and only when stale (entering side, a window width change, fonts finishing loading). (b) `measureColumn` was handed `<html>`, `closest(DOCUMENT_ROOT)` found nothing, the fallback's `parentElement` was null → column width 0, not one table scaled (caught by e2e: 0 scaled and 3 over the column at 1440px; the unit test injected a fake column width and did not catch it, so an assertion that the translation root is passed was added). (c) **The effect-count drift was a baseline bug shown up by the comparison**: `REAL_TRANSLATION` in `split-figures.ts` did not exclude `.axt-mirror` / `.axt-split` (while §7.5 says it draws “the same line” as the preset selector). A figure whose caption is still pending has its media mirrored first; the baseline ran full every pass, and the next pass took the mirror for “has a translation” and **split it by mistake** — deleting the mirror and cloning a figure without any translation. Of the 7 split figures of the baseline's 2312.17141, F4, F5, F7 and F8 were of this kind (their captions never requested); the incremental version runs full once, and the mirrors are built after the split of that same pass, so it was not hit until the next full pass on re-entering side split them by mistake (the source of the mirrors 358 → 353 in e2e). The selector gained the two exclusions, and a test guards “no split when the only `.axt-t` in the figure is a mirror”.

  What remains is almost entirely that one full mirror pass (168 ms on 2312.17141). **The make-up of those 168 ms** (measured with probes inside the function, 2026-09-07): `createMirrors` itself is only 30 ms (`querySelectorAll` scan 13, `.filter(isMirrorContainer)` 3.8, the clone loop 13.6); the other ≈138 ms is the initial style computation **the first reader of style** pays the browser for after 359 clones were inserted — the MathML subtrees of formulas are large, and that bill is paid once whoever reads and whenever; it is the fixed cost of “a mirror = a clone”. The planned PR C (a denied set + parent-pointer walk instead of the `:has()` re-run inside `.filter`) measured 3.8 → 1.9 ms with the kept container sets of both papers identical, **not done**: 2 ms is not worth a PR. The first full pass is heavier than any pass before (every step done at once), so 2609.03768 went from 0 long tasks to 2 of 58 ms — 633 → 66 ms in total, but worth knowing. `pnpm e2e:layout` guards three things: convergence after settling (all pair margins equal, every figure due for a split split — a hole in the invalidation table shows here, **not papered over with “run one full pass as a fallback”**), the mirror count unchanged and still aligned after side → stack → side, and prep total < 600 ms.

  **No pairing registry is built**: `data-axt-id` / `data-axt-for` are the only channel, and CSS recognises them alone; a second `Map<Block, Element>` would be a second source of truth that `clearTranslation` / `restore` both have to keep in sync. The sibling checks differ in meaning from place to place anyway (table-fit wants `[data-axt-for]`, split-figures a real translation, notes any `.axt-t`), and unifying them into one accessor with switches is exactly the “big tool driven by arbitrary parameters” #46 forbids.
- **The two columns must be `minmax(0, 1fr)`** [decided]: `1fr` equals `minmax(auto, 1fr)`, and that `auto` floor is the track content's min-content width. The English column's floor is its longest word (wide tables and long formulas likewise), the Chinese can wrap at every character and its floor is near 0, so when room runs out the English column holds its floor and the Chinese column is squeezed one-sidedly (measured at an article column of 600px: 317 / 227). With the floor zeroed the two columns are always equal (272 / 272), at the cost of over-wide content overflowing its own column rather than taking the neighbour's width — consistent with the wide-table trade-off already recorded in §7.2
- **The container list must use `:where()`, not `:is()`** [decided]: `:is()` takes the specificity of its most specific entry, and with `.ltx_itemize > .ltx_item` (two classes) in the list the container rule rises to (0,4,1), over the (0,3,1) pairing rule; so **blocks hanging directly under `.ltx_document`** (acknowledgements, the abstract) are pinned full-width and the translation drops below the left column (measured on 2609.00095). Blocks nested in containers go through another, more specific selector and are fine, so the bug shows only on the document's direct children. `:where()` has specificity 0, so the pairing rule can override
- **The column lines must be inherited, never computed per container** [decided]: early versions wrote `1fr 1fr` on every container, so each halved **its own width** — indented paragraphs inside lists, bibliography entries with `.ltx_biblist`'s own 3em gap, all had dividers out of line with the body (measured: 720 / 715 / 736 on one page, the divider band visibly crooked). After the switch to subgrid all 105 right-column elements measured on the same x, the precondition for drawing a divider in the gutter later. A subgrid container has to write `column-gap` explicitly, or it uses its own gap (`.ltx_biblist` would be off by 12px)
- `.ltx_enumerate` / `.ltx_description` **do not join** the subgrid chain: ar5iv uses their own two-column grids for numbers and terms, and subgrid would wreck the numbering; the pairs inside them degrade to stacking
- In an environment without subgrid the whole `grid-template-columns: subgrid` declaration is dropped, the container degrades to a single-column grid, pairs stack, and nothing is garbled
- **Mirror nodes** [decided, rewritten 2026-09-05]: formulas, bare figures, list markers, bibliography numbers — content with no translation — would leave the right column empty and span both columns, breaking the reading, so each gets a copy inserted as an `.axt-t.axt-mirror` sibling. Decided structurally (see “mirrors are decided structurally too” above), no longer by enumerating selectors; captioned figures are not mirrored but split in two whole (see “figures are split in two whole”). Built as soon as a block is marked (see §10), then left in the DOM with their visibility controlled by `html:not([data-axt-mode="side"]) .axt-mirror { display: none }`, so a mode switch still changes a single attribute on `<html>`. This is one relaxation of §7.1 item 2: side mode has a one-time DOM write, deleted together with `.axt-t` on restore
- A translation in side mode **does not compress its top margin**: it shares a row with the original, and unequal margins put the two sides out of line (measured: `h2` off by 19px, `figure` by 64px). Only stack / only apply `margin: 0.25em 0 0`
- **The top margins of the two columns on a row have to be copied level** [decided, 2026-09-04]: a translation inserted as the next sibling changes what the **adjacent-sibling selectors** in the site's CSS match. ar5iv has rules of the form `.ltx_role_affiliation + .ltx_role_affiliation { margin-top: 8px }`, and the translation copies the original's classes, so the original's previous sibling is the previous **translation** (different role → 0px) and the translation's previous sibling is its own **original** (same role → 8px); a grid cell's top = the row top + its own `margin-top`, and the two columns differ by 8px (measured on the author area of 2501.00077v1. Control experiments: removing the class from itself, from the previous sibling, or inserting a node between them, all bring the 8px to zero). CSS has no way of “taking a sibling's computed value”, so `alignPairMargins` (`src/core/renderer/pair-margins.ts`) copies the original's computed top margin onto the translation's inline style during side prep — writing our own nodes only, never the original (§7.1). Every round **wipes the previous round's value before measuring**, or it measures what it wrote itself and cannot correct when the column width or the site styles change; on leaving side mode it clears, giving the margins back to the site styles. Measured on that page: of 167 pairs only 2 needed rewriting, 1.2ms per round, and repeated calls change nothing once settled
- The document's main title and its translation span both columns centred and take no part in the pairing (like a paper's running head); `.ltx_title` has `max-inline-size: 52rem`, and once the article column widens it needs `margin-inline: auto` to be centred; `span.ltx_p` and the `.ltx_p` inside tables and inline-blocks degrade to stack (ar5iv's styles already set `.ltx_para` to `display:block`, no conflict)
- Unpaired children of `.ltx_para` (display formulas, figures and so on) get `grid-column: 1 / -1` to span
- Headings and captions: degrade to stacking (their parent is the whole section, which cannot be a grid)
- Tables: the whole-table clone goes below (see 5.3)
- **Width contract** [decided, finalised 2026-09-05; the three versions before it withdrawn]: arXiv's body is a five-column grid `1fr nav article aside 1fr` (the theme's `--nav-width: minmax(14rem, 25rem)`, the article 52rem centred; the 4th column has no named area and only leaves room for the margin notes / acknowledgements / publication notes ar5iv hangs at the article's right). Side mode sets all three columns together, in the order **body first**: the two sides are taken first by “what is left after the body takes its full 96rem” (`--axt-side-w: clamp(14rem, (100vw - 96rem) / 2, 25rem)`, both bounds being the native range of arXiv's theme `--nav-width`), the body takes the rest, capped at 96rem (`--axt-article-w: min(96rem, 100vw - 2 × side)`, arXiv's own cap), the sides are symmetric so the article is always centred, and what is left beyond the cap falls into the `1fr` page margins on both sides (`--axt-margin-w`). All three tokens are closed-form functions of `100vw`; rules depending on column widths reference them directly and no JS measures tracks; ar5iv's `--main-width` / `--main-width-margin` follow the article column. Measured (Playwright, the 145 display formulas of 2609.04056v1):

  **The navigation takes from the freed page margins first, never from the body**: the old version hard-coded both sides as `minmax(8rem, 12rem)`, the navigation forever 176px (table-of-contents entries wrapping up to 4 lines), while at 2560px each side had 512px of pure blank not given to the navigation — exactly the owner's feedback. Now at ≥ 1536px (the body capped) the body is **pixel for pixel the same** as the old version and the navigation takes 216–384 from the page margins (wrapping down to 3 lines); at 1440 / 1600px the cap is not reached, the body gives up 32px (1024 → 992, 1184 → 1152, about 3%) for the navigation to grow from 176 to 208 — the one trade-off in that band. **The three versions that went wrong**: (1) the old version, the navigation too narrow; (2) navigation 14–25rem by viewport, the right side reserved only at ≥ 96rem — in a 1333px window navigation 267, right 16, the whole paper pushed right (rejected by the owner); (3) body `clamp(58rem, 62vw, 84rem)` + the remaining space split between the sides — centred and symmetric, but at 2000px the body 1536 → 1240, per column 740 → 592, 25 of 145 formulas not fitting (the owner's feedback “formulas out of bounds”). Allocating by viewport ratio means **letting the sides share the body's width**, the wrong way round: the sides should take only what the body cannot use. **The right gutter's geometry has to follow the tokens**: ar5iv's four sets of rules (`.ltx_note_outer` hard-coded at 20 / 27rem in two bands at 96 / 109rem and pushed out of the article by a negative `margin-inline-end`, the `min(27rem, (100vw - main) / 2 - 2rem)` of `.ltx_pubnotes_content` and `.ltx_role_thanks`, the author area's last unit block at `inset = (100dvw - main) / 2`) are all made for a 52rem article and overflow the viewport copied as they are. Those rules are rewritten inside `@media (width >= 96rem)` by `--axt-side-w` / `--axt-margin-w`: the boxes always occupy `[article right edge + 1rem, article right edge + side - 1rem]`, with the show / hide and hover / focus interactions left as they are; below 96rem ar5iv shows no margin notes anyway (collapsed into hover pop-ups) and the gutter is only symmetric blank. Inside a paragraph not yet translated the original footnote floats from the **left column** and has to be pushed one more column plus one gap (column width = (article column − the theme's 1rem left and right margins on `.ltx_page_content` − gap) / 2; `--axt-gap` therefore switched to rem, since em would be reinterpreted inside the footnote's .85rem font size); once the translation arrives the copy floats from the right column and the original is hidden, and both states measured land in the gutter alike. Overriding `--main-width` alone without touching the tracks overflows sideways (hiding the navigation bar does not collapse its track; measured: a 1500px viewport overflows by 388px), and zeroing the track makes the TOC vanish; neither is acceptable
- Watched with `matchMedia('(max-width: 1279px)')` (aligned with the 1280px breakpoint at which arXiv's theme collapses the navigation bar): narrowing switches to stack of itself, widening back to side; a mode the user chose by hand is recorded as the preference, and the automatic fallback does not overwrite it. Implemented in `createModeController` of `src/core/renderer/responsive.ts`; the popup shows the preference, and the status carries the mode in effect too

- **Layout `ltx_*` belong to the rule module too** [decided, 2026-09-06, Codex on #22]: `renderer/side-layout.ts` had accumulated 5 `ltx_*` literals (multi-panel flex figures, inline contexts, pair members, footnotes, stacked areas), breaking CLAUDE.md hard rule 2. The rule table answers “which content is translated”; these answer “what structure this content has” — LaTeXML knowledge all the same, so they belong to the `SIDE_LAYOUT` export of `latexml.ts`, and the renderer only composes. The constant names (`MULTI_PANEL_FLEX` / `SIDE_DENY` / `SIDE_STACK` …) are unchanged, and not one caller changed.

  More important, this rule used to live **in the document only**, which is why they quietly accumulated. `tests/rules/selector-boundary.test.ts` now scans every TS / TSX under `src/` except the rule module (with the comments stripped first) and reports the file name and the offending selector on a violation. `src/styles/*.css` remains the one exception the hard rule allows.

### 7.3 stack (stacked)

The translation right after the original block. No extra CSS is needed, only the translation style. Corrected 2026-09-13: stack was the default layout until 2026-09-11; the default is `side` now (`DEFAULT_CONFIG.mode`, UI.md S-P-70), and stack is the automatic fallback under 1280px (§7.2) besides a choice of its own.

- **Short headings share the line** [decided]: a heading in the `title` unit other than the document's main title, with visible text ≤ 60 characters, gets `data-axt-inline` on both the original heading and the translation when rendered, and CSS makes both `display: inline-block` (inline-block keeps the heading's own vertical margins), the translation with a 0.5em left margin, so that “Abstract 摘要” share a line. The reference projects achieve the same by stuffing the translation into the original element; we do not change the subtree, hence attribute + CSS. The main title stays stacked: it is centred by `text-align: center` and cannot be centred once inline.

  **This rule is not limited by mode, because under side it has no effect anyway** [measured, 2026-09-07, issue #68 / raised by Codex on #13]: side's pairing container is `display: grid`, the heading is its direct child, **grid items are always blockified**, and `inline-block` never lands. Of the 69 inline short headings on 2609.00246, under stack all are `inline-block` with original and translation on one line ("Abstract" 0–90 followed by "摘要" 90–157); switched to side, **0** keep `inline-block`, all are `block`, the original filling the left column 0–648 and the translation the right 672–1320, on one row. Limiting the rule with `html[data-axt-mode="stack"]` changes no rendering result and only adds a mode check to maintain, so it is not added. `modes.css` has a separate rule **aimed at `[data-axt-inline]` translations under side** (clearing that 0.5em start margin), showing the current behaviour is intended. `e2e:layout` has an assertion guarding it (display block, original in the left column, translation in the right, same row)

- **Block marks are written in one go, not sliced** [decided, 2026-09-06, issue #67]: both gates of `side prep`'s mirror check (`needsMirror`) look at `data-axt-id`, which cannot tell “a translation unit not yet marked” from “static content that will never have a translation”. Were the marks written in slices, the first prep pass running into the half-done state would clone a whole `.ltx_para` / `.ltx_proof` / `.ltx_theorem` **whole** into the right column, and once the blocks inside were translated the right column would carry a whole extra English passage. Reproduced in happy-dom with three preps at 25% / 50% / 75%: 2312.17141 36 places, 2609.04056 23, 2609.00245 87; with prep pushed past the marking, all 0.

  **But that path is unreachable in a real browser** (measured on 2312.17141, Chromium): slicing marks 828 blocks in **2 ms**, and the first prep pass runs only after **1140 ms** (150 ms debounce + the rhythm of progress callbacks), a window 570 times wider. So this turns an **implicit timing assumption** into a structural guarantee rather than fixing a bug in progress — unwritten, nobody knows safety rests on “marking is two orders of magnitude faster than the debounce”.

  Slicing was meant to prevent “several hundred attribute writes freezing the page” (Read Frog's #1881), a bill that does not hold: the loop is attribute writes only, reading no layout; measured in Chromium, 979 blocks are written in **1.2 ms**, followed by 0 ms of forced layout. Writing synchronously also removes the `halted()` race window — with no `await` in between, restore cannot slip in. The state attribute (`data-axt-state`, with the pending skeleton style) is still sliced; it does not affect prep's decisions.

- **The visibility threshold has to really apply, and must not lock oversized blocks out** [decided, 2026-09-06, Codex on #32 / #36]: `IntersectionObserver`'s `isIntersecting` is defined as “intersection ratio **> 0**”, not “≥ threshold”; the browser sends an initial notification right after observe, and a block just one tenth exposed reports `isIntersecting` under `threshold=0.5` all the same, so the setting was as good as absent. The callback therefore has to compare `intersectionRatio` itself.

  The other end is the reverse: **a block taller than the root (viewport + vertical margins) can never reach a high threshold**, its ratio capped at `root height ÷ element height`; and the design explicitly does not split oversized tables (§7.2), so at `threshold=1` that table would never be translated. The effective threshold is clamped to this cap — as much is demanded as can be reached. The observer's `threshold` is handed **a grid in 5% steps** (`observerThresholds`, with the user's configured value added, since it may be off the grid): it only decides “at which ratios to call back”, and the decision is made in the callback; passing `[0, threshold]` is not enough, see the next item.

- **A translation identical to its source is not shown twice** [decided, 2026-09-06, Codex on #74]: the default prompt's line “Keep author names, journal names, conference names … in the original language” makes a citation author paragraph of bare names **come back as it is**, and `renderText` inserts the sibling unconditionally — in stack mode every author line appeared twice. Not limited to names: any block whose translation equals its source behaves the same. `renderText` compares after normalising whitespace, marks equal ones `data-axt-identity`, and **stack mode's CSS hides that copy**; side relies on it to hold the right column and only hides the original block, so both keep it.

- **The visibility threshold: the registered ratio points must cover the clamped threshold** [revised, 2026-09-06, Codex on #76]: the previous version registered only `[0, threshold]`, and the observer **calls back only when a registered value is crossed** — an oversized block whose ratio cap is below the threshold gets no notification after crossing 0, the decision clamped to the cap never sees the one call that could pass, and the block **is never translated**. Measured in Chromium (element 3000 px, root 900 px, cap 0.3, threshold 1): registering `[0, 1]` called back once in all, ratio 0.267; with the fine 5% grid, ratio 0.3 arrived.

  **The decision has to use the same scale too** (Codex on #81, a remnant of the same bug): the callback carries **the real ratio at that moment**, so an element whose reachable cap falls **between** two grid points never gets the call where “ratio equals the cap”. Measured (a 2700 px element / 900 px root, cap 0.3333, grid 0.30 / 0.35, slow scrolling in 10 px steps): the call crossing 0.30 reports 0.30000001 and there is no call after it; comparing against the exact 0.3333 never passes. So when the configured value is out of reach, the lowered threshold is **aligned down to the registered grid**, and the comparison leaves a 1e-6 floating-point tolerance. A fake observer calling the callback directly cannot reproduce this browser semantics; both cases are guarded in `pnpm e2e:layout`.

### 7.4 only (translation only)

- The original block is `display: none` (not deleted, no text node replaced); the selector is `[data-axt-state="translated"]`, so only blocks that really have a translation are hidden
- Bibliography entries **are no longer exempt** (revised 2026-09-04): once entries are translated by `.ltx_bibblock` fragments (§5.4), the translation follows the matching line and the entry stays fully readable line by line in translation-only mode. The old exemption was a leftover of the whole-entry era
- In only mode citation author names are the translated names only (2026-09-06): once author paragraphs are translated (§5.4) they carry `data-axt-state` too, and the English original is hidden. A name transliterated by a free engine is worthless for **citation lookup** — that is only mode's inherent trade-off for all content; for lookup use side / stack, where the original is always beside
- Blocks not successfully translated keep the original visible: the hiding rule matches `data-axt-state="translated"` only, so `pending` / `failed` simply do not match, and the retry widget beside a failed block (§7.6) stays visible with it. **Do not** write `display: revert` — revert would undo the site's display too (`.ltx_bibblock` from block back to inline), removed 2026-09-05 (Codex on #19)

- **In-page anchors pointing at a hidden block land on the translation** [decided, 2026-09-06, issue #44]: only mode sets the translated original blocks `display: none`, so the cross-reference targets inside those blocks have no layout box and the browser does not know where to scroll. Measured on 2609.00246 (Chromium, only, the whole paper translated): the targets of **128** in-page anchors were invisible, and clicking the “§7” among them (`#S7.p3.1`, the target a `p.ltx_p` with `data-axt-state="translated"`) left `scrollY` **at 0, not a pixel moved**. Of the 3374 in-page anchors in 12 fixtures, **118 (3.5%)** target translation blocks, almost all `.ltx_p`.

  The approach is **to land the navigation on the translation**, not to let the original out: a reader in only mode clicking “see §7” wants §7's Chinese; and §7.4 explicitly forbids undoing the hiding with `display: revert`. `renderer/anchors.ts` attaches three listeners when the session starts (click capture / hashchange / popstate); when the target is invisible it finds the translation node of the block it sits in and scrolls there, changing the hash through `location.hash` (the address bar and the back button work as usual, and **the native `hashchange` is still dispatched** — `pushState` does not, and page scripts or other extensions would not observe the navigation; re-entry is blocked by “remembering the hash we wrote”, not by a synchronous boolean, since the event is dispatched asynchronously). **Only a real translation counts as the stand-in** — a mirror is the right column's balancing copy, pending is the ring, error is the failure widget; scrolling to them is scrolling to an empty box. When the target is visible it never steps in once, so side / stack are wholly unaffected; restoring the original removes the listeners without a trace (§7.1).

  Measured after the fix: the same link scrolls **31 464 px**, the translation landing at the top of the viewport (`top: 0`), `location.hash` synchronised to `#S7.p3.1`. `pnpm e2e` has an assertion guarding it, mutation-verified (without the fallback it goes back to scrolling 0 px).

  **Links on the fallback path (runs)** are another matter, done in an earlier change: an `<a>` with `href` is kept whole as a void on the runs path (`FUNCTIONAL_INLINE`), at the cost of the link text going untranslated — the fallback is lossy by nature, staying clickable matters more than a few more words translated, and of the 4221 translation blocks in 12 fixtures 0 hold such a link (the links in arXiv body text are all `.ltx_ref` or `mailto`, protected nodes at the rule layer already).

- **Hover to see the original** (2026-09-10, issue #141): resting on a translated sentence for 600 ms floats that sentence's original (in the margin when it fits, else beside the sentence), see §7.7 “the original peek in translation-only mode”

### 7.4b Accessibility: the part that is ours [decided, 2026-09-06]

A peer ran an accessibility audit on the rendered page with DevTools and reported four items: skipped heading levels (`h6.ltx_title`), a missing `<main>` landmark, `<object>` without `aria-label`, tables all `<td>` with no `<th>`. **None of the four is caused by us** — the same paper (2410.00260) opened without the extension already has 1 `h6`, 1 `h5`, 0 `main` but 1 `div.ltx_page_main`, 8 of 12 tables without `th`, all products of LaTeXML / ar5iv.

**Nor should we change them**: changing heading levels, adding `role="main"`, labelling the `<object>`, turning headers into `<th>` — each rewrites the original document's subtree, a direct breach of the DOM invariant of §7.1 (original nodes may only gain `data-axt-*`, and after restore the DOM must be equal node by node). This is someone else's page; we are a reading aid, not a page repair tool. To really push this it should go upstream to arXiv / LaTeXML. The only side effect is that bilingual rendering shows each of these elements twice (`h6` from 1 to 2), the inherent cost of side-by-side reading.

**What is ours, and what that audit did not check, are the translation nodes' own attributes**:

- **A translation must carry `lang`**: the page's `<html lang>` speaks of the original (`en` on arXiv), and we insert Chinese into it. Unmarked, a screen reader reads the Chinese in an English voice — measured with the extension installed, all 14 translation nodes inherited `lang="en"`. The translation language (BCP-47, from `toBcp47(target)`) is written into `<html>`'s `data-axt-lang` in `enable()` (§7.1: global state lives here only), and `renderText` writes it onto every translation node's `lang`; **`<html lang>` cannot simply be changed**, that would label the original as Chinese as well
- **Purely decorative copies are hidden from screen readers**: side mode's mirrors (`.axt-mirror`) are the right column's visual balancing copies, identical in content to the left and without a translation; unhidden they would be read twice; the loading skeleton (`.axt-skel`) likewise, the per-block waiting state being carried by the popup's progress. Both get `aria-hidden="true"` **plus `inert`** [addendum, 2026-09-07, caught by the A/B audit on 2401.00596]: `aria-hidden` only stops screen readers, not Tab — the mirror of a bibliography entry carries DOI / arXiv links, and a keyboard user jumps into a decorative copy the screen reader ignores entirely, the focus landing and announcing nothing (axe's `aria-hidden-focus`). `inert` controls both focus and the accessibility tree, supported since Chrome 102, far below this project's floor of 131. Mirrors and skeletons are both **nodes we insert ourselves**, so adding attributes does not touch §7.1. Real translations are not hidden — they are content with information

**The attribution check is automated** [decided, 2026-09-07, issue #72]: comparing by hand against “the same page without the extension” should not be redone every time — auditing any injecting extension repeats that confusion. `tests/e2e/a11y.mjs` (`pnpm e2e:a11y`) runs axe twice on the same paper, the baseline being the same page without the extension, and the gate looks at the difference only.

The hard part is **how to take the difference**: we insert translations as sibling nodes, `:nth-child` shifts wholesale, and comparing the selectors axe gives is all false positives. The approach is to compute, for every violation, a key comparable across the two runs — one inside injected content follows `data-axt-for` back to the original block it translates, then locates **the matching element** inside the original block by relative path and uses its key; a host element uses its own key (`#id` when it has an `id`, otherwise the tag names and the same-tag sibling indices **with `.axt-*` excluded** joined up the ancestors). So the “`h6` from 1 to 2” above is automatically classed as inherited, while a problem on the translation that the original block lacks (a missing `lang`, low contrast) maps to no key in the baseline and is reported as it should be.

Two kinds of thing are compared by rule id rather than by element:

- **Document-level rules** (`region` / `landmark-*` / `page-has-heading-one` / `bypass`): axe reports “the outermost element not inside a landmark”, and inserting a translation makes it report another element. The root cause is that the host page has no landmark at all, and adding one means rewriting the original document's subtree, which §7.1 forbids.
- **`scrollable-region-focusable`**: axe checks for `tabindex` on scroll containers; since Chrome 127 a “scroll container without focusable children” is in sequential focus by default, and this project's minimum is 131. On 2026-09-07 the 6 scroll containers of side mode were measured one by one with the round trip on Chrome 153 (focus → Shift+Tab → Tab), **6/6 came back**. And 3 of the 6 are original nodes (`#alg1.4`, `#S2.T1.2`, `#S2.F2`), where adding `tabindex` breaches §7.1 as well. This one **is still printed**, only not judged a failure.

First measured 2026-09-07 (2410.00260, Chrome 153): baseline 45 items / 6 kinds (`empty-table-header`, `heading-order`, `landmark-*`, `region`); with the extension stack 56, side 544, only 399, **the difference empty in all three modes**. Mutation check: with a low-contrast `color` forced onto `.axt-t` and rebuilt, stack gained 441 and side 569 `color-contrast` items, all labelled `translation` — the mapping did not misjudge the translation's own problems as inherited.

### 7.5 Translation appearance [decided, implemented 2026-09-05; changed to the reader's own configuration lists 2026-09-10]

**Since v12 the appearance is a configuration of the reader's own, not a set of presets we supply** [decided, 2026-09-10, the owner's call; overturning the “port all 21 KISS presets whole” of 09-05 the same year]. A “translation style” = text colour + opacity + underline (`none` / `solid` / `dotted` / `dashed` / `wavy`, thickness 1 or 2) + blur until hover + advanced CSS declarations; a “background highlight” = colour + strength. Both are editable lists; the built-ins (six styles, three highlights) lie in the list as ordinary members, can be changed and deleted, and “reset” restores the built-ins by id and keeps the reader's own additions. Effects removed: borders (`quote` / `box` / `box-dashed`), backgrounds (`marker` / `marker-gradient` / `highlight` / `tint`), text effects (`gradient` / `colorful` / `glow` / `blink`); `blur` stays as a field. The reason is that the reader wants “to tune one to their own eyes”, and 21 fixed combinations neither cover everything nor leave room on the screen.

**The rendering contract narrows accordingly**: `<html>` keeps only two switch attributes, `data-axt-underline` (written only with a line, its value the line style) and `data-axt-blur`; everything else goes through the variables `--axt-color` / `--axt-opacity` / `--axt-deco-thickness` / `--axt-hl-color` / `--axt-hl-mix`, written into the injected sheet by `appearanceRule()`. `presets.css` shrinks from twenty rules to three: the shared underline rule, the blur, and the default variables. `data-axt-style` and `--axt-accent` are retired. The two disciplines below stay as they are; they do not depend on the number of presets.

The original record (the preset scheme of 2026-09-05):

- A translation node copies the original block's classes (§7.1), so font, size, line height, alignment and grid position match the original by nature, and a preset **only decorates on top**. The injected `<style>` comes after the site's styles, and `.axt-t` must **not** carry properties like `font: inherit` that would override the site's styles at equal specificity (measured: it overrode the abstract heading's 1.4rem and the bibliography's font with the parent defaults). `presets.test.ts` guards with a regex that `font` / `display` / `margin` / `line-height` / `width` do not appear in the presets
- **Port all of KISS's presets whole and delete the unused ones later** [decided, 2026-09-05, the owner's call; overturning the same day's first version of “pick only 4”]: the first version kept 4 on the grounds that “a paper is read for tens of minutes and motion gets in the way”; having seen it, the owner asked to port them all first and delete one by one by actual use — consistent with the criterion “port or not turns only on negative impact”: these presets do not interfere with each other, each is a few lines of CSS, no extra burden. The existing 20 plus one custom slot, in five groups: basic (`none` / `muted` / `green`), underline (`underline` / `dotted` / `dashed` / `dashed-bold` / `wavy` / `wavy-bold`), border (`quote` / `box` / `box-dashed`), background (`marker` / `marker-gradient` / `highlight` / `tint`), effects (`gradient` / `colorful` / `glow` / `blink` / `blur`). `green` and `tint` come from Read Frog's `custom-translation-node.css` (the former its default translation colour `oklch(0.693 0.17 162.48)`, the easiest to tell apart when comparing); `blur` is sharp only on hover, for self-testing and memorising. **Only compositor animations may stay** [decided, 2026-09-05, measured; Codex on #52]: main-thread tasks within 4 seconds on 600 translation blocks — `glow`'s `text-shadow` breathing **1028 ms** (style recalculation 549, layout 144), `gradient`'s `background-position` flow **573 ms**, against 2 ms at rest. A paper is read for tens of minutes, and such decoration is not worth burning a quarter of a core continuously, so both became **static** (the gradient fill and the glow remain, only unmoving), both back to 1 ms afterwards. `blink` changes `opacity`, runs on the compositor without style recalculation, measured 3 ms; it keeps its animation and still respects `prefers-reduced-motion: reduce`. Note that frame rate is no valid indicator: before going static all four presets held 60 fps — the work fit into the frame budget while the CPU kept burning; only CDP's `TaskDuration` shows it
- **Underline classes must draw explicitly onto atomic inline elements** [decided, 2026-09-05, the owner's report of missing lines]: by the CSS spec `text-decoration` **does not propagate into atomic inline boxes** like inline-block, inline-table and MathML, so the line breaks at formulas and inline boxes (measured: the computed `text-decoration-line` of `.axt-t math` is `none`). `text-decoration: inherit` does not work either — `text-decoration-line` is not inherited, and one ordinary `span` in between breaks it (measured likewise). The approach is for the underline classes to set only the `--axt-deco` variable, with one shared rule acting on both `.axt-t` and `.axt-t :is(math, .ltx_inline-block, svg, img)`. That shared rule **lists the underline class ids only** and cannot be written as a wildcard `html[data-axt-style]`: that would write `text-decoration: none` for the other presets and wipe the lines the site draws under links and citation marks. Measured on 2609.04056v1: all 51 formulas inside translations got `underline/dashed`
- **Appearance and mode are on the same layer**: the switch attributes are written on `<html>` (alongside `data-axt-mode`); a switch changes attributes only and touches no DOM. Before v12 it was `data-axt-style="<preset id>"`, now `data-axt-underline` and `data-axt-blur`
- **Decoration parameters are tunable** [decided, 2026-09-08, the owner narrowed #47 to this range]: the translation's **text colour, opacity and highlight colour** are set by the user and written into the config (v9). **Typography (font size, line height, page width, column gap, paragraph spacing) is not done** — the probe showed that half to be both expensive and risky: the body cap `96rem` is hard-coded in two places in `modes.css` and pinned from both sides by `layout.mjs`; changing the font size squeezes the column width, and §7.2 records 25 of 145 formulas not fitting when the body went 1536 → 1240; the default paragraph spacing must equal the uninstalled page pixel for pixel (`layout.mjs`'s `after.gap === before` is strict equality). **Weight is not done either**: the translation node copies the original block's classes, and writing `font-weight` would override the bold the site gives headings, the same kind of bug as the `font: inherit` recorded in this section; opacity already achieves “the translation does not compete for attention”.

  In the implementation **`modes.css` and `presets.css` are not changed**: the rule `styleVarsRule()` generates uses the same selector shape as the presets and comes after `presetsCss`, overriding at equal specificity by cascade order the `--axt-color` written by `muted` / `green` and the `--axt-accent` on `html[data-axt-on]`; the custom declaration block still comes last and has the final word. The values are **not written into `<html>`'s inline style** — `restore()` restores by “removing the injected sheet + stripping the `data-axt-*`-prefixed attributes”, an inline style carries no prefix and would not be cleared, breaking the node-by-node equality of §7.1 item 4. A hand-typed colour has to pass an allowlist (`sanitizeColor`), blocking input like `red; opacity: 0` that would open a new declaration.

  **Immediate effect**: the content script subscribes to `watchConfig`, and when `style` changes it calls `applyStyle()` — recomputing only the injected sheet's content and `data-axt-style`, touching not one translation node and **requesting no retranslation** (`chainConfigChanged` ignores `style` anyway). No message is used because the settings page is itself the active tab and `sendToActiveTab` cannot reach the content page, and the subscription also updates every open paper at once. Measured: after changing colour and opacity the computed style changes at once, the translation node count is unchanged, **new requests 0**

  > Corrected 2026-09-13: the three paragraphs above describe v9's `config.style` and `styleVarsRule()`, both gone with v12 on 2026-09-10 — the configuration is `appearance` (two lists, the passage below), the rule is `appearanceRule()` in `renderer/style-preset.ts`, and `data-axt-style` is no longer written. Kept as the record of why typography and weight were not done.
- **Decoration lands only on real translations**: `.axt-pending` (the loading ring) and `.axt-error` (the failure control with a “重试” button) carry `.axt-t` too — they grow in the translation's place, and side mode pairs by this class — but they are no translations. Side mode's structural clones `.axt-mirror` (mirrored formulas / figures) and `.axt-split` (whole figures split into the right column) likewise — they carry `.axt-t` for pairing only, `blur` would smudge a mirrored formula and other presets would paint the wrapper layer once more. Every preset selector is written `.axt-t:not(.axt-pending, .axt-error, .axt-mirror, .axt-split)`, and the real translations nested inside a clone still match; it is the same line as `REAL_TRANSLATION` in `split-figures.ts` (found missing `.axt-mirror` / `.axt-split` on 2026-09-07, now complete — for the consequence of the omission see §7.2 “tidying is incremental by changed area” (c)). Without the exclusion `gradient`'s `color: transparent` would make the retry button's text transparent, exactly when the user most needs to click it (Codex on #52)
- **Advanced CSS accepts a declaration block only, not whole rules**: the selector is supplied by the extension (since v12 `html[data-axt-on] .axt-t:not(…) { … }`, stacking with the other fields rather than being a separate `custom` preset), and what the user types is inserted whole between the braces, so `{` `}` `@` `<` are all refused. This is no security boundary (the user can install any extension anyway); it is against slips — one stray brace would change the layout of the whole paper and be hard to trace

- **The document title and subtitle do not share a line with their translations** [decided, 2026-09-06, Codex on #13]: `.ltx_subtitle` and `.ltx_title_document` both belong to the centred title area, and squeezed into `inline-block` they shrink to their content width and stick to the left — measured on a real page, the `(Extended Version)` of 2609.00246: originally `block` + `text-align: center`, filling the 800px column, the text centred at x≈720; as `inline-block` the box shrinks to 176px and lands at l=320 (the parent `<article>` is `text-align: start`). A section's run-in short heading is `.ltx_title_*` and unaffected

### 7.6 The waiting state: a skeleton [decided, Read Frog's ring ported 2026-09-05; changed to a skeleton 2026-09-11]

- The pending translation node is inserted after the original **before** the request goes out (`.axt-t.axt-pending`, the original's tag and classes, `data-axt-for` pointing at it). The wrapper first, the content later, exactly as §7.1 requires. When the translation arrives it **replaces** the node (`clearTranslation` at the top of `renderText` / `renderTable` removes the sibling with the same `data-axt-for`, cancelling the animation first) — the same result as filling the node in, with one path fewer. A table's pending node is a `div`; it only becomes a `table` once the whole clone is there. A short heading's pending node sits on the same line, per §7.3
- **What it holds is a skeleton, not a ring** (2026-09-11): one `<span class="axt-skel">` with one to three `<span class="axt-skel-line">` bars, sized in `em` so they follow the paper's type. How many bars comes from the original's `textContent.length` (under 120 characters one, under 320 two, otherwise three) — **an estimate, never a measurement**: reading layout here would force a reflow in the middle of rendering (§10). The last bar is short, so the block reads as text rather than as a box. A short heading's node keeps a single inline bar
- **The bars carry the brand colour.** `--axt-skel` is arXiv red mixed into transparency (14% on light, 24% on dark), so the placeholder is recognisably ours and the paper's background still shows through. A 6px grey ring said "something is happening"; a skeleton the size of the coming translation also says **where** and **how much**, and the page settles less when it lands
- **The pulse is one animation per block, and it is capped.** The skeleton breathes between full and 45% opacity over 1.4s (the shadcn/ui pulse, not a gradient sweep: opacity is composited, a moving gradient repaints every frame on every block). Web Animations API rather than a CSS keyframe, so the count stays countable: **at most 60 pulsing at once**, the rest are still — a page can hold hundreds of pending nodes at a time, and Read Frog measured two thousand concurrent animations taking the main thread down (#1881). `prefers-reduced-motion` means no animation at all, and the skeleton is still legible standing still. Handles live in a WeakMap and are cancelled before any node is removed, or a running animation pins a detached node in the renderer (#1831). The cap, the registry and the cancellation are Read Frog's, unchanged; only what is drawn is ours
- Failure: the skeleton is replaced by an error hint + a “重试” button (isolated in a Shadow DOM, §stack), the node kept; on user cancellation (restore the original / turn translation off) the whole pending node is deleted and no error is shown
- Side mode's tidying steps (figure split, mirror, footnote placement, margin alignment) **recognise real translations only** (`.axt-t` without `axt-pending`): a pending node's height has nothing to do with the translation, and computing `translationKey` from it or copying footnotes into it is work done for nothing. The pairing rule `:has(+ .axt-t)` applies to pending nodes as usual, so the original block and the skeleton take one column each, and the layout no longer jumps when the translation arrives
- In only mode a pending block's original stays visible as usual (the hiding rule recognises `translated` only, §7.4), the skeleton following it
- **The failed state** (PR 2b, 2026-09-05): an `.axt-t.axt-error` widget is inserted beside the failed block — inside a Shadow DOM, a “重试” button and a “！” with the reason (both the host and the “！” carry `title`), the original block marked `failed` with a red line. Retry = handing the block to `run.translate` again, deleting the widget first and inserting pending; the popup's “retry the N failed blocks” (`axt:retry-failed`) takes the same path. The reason is recorded per segment by the pipeline (the provider's kind + message, “the translation's placeholders do not match the source”, “cancelled”). Read Frog's React + jotai + @tabler/icons + base-ui version is not ported (the §12 trade-off); in side mode the widget lands in the right column, in the position of its inline error block

### 7.7 Hover highlight for sentence pairs [decided, implemented 2026-09-09, issue #105]

When the mouse rests on a sentence of the original or of the translation, **the matching sentence in the original and in the translation both get a background colour**. It answers the question asked dozens of times a day in a long paragraph: “which sentence of the original does this translated sentence correspond to”.

- **A background, not a text highlight.** Not one pixel of the text moves; only the background colour appears and disappears (the owner, 2026-09-09, explicitly)
- **One flat band per line, not hugging the glyphs (changed after the owner's feedback of 2026-09-09).** The first version drew with the CSS Custom Highlight API; `::highlight()` paints the text's own boxes: gaps at inline formulas, the background rising and falling with the shape of the glyphs, looking fragmented, while the owner wanted the flat band that wraps the whole line, like the “亮色底” of the style presets (two comparison screenshots were attached). Now it draws by the **line-level rectangles** `Range.getClientRects()` gives: one rectangle per line (measured: a two-line sentence returns 2, both 25 px high, formula and text treated alike), and several rectangles on one line are merged into one by vertical overlap, so **however many boxes a sentence is made of, a line always has one band** — no more gaps at formulas
- **§7.1 still holds.** Every background `<div>` sits in one container hung on `<body>`, outside `article.ltx_document`: the original tree is untouched, nothing is inserted between paired nodes, and the container carries `HL_CLASS` so `restore()` clears it with the other injected nodes. Coordinates are computed with the `documentElement` rectangle as the origin, so a margin or positioning the site puts on `<body>` does not shift everything
- **The measured limits of `::highlight()`** (measured in real Chrome at the time, kept on record to explain why that road could not give a flat band): it honours `background-color`; `border-radius` and `padding` parse but are ignored, `background-image` is not painted at all. **The ignored `padding` is exactly why it cannot paint “wrap the whole line”** — that pseudo-element has no box of its own to enlarge, and is forever only as tall as the glyphs. With rectangles drawn instead, the rounding and the inset are back
- **No transition (decided 2026-09-09).** `::highlight()` cannot take a `transition` itself; the first version had it read a custom property registered with `@property` and let `:root` transition that property — **it works** (a 2 s transition captured at four moments, four different images), but the property must be `inherits: true` for the pseudo-element to read it, so **every frame of the fade recomputes an inherited property for the whole DOM tree**. Measured sweeping a passage on a 292-block paper:

  | | p50 | p95 | max |
  |---|---|---|---|
  | highlight off | 8.3 ms | 9.1 ms | 9.4 ms |
  | highlight on · no transition | 8.3 ms | 9.1 ms | 9.5 ms |
  | highlight on · with transition | 8.4 ms | 13.0 ms | 16.9 ms |

  **Without a transition this feature is free**; with one the worst frame hits the 60 Hz budget, and exactly that stutter is what the owner reported in real use. Now the background appears and disappears directly. Wanting animation means another approach, in a new issue.
- **A miss is held 120 ms before clearing**: the gap between paragraphs is one continuous movement to the reader, and clearing at once flashes halfway. This has nothing to do with animation; it is the continuity of the hit test
- **The pointer has to be really on the text**: `caretPositionFromPoint` answers “where is the nearest insertion point”, not “is there text here”, so with the pointer in the page margin it still returns the character at the end of the line — the whole blank strip on the right lit up the paragraph beside it (the owner's report in real use). The hit counts only after comparing against that character's own rectangle, with a 4 px margin
- **The hit test** uses `caretPositionFromPoint`, not `highlightsFromPoint` — the latter answers directly, but it is a Chrome 140 interface while `minimum_chrome_version` is 131. Every pointer move does one `caretPositionFromPoint` + one walk up to the block + two binary searches; coalesced into `requestAnimationFrame`, and the `Range` is not rebuilt while the sentence is unchanged
- **When the engine is off by a character or two, the boundary is snapped back to the sentence-final punctuation**: the engine reports the sentence boundaries as it sees them, occasionally off by a character or two — Microsoft reported `…对话式工作流程。这|种新兴的…` on `2509.10652v3`, counting the next sentence's first character into the previous one (the owner's feedback of 2026-09-09). The division itself is exact, so `verifyAlignment` cannot stop it, and only the reader sees it. A snap is done at the gate: **one already after sentence-final punctuation stays**, **one with no sentence-final punctuation within three characters stays** (the author lists of a bibliography are of this kind; the “sentences” there are no sentences to begin with), **one whose snap would leave some sentence with only placeholders stays**. Placeholders are recognised by **the protocol's own grammar** (the engine may write `<x id='1' />`, and a narrow check would take it for visible text). **“Is it right now” uses the loose criterion, “can it be snapped over” the strict one** — merged into one, they would split a boundary like `…grafting?) |using`, already after punctuation, into the middle of `?)` (measured, it happened once). The strict criterion adds three conditions to the loose one: the punctuation must sit **directly** before the candidate position (a placeholder in between means the next sentence opens with a formula, and pulling it over hands the formula to the previous sentence), the period must not be an abbreviation's (`U.S. D|epartment` is followed by a capital, which “not followed by a lower-case letter or digit” cannot tell, so the sentence splitter's measured abbreviation table decides), and it must not be followed by a lower-case letter or digit (`Vol. 2`, `3.5`). In both directions the **whole terminal punctuation run is crossed** (`。”`, `……` is one ending; stopping in the middle hands half the punctuation to the next sentence) — what is crossed is the terminal punctuation and the **unambiguous** closing marks, **straight quotes excepted**: `"` can close as well as open, and in `甲。|"乙。"` that quote opens the next sentence. Among the abbreviations, `etc.` / `al.` really can end a sentence (the splitter already judges them by “what follows”) and cannot be rejected wholesale with `Vol.`. Candidates are **validated as a whole, all used or none**: backing off one by one would make the result depend on iteration order, and two candidates snapping to the same punctuation would cut a misaligned `[1, 2, 4]`; **equally close on both sides, the whole side stays** (no evidence favours either side, and leaving one in place while its neighbour moves cuts a division worse than the engine's). **The snap must be idempotent** — `verifyAlignment` runs more than once (once in the provider, once in the service layer, once more on a cache hit), a result landing in the middle of a punctuation run would move one more step the next time, and the same alignment would give different highlights depending on which road it took; so whichever direction a candidate comes from, it walks to the end of the whole terminal punctuation run. Measured: 483 alignments replayed twice, the results identical. Measured over 483 alignments of two engines, 3532 boundaries: **2 moved, 2 fixed, 0 broken**, the number of sentences without visible content level with the baseline (36)
- **Sentence boundaries come from the engine; nothing is guessed.** A block is registered only when the engine reported sentence boundaries and both sides' lengths rebuild the original strings exactly (§8.6 / `providers/alignment.ts`). Microsoft reports them; on the `tags` path the service inserts sentence markers so that Google's web endpoint reports them too (#137, `providers/sentence-markers.ts`; corrected 2026-09-13 — it read “Today only Microsoft reports them”). Blocks that come back without usable boundaries (the LLM engines today) are not registered and hovering does nothing — **a guessed pairing would put the highlight on the wrong sentence, which is worse than no highlight**
- The three things (the source side's wire offsets, the translation side's wire offsets, the sentence boundaries) exist together only at the instant of rendering, so they are registered after `renderText` into the module-level `WeakMap` of `src/core/renderer/sentences.ts`. **No `data-axt-*` attribute is written**: §7.1 allows adding, but this is hundreds of numbers per block; written in, they would bloat the document the reader is reading, be serialised out with the page, and be parsed again on every pointer move. The WeakMap also disappears with the node, so `restore()` needs no extra clean-up pass for it; after `restore()` the original block remains and the translation node is gone, and `target.root.isConnected` identifies the stale entry on the spot
- **The background is clipped to the container that clips it**: the band layer hangs on `<body>` (as §7.1 wants), hence outside the container that clips that text, while `getClientRects()` reports the whole layout box, the scrolled-out part included — in side mode a wide table scrolls inside `overflow-x: auto` (`modes.css`'s `[data-axt-fit="scroll"]` and `.axt-split`), and unclipped the band would run out of the container and over the neighbouring column. The boxes of every clipping ancestor are intersected, walking up from the block itself, read only once when the sentence changes and it is repainted (Codex on #138)
- **A reflow needs a repaint**: the bands are absolute boxes in document coordinates; scrolling they follow, window resizes / browser zoom / a font swap they do not, and none of those produces a pointer event — and the sentence cache would block the repaint while the pointer has not left the sentence. So on `resize` the cache is dropped and the geometry measured again at the pointer's current position; `applyStyle` changing the injected sheet (font size, line height, weight may all change) clears it too. **A reflow while the pointer does not move needs a repaint as well**: translations arrive block by block (the controller starts before the translation), and when a block above the pointed-at sentence is translated and inserted, the sentence is pushed down, with no resize / scroll / pointer event coming — a `ResizeObserver` watches `<body>`'s own box, covering image loads, font swaps and section expansions in one go; the bands are absolutely positioned and do not enlarge the container, so there is no self-triggering. **Watching the size alone is not enough**: a translation inserted between two blocks reflows everything below while the document height need not change, so a `MutationObserver` watches `<body>`'s subtree too, **`childList` / `attributes` / `characterData` all three** (a class changed on an ancestor can reflow a whole subtree without inserting a character) — **records whose target is the band layer are skipped**, or every paint of ours would trigger another repaint. A font swap produces not even a mutation and is caught by `document.fonts`' `loadingdone` (Codex on #138, in three rounds). **The remaining gap is “a pure CSS reflow with neither a mutation nor a change of `<body>`'s size”**; covering it would mean measuring the geometry every frame, exactly the cost this feature must not pay; the price is a band stuck in its old place until the pointer moves again. **A container scrolling by itself needs a repaint too**: page scrolling carries the bands along (they are boxes in document coordinates), a container scrolling its own content inside `overflow` does not, and that produces no pointer event either — `scroll` is captured on the document and the container's band repainted at once. **The page's own scroll is another matter**: the bands following is right, but the sentence under the pointer has changed, and a hit test on every frame of scrolling is exactly the cost this feature must not pay — so it holds 120 ms and asks where the pointer is once the scroll stops (Codex on #138 pointed out these four)
- **Clearing on a miss clears the container only**: with no transition there is no need for the “wait for the animation to end before removing” timing (which #130 kept for the fade-out); one `layer.remove()` is clean
- **An external clear has to invalidate the cache**: `setMode()` / `restore()` take the band layer away but cannot reach the controller's cache of “which sentence is painted now”. A module-level epoch, incremented on an external clear, and the cache records which generation it painted in — otherwise a pointer resting in place takes the short circuit forever and never repaints (Codex on #130)
- **Table cells are registered too**: after `renderTable` builds the clone table it reports “source cell → clone cell”, and the pipeline registers cell by cell from that table. What is on screen is the clone cell, and it is built only there
- **A footnote's box is carved out of the sentence's ranges** (2026-09-10, reported on 2609.09360v1): the note is a void placeholder inside the sentence, so the sentence's range covers the whole `.ltx_note`, and Chrome's `getClientRects()` reports **every** text box inside a range, the note text floated to the page's edge included — hovering a sentence with a footnote tinted the whole note in the margin. `rangesOf` already carved our own nodes out of a placeholder (#123); it now carves `.ltx_note_outer` too. The mark is on the line and belongs to the sentence, so it stays; the box holds another block, which tints on its own registration when pointed at. **The margin copy of a note is registered as a pair of its own**: both halves of it are clones — the original rebuilt from the placeholder, the translation `localizeNotes` places beside it — so neither was registered, and pointing at the note walked up to the paragraph's translation. `mirrorPair` mirrors the note pair's registration onto the copy, with node mappings from flattening both trees along their known differences (the wrapper walked through, our own nodes left out; the placed translation hides its marks rather than removing them so the trees stay isomorphic — a missing twin would let a sentence range run from the hidden original to the copy). The wrapper is the source root, which is what only mode hides, so the peek covers footnotes
- The colour follows `--axt-green`, the same colour source as the marker family; since v12 the background-highlight list of the appearance configuration (§7.5) writes `--axt-hl-color` / `--axt-hl-mix` over it (corrected 2026-09-13 — it read “`styleVarsRule` rewrites it from `config.style.accent`”, both gone with v12). The switch is `config.reading.sentenceHighlight` (the “阅读” section of the settings page), on by default
- **[Known gap]** rotated table headers: for a label under `rotate(-90deg)` inside `.ltx_transformed_inner` the rectangles of one line are stacked vertically, and merging by vertical overlap means nothing for it. Measured: of 12 fixtures only 2608.29808 has 6 really rotated ones (the other 12 are `rotate(-0deg)`), all single words like “Python” “Java” “C”, **not one a translation block** (0 `data-axt-id` inside rotated containers), so this path is unreachable today. When it is reached, group by the text's own axis, in a new issue (Codex on #138)
- **Copies are registered too (issue #139)**: in side mode `splitFigures` clones the whole figure with its caption into the right column, **what is on screen is the clone**, and the original's translation is hidden; registering the original alone, hovering the caption gives an empty rectangle on the translation side and not one band is drawn (the owner's measurement of 2026-09-10: 3 bands on the source, 0 on the translation). **The correspondence is recorded the moment the clone is made, while the two trees are still identical** — afterwards the source member of each pair is deleted inside the clone, the two sides are no longer isomorphic, and matching can only be guessed. One source can have several translations, and **the one on screen** is taken: `checkVisibility()` rather than `isConnected`, because a mode switch does not delete the copy, it only hides one side with CSS (stack hides the copy, only hides the original). With a single translation (every block except split figures) it returns directly without that style query. **The copy's lifetime follows the sentence registration**: on a retranslation, if the text length matches, the old copy's sentence boundaries are swapped for this version's, else it is dropped; if this round has no alignment, the copy's own record is deleted too (deleting the “source → translation” index alone is not enough; the copy is a key of the record table itself); and the split's signature encodes **the sentence registration state** too, so on “text unchanged, registration from none to some” the copy is rebuilt and mirrored again, leaving no copy that can never be looked up. **Tables are registered on the cells** (`renderTable` reports “source cell → clone cell” per cell), so the signature has to enter the cells: asking the `.axt-t` table itself is always empty, and “a table from no alignment to alignment, text unchanged” is invisible (Codex on #148; measured: of 157 splittable figures in 24 papers 2 hold tables, both in 2312.11805v4)
- **The original peek in translation-only mode [decided, 2026-09-10, issue #141]**: only mode has no original side by side, and on hover the band can land on the translation alone; the owner wants to rest on a translated sentence and see that sentence's original **in place**. The hover chain already ran whole under only, the source-side Range was right, it merely landed on `display: none` nodes with no boxes — all that was missing was “show a sentence that was not rendered”
  - **The trigger is “is the other side rendered”, not the mode**: `checkVisibility()` as one condition covers only, collapsed areas and any side hidden in the future; judging by mode needs a branch for each. With `visibilityProperty` and `opacityProperty`: blocks under `visibility: hidden` and `opacity: 0` keep their layout boxes, and without those two options bands would be painted on invisible text and the panel would never open (Codex on #149)
  - **Three placements, in order**: (1) when the article's right margin has room (usable width ≥ 18rem) **and that stretch of margin is empty**, it goes in the margin with its top edge aligned to the sentence's first line, covering nothing — at ≥ 96rem ar5iv puts footnotes and publication notes at the page's right edge, and `localizeNotes` leaves the translations there too (§7.2), so a panel on top would cover exactly what the margin placement promises not to cover (Codex on #149): in the read phase the rectangle the panel will occupy (the margin column × from the sentence to the viewport edge, in the direction the panel grows: downward when top-aligned, upward when hung from the bottom) is intersected with the box of every `MARGIN_ASIDE` on the page, and on an intersection it falls back to the beside-the-sentence placement; each margin note's rectangle is read once, and collapsed ones (0×0) and those left in the body flow naturally do not intersect. Two versions of point probes were tried and both wrong: first no probe at all, then one every 120px that misses a footnote one line high, with an 8-probe cap that does not serve a tall viewport either (Codex on #149, three rounds) — arXiv's original layout centres a 52rem article, the margin = (100vw − 52rem)/2, 224px at 1280px, 304px at 1440px, 544px at 1920px, room enough from about 1300px up; (2) otherwise it floats right under the sentence's last line, as wide as **the part of its block visible on screen** (the block rectangle intersected with the clipping ancestors' boxes and the viewport — a wide table block inside a horizontal scroll container has a rectangle wider than the viewport starting left of it, and copying it would put the panel's start off screen, Codex on #149), not covering the sentence being compared; (3) when less than about 10 lines (240px) remain below **and there is more room above**, it goes right above the sentence's first line — the panel is never measured, and going to the roomier side is the one thing it can do for a long sentence; the margin placement likewise chooses between “top aligned to the first line” and “bottom hung from the last line”. A sentence taller than both sides is still clipped (`overflow: hidden`; the panel takes no pointer events, so it cannot scroll either) — seeing it whole has to wait for an interactive panel, the same follow-up issue as “cannot be selected and copied” (Codex on #149). A bubble following the cursor was rejected: it covers exactly the neighbouring sentences to be compared, has to flip at every edge, and jitters as the pointer moves inside the sentence
  - **The content is a DOM clone of this sentence's original, not text**: a `display: none` subtree can still `cloneContents()` (the DOM is not the layout), and inline formulas, links and formatting all live; `textContent` would turn a formula into TeX source or nothing at all. **Cloned segment by segment, not with one spanning Range**: `rangesOf` cuts segments only at our own injected nodes (footnotes translated in place), and a Range from start to end would clone the translation into the panel. After cloning it goes through `stripInjected` (injected nodes removed, id and every data-axt-* stripped), then the footnote containers are removed (`ANNOTATION_SELECTOR` — it carries `float: inline-end` and a negative margin, and left in it would drift out of the panel to the page edge)
  - **Not in a Shadow DOM**: the cloned MathML and `ltx_*` nodes render correctly only with the page's own style sheets, and inside a shadow root the formulas fall apart. So it is an ordinary element hung on `<body>`, carrying the fifth injected mark `axt-peek`, cleared by `restore()` with the rest — §7.1 already accepted the same shape for `.axt-hl`. The panel carries **`inert`**: `aria-hidden` only removes it from the accessibility tree and `pointer-events: none` only handles the pointer, while a cloned `<a href>` can still be tabbed to and activated with Enter (Codex on #149); `inert` blocks focus, clicks and the accessibility tree together. **Font and colour are read from the page itself, not system colours**: arXiv sets the font on the article container rather than `<body>`, and a panel hung on body inherits the UA's serif; its dark theme is also switched by the site itself and does not follow the system preference, and `Canvas`/`CanvasText` under an emulated `prefers-color-scheme: dark` painted the panel white on black while the page stayed white (measured with a screenshot, 2026-09-10). So font and text colour are taken from the computed style of **the hidden side** (the original block) — the panel shows the original, and it looks the way the site sets the original, not the way a preset decorates the translation: the gradient preset sets the translation's `color` to transparent and clips a gradient out of the background, and copying the translation block would give a blank (Codex on #149); a `display: none` element's computed style is still computed, only the layout values are missing. A transparent colour walks up the ancestors to the first really painted one; the background takes the first really painted colour among `body` / `html`. These `getComputedStyle` calls all sit in the read phase and happen only when the other side is hidden
  - **Division of labour with the bands**: the visible side still gets its band (answering “which sentence am I in”), the panel uses the body font and no colour (answering “what does the original say”) — two colours for one relation are noise. **When the other side is hidden no band is computed for it**; the Range is built once and handed to the clone. Cloning is cheap: in real Chromium, `cloneContents()` of a whole source paragraph (a good deal more than a sentence) 20 times averages **0.010 ms each** (measured by e2e on 2609.00246), and it is done only once when the dwell expires and once on each sentence change
  - **Zero-measurement placement**: the panel's own height is never read — floating above uses `bottom` to anchor it so it grows upward, capped by `max-height`; below and in the margin use `top` + `max-height`. The reads needed (the article rectangle, the block rectangle, the first and last band of the visible side) all sit in the read phase of `update()`, read before writing together with the bands. `position: fixed`: scrolling closes the panel anyway, so it need not follow, and it does not enlarge `<body>`, so the resize observer does not self-trigger; the mutation observer skips the panel subtree
  - **Anchored to the part of the sentence inside the viewport**: a long sentence may have its start scrolled above the viewport with the pointer resting several lines down, and placing the panel by the start's negative `top` puts it off screen (Codex on #149); the first / last fully visible band is taken, clamped into the viewport, and `max-height` clamped to ≥ 0
  - **When the cloned subtree changes in place, close and wait for re-registration**: the registered offsets describe the text at registration time, and once the body text changes in place afterwards (`characterData`, additions or removals of non-injected nodes) the offsets are stale — rebuilding the clone from the old offsets would cross sentence boundaries and show a false comparison (Codex on #149; the example was a whole sentence replaced by `X.` with the panel then showing `X. Second sentence h`). So for every record in the observer that really moves text (`characterData`, additions or removals of non-injected nodes) the registered block it belongs to is found along the ancestors and that registration marked dirty — **whether or not the panel is open or a dwell is timing at that moment** (Codex on #149, third time: looking only at an open panel misses changes during the dwell and after a scroll closed it); the panel showing it closes, the dwell timing for it is voided, and it shows again only once the block is re-registered (a new map object). Attribute changes move no text, but one inside the element being shown makes the clone stale (an inline child hidden or revealed), and the next `show` with the same key rebuilds the clone; the nodes we insert into a block ourselves (a footnote's translation, the ring) and changes inside injected nodes never count — they are exactly what the pipeline does right after registering, the records arrive after the registration, and counting them would make every block stale the moment it is registered
  - **`<html>`'s attributes are observed too**: the site switches its theme by changing `<html data-theme>`, not one pixel of the body moves and neither does the pointer, while the panel's colours are copied inline; the same observer watches one more place, and on repaint rewrites the colours freshly read in the read phase (Codex on #149)
  - **When the dwell expires it first asks “is it still the current sentence”**: the `clearSentenceHighlights()` that `setMode()` / `applyStyle()` take has no panel to delete during the dwell, and an expiring timer that did not ask would render a stale panel by the decision and position from before the switch (Codex on #149); it asks the controller's sentence cache and the epoch. Besides the sentence identity, the panel's key holds **the element that was cloned**: the same sentence with the hidden side swapped, or the hidden side re-rendered, and the fast path that only moves the position would leave the old clone (Codex on #149)
  - **A 600 ms dwell, timed by sentence identity** (the owner, 2026-09-09: the pointer naturally brushes text while scrolling, and popping up at every sentence it brushes would be very disturbing; float only on a real stop): jitter within the same sentence does not reset; **with the panel open a sentence change switches at once** (the tooltip's warm-up model, no waiting again at every sentence when comparing sentence by sentence); leaving the text keeps the 120 ms grace then closes and cools down; **a page scroll closes at once and cools down**, and not one sentence swept while scrolling pops up; **a container scrolling by itself likewise** — the sentences passing under the pointer beneath a scrollable table must not switch warm one by one (Codex on #149); after the stop the dwell starts over
  - The panel is `pointer-events: none`, so moving toward it does not count as leaving the sentence; the cost is that the original cannot be selected and copied, which would need a “the pointer is on its way to the panel” grace, in a new issue
  - **Known limits**: coverage follows the sentence alignment (Microsoft, and Google since #137), and blocks without an alignment do not pop up — the same as the highlight today, degrading to paragraph level being a separate discussion; screen readers cannot reach the original under only anyway, and the panel is `aria-hidden`, which changes nothing about that

## 8. Provider interface

### 8.0 Requests run in the background [decided, revised 2026-09-06; the “run in the content script” of 2026-09-04 withdrawn]

The providers' `fetch`, the engine chain, the queues and the cache are **all in the background**. The content script's translation traffic is three kinds of message: `axt:translate` / `axt:cancel-scope` / `axt:provider-status` (corrected 2026-09-13: it sends others too — `axt:ocr`, `axt:helper-status`, the replies to the popup's page commands; `shared/messages.ts` is the table). The settings page's “连接” (it saves and then tests, one action since UI.md S-O-19; corrected 2026-09-13 — it read “connection test”) and page translation therefore share the same `TranslationTransport`, and “the test passes, translation fails” can no longer happen (issue #42).

The two reasons for moving requests into content on 2026-09-04 were both overturned by the measurements of 2026-09-05 / 06:

- **“The worker gets suspended while waiting, and a cold start costs a message tens of seconds” does not hold**. RESEARCH §6.7: in real Chrome, after three rounds of 40 s idle (beyond MV3's 30 s idle reclaim) and a reload, the content → background round trip is 77–81 ms, the 1.5 s cache-read budget never fired once, and the popup's “翻译” button is clickable right after a cold start; the 6.7–77 s recorded in §6.5 cannot be reproduced on the current code (that measurement was made on the version whose cache write still scanned the whole store). RESEARCH §6.8 also measured “survival while waiting” — the failure mode §6.5 really feared: a request forwarded through the background and answered after a 90 s delay returned as usual, **with no keep-alive of any kind** (neither a Port nor a heartbeat)
- **“The content side can make cross-origin requests” holds only when the other side sends CORS headers**. RESEARCH §6.7: a content script's fetch carries **the page's origin** and goes through a preflight, and an endpoint returning no CORS headers fails outright with `TypeError: Failed to fetch`; the background's fetch carries the extension origin, skips the preflight, and reaches both kinds of endpoint. `host_permissions` does not lift this constraint (Chrome's behaviour since 85). The harder one is **Local Network Access**: a page on `https://arxiv.org` **cannot reach a local endpoint at all**, the request never leaves the browser — the local Ollama CLAUDE.md explicitly supports (`http://localhost:11434`) is wholly unreachable from the content side. This used to say “mixed content”, a misattribution (Codex on #57): loopback is a potentially trustworthy origin by the spec, and an `https` page calling it is no mixed content; in the control experiment of RESEARCH §6.7 `https://127.0.0.1` was blocked just the same, so **a certificate on the local endpoint is no way around it**, and only the background gets through
- A correction in passing to how §6.5 cited the reference projects: Read Frog's requests **also run in the background** (`entrypoints/background/translation-queues.ts` queues them and calls the model); “it puts fetch in content”, written at the time, does not hold against the reference snapshot

After moving back:

- The API key no longer enters the content script's isolated-world memory, one layer stronger than before (the rest of hard rule 7 unchanged)
- The content script no longer bundles the three providers and the AI SDK: the output fell from 428.95 kB to 152.47 kB, that much less to parse on every arXiv HTML page opened
- Two fewer message round trips per batch: the cache no longer goes through `axt:cache-get` / `axt:cache-put`, the background reads and writes Dexie directly
- **Direct evidence**: `pnpm e2e:local-endpoint` starts an `http://127.0.0.1` OpenAI-compatible endpoint that **returns no CORS header and answers every preflight with 405**, and translates a real arXiv page with it. The same e2e run before and after the change (`AXT_EXT_DIR` pointing at the two builds):

  | | Settings page connection test | Page translation from the local endpoint | Page-translation requests the endpoint received | Requests the page itself sent |
  |---|---|---|---|---|
  | Before the move (main) | passes | **0 / 12 segments** | **0** | **21** (all blocked by Local Network Access)|
  | After the move | passes | 12 / 12 segments | 7 | 0 |

  The “before” column is exactly the complaint in issue #42's title: **the same endpoint passes the test and fails to translate**, and the failure is **silent** — the chain falls back to google-web, fluent Chinese appears on the page all the same, and the user cannot tell that the endpoint they configured was never used. So this e2e asserts “the translation carries the local endpoint's prefix”, not “Chinese came out”

```ts
/** Where a translation request runs, abstracted (src/providers/transport.ts). Two implementations, one interface */
export interface TranslationTransport {
  translate(call: TranslateCall): Promise<TranslateMessageResponse>
  /** Withdraw the scope's queued and in-flight requests; returns how many were withdrawn */
  cancel(scope: string): Promise<number>
  status(): Promise<ProviderStatus>
}
```

- `createLocalTransport(config)` (background): `buildChain` → one `createTranslateService` per engine (sharing the local Dexie cache port) → composed by `createFallbackService`
- `createMessageTransport()` (content / options, `src/shared/transport.ts`): every method is one runtime message. **A file of its own** for the bundle size — `transport.ts` pulls in the three providers and the AI SDK, and content should get only the message proxy
- **Cancellation is best effort**: `axt:cancel-scope` is dispatched to the **current** chain. If a configuration change or `axt:engine-ready` has rebuilt the chain, requests still in flight on the old chain cannot be withdrawn — when they return, the content side blocks them at the receiving end by session id (`halted()` in `run.ts`), the cost being a few wasted requests, with nothing written to the DOM. Not cancelling the old chain is deliberate: turning every in-flight batch into a failure on a configuration change would show the user a screen of retry buttons, worse than letting them finish
- **A call naming an engine does not go down the fallback chain**: when `TranslateCall.providerId` is set, it is dispatched straight to that step's service. The settings page's “测试连接” asks “does the endpoint I configured work”; with a free fallback on the chain showing it as success would be issue #42's “two paths disagree” made again in the other direction — the user would think the key is fine while the whole page is being translated by Google. Naming an engine not on the chain reports the error truthfully, with no quiet substitution (`pnpm e2e` has an assertion guarding it)

### 8.2 LLM call conventions

- AI SDK 7's `generateText` + `Output.object({ schema })` (`generateObject` is superseded) + the zod schema `{ segments: { id, text }[] }`, leaving structural validation to the SDK; the SDK's own `maxRetries: 0`, retries left to the ported retry policy
- **The prompt has two layers** [decided, 2026-09-05]: `prompt-library.ts` is ported from Read Frog (the template variables `{{targetLanguage}}` `{{input}}` `{{paperTitle}}` `{{abstract}}` `{{sectionTitle}}` `{{glossary}}`, the built-in prompts `default` / `precision-rewrite`, user-defined `patterns`, selection by `promptId`, fallback to default when not found) and is in charge of “how to translate”; the **protocol block** of `prompt.ts` (JSON segments + placeholder rules + output shape) is appended after any system prompt and is in charge of “how to send and receive”, and a user-defined prompt cannot change it. The protocol is ours (AI SDK structured output + zod), steadier than Read Frog's text-delimiter batching, and stays; Read Frog's web-page summary takes an extra LLM call, while a paper's own abstract is used directly
- **The two placeholder examples in the protocol block: kept, but recorded as an unverified trade-off** [2026-09-11]: item 2 of `PROTOCOL_BLOCK` gives `<x id="3"/>` and `<t id="5">` as examples. Read Frog **deliberately gives no example** at the same spot, the reason written in the comment of their `inline-atom-tokens.ts`: one marker appearing in an example tells the model that “emitting a marker” has a baseline probability. We have no evidence for that claim — our marker shape differs from theirs (XML style vs `{{n}}`), and validation stops ids that do not exist (judged `unknown` → the single block re-sent → the runs fallback), so the worst case is one wasted request. **Settling it needs a real-machine A/B**: the same batch of segments, two versions of the protocol block, count the ids that appear from nowhere and the ids lost; `pnpm e2e:placeholders` can already run against a configured service, and all that is missing is an LLM key. Unchanged until there is data
- **Metadata goes in the user message, delimited with `<document_metadata>` and declared untrusted reference**: Read Frog puts it in the system prompt; the title / abstract are written by the author, and a paper discussing prompt injection may carry instruction-like text, which in system would be taken as peer instructions (Codex on #28). The protocol block also declares that both the segments and the metadata are data, not instructions
- **The glossary is sent with every batch** [decided, 2026-09-05]: the source is the configuration (`glossary: { term, translation }[]`, since v6), edited as text on the settings page (one entry per line, comma or tab separated, `#` comments); parsing and deduplication in `providers/glossary.ts` (the shape after KISS `parseAITerms`, plus tabs, comments and line-level error reporting — a faulty line is reported rather than silently dropped). **A semicolon is no record separator** (KISS splits `a, 甲; b, 乙` into two): a semicolon inside a translation is ordinary writing (`kernel, 核; 统计学中称核函数`), and treating it as a separator would quietly split one valid mapping into two unrelated ones (Codex on #52). **Capped at 200 entries**: every batch carries it, and 200 entries are about 2–3 KB / 700 tokens, the order of the abstract; beyond that it should be filtered by hits per passage, left to v2. There are per-entry caps too (source 120 characters, translation 200) and a total cap of 6000 characters, or a whole document pasted in as one entry would be accepted just the same. The caps live in `GLOSSARY_LIMITS`, and **the migration must run `normalizeGlossary`** — v6 had none of these caps, and copied into v7 as it was, `getConfig()` would judge the whole configuration invalid and fall back to the defaults; the user would see API key, engine and prompts all gone (Codex on #52). **A custom prompt missing `{{glossary}}` gets it appended automatically**: the same fallback as for `{{input}}` / `{{targetLanguage}}`, or a template “created” anew would not carry the variable by default and a configured glossary would have no effect at all; this changes what is actually sent to the model, so `PROMPT_VERSION` rose to 4 with it (hard rule 6). **An empty table sends no field** (not an empty array): in `contextPayload` an empty array and absence share a key, so enabling the glossary does not void every existing cache entry at once, while changing one rendering voids the affected ones — exactly what is wanted. LLM only: the free engines read no context, and `translate-service` puts the context into the cache key only when `provider.promptKey` exists
- **Paper-level context goes with every batch**: on page load `paperContext()` extracts the title and abstract once (the abstract with the "Abstract" heading removed, the TeX source inside MathML `<annotation>` skipped, truncated to 1200 characters; it must be extracted before translation, since extracting after one would count the previous round's translation in), enters every batch's `request.context` through `RunOptions.context`, and is merged with the batch's `sectionTitle`; the cost is about 300 input tokens per batch
- The prompt carries a version number `PROMPT_VERSION` (2 when the prompt library was wired in; 3 when `{{targetLanguage}}` switched to the English language name), written into the cache key; **the prompt identity `promptKey`** (the id for a built-in, the full text in two separately encoded parts for a custom one) and **the context text** (title / abstract / section / glossary, serialised structurally; free engines read no context and carry none) also enter the cache key's SHA-256 payload — a changed prompt, or the same passage appearing in another paper, must not hit the old translation. **Not squeezed into a 32-bit hash first**: a DJB2 collision cannot be told apart by the outer SHA-256 (Codex on #28 gave the instance `19k04n01vcr73f` / `1efm0uaep90s9`); the configuration migration v1→v2 adds the `prompts` field and keeps the API key
- **`{{targetLanguage}}` is filled with the English language name, not the language code** [decided, 2026-09-05, after Read Frog's `translate-text.ts`]: "professional zh-CN native translator" reads worse than "Simplified Mandarin Chinese"; the names come from `config/languages.ts` (the table ported from `@read-frog/definitions`, ISO 639-3 codes), and an unknown code is filled in as it is
- **The entry points for prompts and thinking mode** (clean-up item 3, 2026-09-05): the settings page has prompt management (built-ins read-only with “复制并自定义”, custom ones created / edited / deleted, variable buttons inserted at the caret, JSON import / export with the same file shape as Read Frog, importable both ways) and a thinking-mode switch (no field sent for unregistered endpoints); the popup has a prompt drop-down (saved at once, effective the next time translation starts). Read Frog's corresponding components depend on base-ui, jotai, Tailwind and its i18n; pulling in a whole UI stack for a page of a dozen fields is not worth it, so the logic is ported by file (`prompt-file.ts`) and the UI rewritten in the settings page's existing plain React. Read Frog has since turned the thinking switch into the AI SDK's `reasoning` levels (none…xhigh); we still send a switch field per endpoint KISS-style, and the level model waits for verification on the AI SDK side
- **Batching does not look at the engine kind, only at how much it takes at once** [decided, 2026-09-06, met in measurement]: `BatchQueue` used to be built for `kind: 'llm'` only, copying Read Frog's `shouldUseBatchQueue`. But that check presumes **their free engines are single-item interfaces**, and ours are not — `translateHtml` carries 150 items at once (RESEARCH §6.6), and the built-in engine declares 20. Copying it threw away the free engines' greatest advantage. Now every provider gets a `BatchQueue`, and a provider with `maxItemsPerBatch` 1 degrades naturally to one request per item, with no second path needed (`enqueueWhole` deleted with it)
- **For engines that read no context, the context does not enter the batch key**: `batchKey` carried `request.context` unconditionally, and `run.ts` puts `sectionTitle` into it, so the key changed at every section — a free engine's batches could not cross sections, and batching was as good as off. The cache key has had the same check all along (`context: provider.promptKey ? request.context : undefined`); the batch key missed it, now aligned
- **One chain and one set of queues for the whole browser** [decided, 2026-09-06, issue #43]: rate limits are per API key, not per tab. With one set of queues per tab the real concurrency against one endpoint is “tabs × 8”, exactly the recipe for a 429. The chain lives in the background and is rebuilt only when **a configuration field that changes the chain** (`provider` / `services` / `prompts` / `targetLanguage` / `fallback` — `openaiCompat` became `services` in v12; corrected 2026-09-13, the table is `CHAIN_CONFIG_FIELDS` in `config/revision.ts`) changes — content writes the configuration at every display-mode switch, usually while the page is translating, and an indiscriminate rebuild would uproot the token buckets and the fallback records (the classification table is in `CHAIN_CONFIG_FIELDS` / `VOLATILE_CONFIG_FIELDS`, with a test guarding “every configuration field is classified explicitly”). The cost is halved throughput when two papers translate at once, a deliberate trade-off
- **One batch's failure does not condemn another batch's results with it** [decided, 2026-09-11, Codex on #163]: one `translate` call may be split over several `BatchQueue` batches, and when one succeeds while another hits a systemic failure (timeout, quota, network) the service writes the successful ones into the cache yet reports `ok: false` as a whole. With “systemic failures are not halved” added, the content layer then marked the whole batch failed — while those translations were sitting in the cache, and one press of retry brought them all back in an instant. Now the failure response carries `partial` (the segments that succeeded in this call), `run.ts` renders them first, and only what remains enters the “split or not” decision. **The image pipeline likewise**: one image's labels can span several batches too (an inline TikZ picture easily has a hundred-odd nodes), and the translated ones are drawn before the failure is recorded — a few labels missing beats an empty figure, and on retry the drawn ones hit the cache directly. **On the fallback chain the union is gathered by id**: every step of the chain re-sends the whole call, and since the cache key carries the provider, a segment translated by the previous step does not hit the cache at the next, and is lost if that step cannot translate it; when the primary engine translates A and the fallback B, the caller has to get both (the later overriding the earlier). Not solved by “treat any partial success as isolatable”: that would put timeout-class failures back into halving, and the old problem of 8 segments fanning out into 15 calls returns.
- **Only the glossary entries this passage uses are sent** [decided, 2026-09-11]: before, every batch carried the whole table — 50 entries are about 300 tokens, while a batch of body text is around 1000 characters, so a request could double; and the cache key carried the whole table, so changing one term voided the whole site's cache. Now `createGlossaryMatcher` (`providers/glossary.ts`) matches passage by passage: **each passage's cache key carries only the entries it uses**, **the prompt a batch sends carries the batch's union** (in the glossary's own order, so the same set of terms renders as the same text in any batch). The batch key still groups by the whole table — keyed on the match result, two passages using different terms could not be batched together, and batching would be for nothing. An entry absent from a passage cannot change that passage's translation; this trade-off is the same as Read Frog's `mergeBatchGlossaryTerms`.
  Matching uses **the body text with placeholders removed and entities decoded**: in the wire text an `<x id="1"/>` keeps a term from spanning it, and the attribute name itself is matched as body text (the term `id`); and `&` / `<` / `>` are escaped in the wire text (`serialize.ts`), so without decoding, terms like `R&D`, `<UNK>` never match against `R&amp;D`, `&lt;UNK&gt;`, and both the prompt and the cache key quietly lose that entry (Codex on #163). **Decoded token by token, not joined and then decoded**: `foo&` + a placeholder + `amp;bar` joined look like one `&amp;` and would conjure an entity. The matching pitfalls copy Read Frog's lessons (they shipped two fixes for them, the failure mode each time being “a term was configured and quietly had no effect”): whitespace inside a term compiles to `\s+` (on the page it may be two spaces, a soft break, a non-breaking space), both sides are NFC-normalised first, word boundaries follow the writing system (`net` does not enter `network`, while there are no spaces between Han characters so no boundary is required; the unspaced scripts are not only Han and Japanese kana — Thai, Khmer, Lao, Burmese and Tibetan in the target-language table cannot demand boundaries either, Codex on #163 pointed out the latter four were missing), and when a hit's boundary is wrong the search continues (`network and then the net`). Their implementation was not copied — it has to run over 20 thousand terms and uses one compiled giant alternation plus an index; our scale is the few dozen entries one reader lists for one paper, and scanning entry by entry is enough. **With no glossary configured, keys and requests are byte for byte as before**.
  **The batch's union does not enter the cache key**, a conscious trade-off (Codex on #163 asked for either into the key or batching by hits): batching by hits measured multiplied requests **5.16-fold** (the 769 text segments of 2609.04056, 20 terms, windows of 8 segments: 97 batches → 501; windows of 16, 8.45-fold), a cost far beyond the gain. And “one key corresponds to one prompt” **never held under batching anyway**: a request also carries the body text of the other segments in the batch, and who the neighbours are affects word choice to begin with; the union of terms is only a smaller share of the same influence. So the status quo stays, written down here instead of pretending the cache key pins the prompt.
- Batches are cut by section (a heading block opens a new batch), one batch not exceeding `maxBatchChars` (defaults after Read Frog: 1000 characters / 4 segments; the rate likewise its token-bucket defaults of 8 requests/second, burst 20; the service batches by batch key for another 100ms — small batches, high concurrency, a fast first screen); `sectionTitle` goes along as context; formula-dense blocks form batches of their own; a table block is one batch for the whole table (`renderTable` needs all cells to arrive together)
- Batch failure: **only one caused by some segment** is halved and retried → single block → marked failed

  **Where a failure belongs is decided on the service side; the content side does not guess** [decided, 2026-09-11, the independent audit's F14 / A02]: before, the content side halved on any failure whatsoever; measured, a systemic `bad-request` on 4 segments became 7 calls (`4,2,1,1,2,1,1`) — the same failure multiplied by the segment count, and for quota-class failures counterproductive. Yet the service side had long had a rule for the same thing (`asBatchError` does not turn systemic failures into batch errors, Codex on #61: a batch of 100 segments would be fired 104 times for nothing). Now `ProviderError.isolatable` takes a default by kind (`invalid-response` / `timeout` / `unknown` true — splitting smaller may locate the segment; `rate-limit` / `network` / `bad-request` / `no-key` / `auth` / `aborted` false), a provider overrides when it knows more (a free engine's “the response is not JSON” is systemic, while a 4xx caused by one over-long segment is, conversely, isolatable), and it follows the error across the message boundary through `toErrorInfo`. There is only one criterion: **was this failure caused by some segment, or is the whole road down**.
  `timeout` counted as isolatable at first (“a smaller batch might come back within budget”), changed after measuring: a batch of 8 segments fanned out into **15 calls** at the content layer (`8,4,2,1,1,2,1,1,4,2,1,1,2,1,1`), and the queue retries by retry-policy on top, the two layers multiplying to as many as 45 requests, each waiting out its own timeout — exactly the “whole page stuck in progress” the timeout was set to avoid. Recovering from a timeout belongs to the queue: the budget by character count, the deadline per batch, the data and the responsibility both at that layer.

- **Every request has a cap, and a timeout is handled as a retryable error** [decided, 2026-09-05; the same day handed to the ported request-queue]: without a cap one hung connection leaves the whole paper's translation “in progress” forever — measured on 2312.17527 against the real API: 152 of 153 blocks translated, the last (1600 characters, 32 placeholders) still not back after 220s, `translation done` never logged, the popup spinning forever. The cap scales with length: 20 s + 15 ms per character, at most 120 s (Read Frog's constants; a 1000-character batch 35 s, that 1600-character block 44 s); request-queue adds the timeout with `Promise.race` and aborts the in-flight request (cut off even when the provider ignores the signal), the timeout falls under retry-policy's `timeout` class and is retried (2 by default), and once exhausted only that block is marked failed

### 8.3 Free engine conventions

- **Throttling has two gates: the concurrency cap controls “how many are open at once”, the token bucket “how many are sent per second”** [decided, 2026-09-06, met in measurement]. `google-web` was originally p-queue's `concurrency: 2` (2 in flight at once, no rate limit); when `RequestQueue` was ported on 2026-09-05 it was miswritten as `rateLimit: { rate: 2 }` (2 per second). The two differ in meaning: Google's median response is only **63 ms**, yet the token bucket held it to one every 500 ms. Now `TranslationProvider` declares `maxConcurrent` separately, `google-web` is back to `maxConcurrent: 2`, and the rate is loosened to `rate: 20 / capacity: 8` **only to catch pathological bursts** — `rate: 4` was tried in between, and at once became the new bottleneck (24 requests filled 5.3 seconds); the rate gate should not be the everyday constraint.

  Measured with the three defects stacked (2410.00260, google-web, a fresh empty cache, scrolling screen by screen to the end):

  | | Before the fix | After the fix |
  |---|---|---|
  | Whole paper | 31 615 ms / 213 blocks (**148 ms per block**)| 2 959 ms / 190 blocks (**15.6 ms per block**)|
  | Requests | 65 | **21** |
  | Segments per request | median 2, mean 4.2 | median 11, mean 11.2 |
  | Gap between adjacent requests | median 500 ms (= 1/rate)| — |
  | HTTP status | 200 | 200 (not rate-limited)|

  **9.5×**, and the request count down to a third — gentler, if anything, on this unofficial endpoint. `pnpm e2e` has two assertions guarding it: mean ≥ 5 segments/request, at most 2 in flight at once.

- **Systemic failures do not enter batch-level retries** [decided, 2026-09-06, Codex on #61]: `BatchQueue` does “retry 3 times + fall back item by item” for `BatchCountMismatchError` only, and `asBatchError` turns a provider's `invalid-response` into it — right for an LLM (most likely one segment derailed the output, and splitting smaller can locate it), pure waste for a free engine's “the whole response is not JSON”: a batch of 100 segments fires 104 requests for nothing, at the very endpoint we want to spare. `ProviderError` therefore carries an `isolatable` (true by default), a provider declares it false explicitly on a systemic failure, `asBatchError` does not convert, and the error is reported to the fallback chain at once. google-web's “not JSON” and “malformed” are false, “the count does not match” stays true (sent item by item it usually matches)
- **HTTP statuses have to tell transient from permanent** [decided, 2026-09-06, Codex on #17]: `google-web` used to class every non-429 failure as `network`, and retry-policy's `isRetryableRequestErrorMeta` **looks at the kind before the status code**, judging `network` retryable outright — a 400 that can never succeed would be retried the full 3 times and then halved by BatchQueue and retried item by item, a batch of 100 segments ballooning into dozens of useless requests. Now mapped by status code: 429 → `rate-limit`, 401 / 403 → `auth`, the other 4xx (408 / 409 excepted, which the status table counts as transient) → the new `bad-request` (not retried but still triggering the fallback chain — another engine may succeed), and only 5xx and connection-layer failures are left to `network`
- Treated as things that **may break at any time**: a file of their own, an error type of their own, failure switching automatically to the next in the fallback chain
- The default fallback chain: the user's chosen provider → `chrome-builtin` → `google-web`
- `google-web` sends several items per request (by default 100 items / 8000 characters a batch), `rateLimit: { rate: 20, capacity: 8 }` with `maxConcurrent: 2` — the “2 a second” written here on 2026-09-05 was a porting mistake that starved the queue (`google-web.ts`), and every provider batches through the `BatchQueue` (§8.2); corrected 2026-09-13, it read “rate pressed to 2 requests/second, burst 2 … no batching”; 429 and timeouts as in §8.2, handled by request-queue throughout
- **A 429 pauses the whole queue, provided by the ported request-queue** (2026-09-05): concurrency or rate are only caps, and while the task that hit the limit sleeps the other tasks keep firing at the same endpoint (Codex on #6 / #10). request-queue's approach: the pause lasts the larger of Retry-After and the backoff (5 s × 2^consecutive, 10% jitter), several 429s within the same window count as one consecutive; no task is dispatched during the pause, and the one that hit it is rescheduled to the end of the pause; at the end of the pause the bucket keeps at most one old token and the rest refill at the rate — at the default 8/s a 5 s pause refills the capacity of 20, so “a single probe” holds only at low rates, which is its behaviour as ported (the stricter hand-written probe gate of #30 was deleted, by the rule of porting by directory without changes); 5 consecutive windows or 8 429s on one task drain the whole queue. `no-key` / `auth` are marked access-denied and drain the whole queue, `aborted` / `invalid-response` are marked non-retryable — the metadata is attached by kind when `ProviderError` is constructed (no-key and mismatched ids are thrown outside the try), since the ported policy does not know these kinds and once retried no-key as an unknown error 4 times, waiting 7 s for nothing
- **Thinking mode is off by default** (after KISS's THINKING_API_REGISTRY): the field is chosen by endpoint domain — OpenRouter `reasoning: { effort: "none" }`, DeepSeek official `thinking: { type: "disabled" }`, Bailian / SiliconFlow `enable_thinking: false`, nothing sent for unregistered endpoints; it enters the request body through the AI SDK's `providerOptions` (`src/providers/thinking.ts`)
- **The instant engine** [withdrawn 2026-09-13 — never built; what exists is the fallback chain of §8.5 alone, `chrome-builtin` serving when the chosen engine fails, and no setting for the double write described here; RESEARCH §7 row 21 was a suggestion, written in here as if decided]: when `chrome-builtin`'s model is ready (`availability() === 'available'`) a single sentence takes 10–20 ms offline; it renders the blocks in the viewport first, and the user's chosen LLM translation replaces them in place when it arrives; the cache key carries the provider, so the two do not overwrite each other. The user can turn it off in the settings

### 8.4 `chrome-builtin` conventions (Phase 0 measurements, Chrome 152, RESEARCH.md §6)

- `isAvailable()` goes by `Translator.availability({ sourceLanguage, targetLanguage })`: `available` is usable directly; `downloadable` / `downloading` need a **user gesture** — the language pack download can only be triggered by calling `create()` inside the popup's click handler, otherwise `NotAllowedError` is thrown; once the model is ready `create()` needs no gesture (1 ms)
- During the first download `availability()` does not become `downloading`, and `monitor` has no `downloadprogress` event (measured: `downloadable` throughout 67 s); the UI shows the indeterminate hint “正在下载语言包”; only a second `create()` after the download completes gives 0→1 progress events (about 8 s of local loading)
- Language packs are downloaded per language pair (en→zh and en→ja separately)
- **Implementation conventions** (2026-09-05): `isAvailable()` **recognises `available` only** — `downloadable` / `downloading` both need a user gesture, which the automatic fallback on the chain cannot get, and `create()` would throw `NotAllowedError`; the download entry therefore sits in a click handler — the popup's service menu and, since UI.md S-O-11, the Chrome card of the settings page (corrected 2026-09-13; it read “only in the popup”) —, and only an indeterminate hint is given (no progress events during the first download). **Session creation takes no batch's signal** (Codex on #50): the session is shared by every batch, loading the model takes seconds to a dozen seconds, and the concurrent batches all wait on one Promise; passing the first batch's signal into `create()`, that one batch timing out would reject the shared session at the root, every other batch would get `aborted`, and the fallback chain neither retries nor falls back on `aborted`, so the whole page's translation would break right there. Cancelling a single translation still works. **The concurrency gate is provider-level** (same source): batches are planned by the pipeline against the **preferred** engine's caps, and the fallback chain forwards the same call as it is — with `google-web` preferred (8000 characters / 100 items), 100 concurrent inferences would be fired at the local model in one go, crushing it exactly when the fallback is needed. The gate is a semaphore shared by one provider instance guarding `BUILTIN_MAX_ITEMS = 20`, **not batching within one call**: the queue can dispatch several batches at once, and controlling one call alone is no control (Codex on #50). **Session creation has its own timeout** (same source, 60 s; local loading measured at about 8.6 s): since the shared session Promise takes no batch's signal, it must have an expiry of its own — or a `create()` that never returns lives in the cache for good and every later retry waits on the same dead Promise; the timeout is reported as `timeout` (retryable, fallback-able) and the entry is deleted so the next attempt really rebuilds; the timeout must also **really abort** the underlying model load through the provider's own `AbortController`, or a retry starts another while the hung one keeps running, piling up in one tab. **A finished language-pack download has to notify sessions in progress**: a page that started translating before the download has degraded `chrome-builtin` permanently (`no-key`), and unless revoked the page keeps taking the online fallback until restored and reopened; after a successful download the popup sends `axt:engine-ready` to the current page, content calls `FallbackService.reset()` to revoke the degradation record, and the blocks after that return to the offline engine (Codex on #50). **Sessions are cached per language pair** (after KISS `builtinAI.js`'s `#translatorMap`): even with the model ready, `create()` takes about 8.6 s of local loading, and a new session per batch would stretch a 10 ms translation to seconds; when `create` fails the entry is deleted for a retry. Error classification: `NotAllowedError` / `NotSupportedError` → `no-key` (what is missing is a gesture or support for the language pair, retrying is useless, let the chain degrade it permanently), `AbortError` → `aborted`, the rest → `unknown`. Translations are normalised for the surplus spaces after CJK punctuation as measured in §6.2
- **Out of e2e's reach**: in headless Chromium the language pack is `downloadable`, and the download needs a user gesture and about a minute, unsuitable for regression. Unit tests cover every branch with an injected fake `Translator`, the real path is verified by hand; `pnpm e2e` only guarantees the chain's behaviour is unchanged when the built-in engine is unavailable
- Translations need the surplus space after a full stop normalised (“。 ” → “。”)
- The content script's isolated world exposes `Translator` too (measured 2026-09-05, Chrome 153, RESEARCH §6.3): `'Translator' in self` is true, `availability()` agrees with the main world, and it can be called directly on the content side

### 8.5 The engine fallback chain [decided, 2026-09-05]

Hard rule 4 demands that “a failure must be recoverable and trigger the fallback chain, and must never take the extension down”. Before this, an expired key, an exhausted quota or a network hiccup made `run.ts` hit `no-key` / `auth` and `scheduler.disconnect()`, the whole page's translation dead in its tracks and the reader staring at half a translation.

- **Services are added by the reader, and engines are claimed by service id** [decided, 2026-09-10]: each item of `config.services[]` is “name + endpoint address + API key + model”; when `getProvider` sees `provider` is a service id it builds an OpenAI-compatible engine from that configuration and **uses the service id as the engine id** — the fallback chain, status reporting and cache key therefore need no special case, and `serviceName(id, services)` turns the id into the name the reader gave. When the chosen service is deleted it falls to the built-in free services, and the popup notes it as usual. Vendor templates (preset addresses and models for OpenRouter / DeepSeek and so on) are not done; three fields are enough for the reader to fill in
- **The chain's shape**: the engine chosen in the configuration first, followed by the free engines not duplicating it, in the order `chrome-builtin` → `google-web` (the built-in is offline, 10–20 ms a sentence and not rate-limited, so it comes first; without the language pack its `isAvailable()` is false and it is skipped automatically). Assembled in `buildChain` of `providers/index.ts`, with two filters: those whose `isAvailable()` is false are dropped (so no link doomed to fail lies in the chain), but **the first engine is kept when unavailable** — the popup needs it to say “未配置 API key” rather than quietly switching to a free engine
- **A session is bound to the chain it started on, and a new session may replace it in place** [decided 2026-09-10, ui/phase-1]. A run never switches service or language mid-way (Codex on #59). What changed: `axt:translate-page { restart }` starts a new session over a running one without showing the original first; `renderPending` already removes a block's previous translation when it is requested again, so the page follows the new settings paragraph by paragraph, cached ones at once. The popup uses this for every service / language / prompt change while the page is on. The same path runs when the chain hands over **permanently** (`no-key` / `auth`): the run reports the serving service (`onProvider`), the content script asks the background why, and restarts the page on the service that took over, so a reader gets one service for the whole page instead of a mix. Temporary hand-overs keep going, they come back on their own
- **Not inside `translate-service`** [decided]: that is already the closure of “one provider, one set of queues + cache + batching”, its cache key carrying `providerId | model | promptKey`, so different engines' translations are stored apart by nature. The chain is a thin layer outside, `providers/fallback.ts` (about 110 lines): every step is a complete service, and the chain only hands **the same call** to the next step on failure. Stuffed inside the service it would couple the queue, batching and cache with engine selection
- **Two degradation durations**: `no-key` / `auth` are configuration problems that do not heal by themselves, degraded permanently for the session; `network` / `timeout` / `rate-limit` / `invalid-response` / `unknown` are transient, the degradation recovering by itself after a 60s cool-down, and a success of that engine clears its record at once. The queue's own retries (retry-policy) run out before the chain is reached, so the chain does not stack retries; the cool-down avoids every call waiting out the longest 120s batch timeout for nothing during a sustained outage. `aborted` never degrades and is never recorded — a session cancellation is not the engine's fault, and redoing it on another engine would only be cancelled once more
- **When everything is degraded, fall back to the last step**: better to fail once more and report the error truthfully to `run.ts` (which stops and draws the failure widget by it) than to reach a state of “no engine available”
- **The capability invariant**: the render path decides the shape of a block, and `run.ts` takes `capabilities` only once at the start; switching paths midway gives blocks rendered earlier and later two shapes. Therefore **one session can have one wire format only**. **The format is decided by the preferred engine** — the first in its `wireFormats` preference order; a candidate that cannot support that format stays out of the chain with a warning. This rule is **order-independent**
  - Google chosen (`['tags','markers']`) → `tags` locked → the built-in (`['tags']`) joins; markers-only candidates stay out
  - Microsoft chosen (`['markers']`) → `markers` locked → Google keeps both and joins as the fallback
  - The preferred engine with `wireFormats: []` (none of the placeholders survive) → the whole session takes `runs`; runs sends plain-text segments and needs no common format, so the format gate steps aside entirely, or the preferred engine failing would leave nothing to fall back to
  - A boolean cannot express “both work” and would force “no fallback once Microsoft is chosen” — the reason #104 replaced it with a set
  - **The rule used to be “the intersection shrinks in iteration order”** [withdrawn, 2026-09-09, a prerequisite of #103]: it let **a fallback engine change the preferred engine's rendering format** — with Google chosen and the built-in lacking its language pack, a markers-only fallback dragged the whole session to `markers`, paired placeholders flattened and the whole page's inline styling gone, when all the user wanted was a fallback. #103 opens the chain order to customisation, and that rule would turn “adjust the fallback priority a little” into “silently change the rendering format”. The two rules produce exactly the same chains today (a markers engine could never have rescued a tags session anyway), so this trades order-dependent for order-independent; it is no behaviour change
- **Visibility**: the `engine` of `axt:provider-status` carries the engine actually in use and the reason for the degradation (since 2026-09-06 the chain lives in the background and no longer hangs on `PageStatus`); the popup polls it along with the progress while translation runs, shows a note on degradation stating that a free engine's terminology is less accurate than an LLM's (§8.1's "weights → 重量") and that “once the settings are fixed, restore the original and translate again to switch back”. The degradation also logs one `console.warn`, which e2e and user troubleshooting rely on
- **Once the user fixes the configuration the chain has to return to the preferred engine**: when the popup finishes downloading a language pack it sends `axt:engine-ready`, and the background **rebuilds the whole chain**. That is more thorough than “revoke the degradation record” — an engine whose `isAvailable()` was false when the chain was built and never joined cannot be rescued by revoking a record, and with the chain resident that case is in fact more common (the chain may have been built long before the user downloaded the pack). Hence `FallbackService` has no `reset()`
- **The switch**: configuration v5's `fallback.enabled`, on by default; off, the chain holds the configured engine alone, and the behaviour is exactly as before the implementation. Two e2e assertions guard the two behaviours

> Added 2026-09-13: the code cites a **§8.6** — sentence alignment: boundaries reported by the engine or sentence markers inserted by the service on the `tags` path, the `alignment` field of a translated segment, and why `CACHE_KEY_VERSION` went 5 → 6 — that this document never received. The design lives in `providers/alignment.ts`, `providers/sentence-markers.ts`, `providers/translate-service.ts` and `cache/key.ts`; §7.7 uses it; an ADR is to write it up.

## 9. Cache and configuration

- Translation cache: IndexedDB, **Dexie**, ported from FluentRead `services/translation/cache.ts` (key normalisation, TTL, capacity cap, in-memory hot layer), crypto-js swapped for Web Crypto SHA-256 (revised in v0.4; idb-keyval was planned originally)
- The cache key: `sha256(CACHE_KEY_VERSION | providerId | model | PROMPT_VERSION | promptKey | context | RULES_VERSION | target | renderPath | normalizedText | cuts)` (corrected 2026-09-13 to the identity `cache/key.ts` builds: `promptKey` and the context entered with §8.2's prompt library and glossary, `cuts` with the sentence markers of #137; it read the seven-part key of 2026-09-05); `renderPath` takes the three values `tags` / `markers` / `runs`, **the same names as `WireFormat`** (#108: it was once called `tags` under two sets of names for one thing, converted back and forth by a mapping function, and the type system could not catch a new call site with one wrong literal) — the same source text without placeholders has the same wire text on all three paths, and only this field tells the three apart; the batch key uses the same field, so segments of the two formats are not batched together (`CACHE_KEY_VERSION` rose to 3 for it, to 4 on the rename — the key stores that very string — then to 5 when serialisation began collapsing whitespace (#119) and to 6 when the sentence markers changed the request sent (#137); it is 6 today, corrected 2026-09-13); **`providerId` is `provider.cacheId ?? provider.id`** [decided, 2026-09-05, issue #45]: the id `openai-compat` is the same for every OpenAI-compatible endpoint, and with id + model name alone a model of that name on OpenRouter and on a local Ollama would share cache entries and contaminate each other's translations. The provider declares its own identity (`openai-compat:<origin><path>`, **the path included**: different paths under one domain may be different gateway routes to different back ends, and origin alone would let two routes share entries; the trailing slash normalised), **never with the API key** (hard rule 7); `normalizedText` = NFC normalisation + runs of whitespace collapsed to one space + trimmed at both ends, the placeholder text taking part in the hash
- The value: `{ text: string; ts: number; paper: string }`, `paper` being the arXiv id, for per-paper cleanup and export. TTL 30 days, caps of 20,000 entries / 50 MB, 256 KB per entry, an in-memory hot layer of 256 entries; the cache is held by the background alone and read and written directly (IndexedDB is isolated per extension origin and shared across papers); the translation requests themselves are in the background too, so content never touches the cache, and every batch saves two message round trips (§8.0, 2026-09-06)
- **Cache management is a global clear on the settings page only** [decided, 2026-09-05]: `axt:cache-stats` shows the count and size, `axt:cache-clear` (without a paper) empties the whole store, and the statistics are re-read on returning to the settings page (translation happens in other tabs, and unread they would forever show the numbers of the moment the page opened). Both messages answer `{ ok: true, … } | { ok: false, message }`: **a failure must not be shown as “the cache is empty” or “0 deleted”**; with IndexedDB unusable that is the last place to lie (Codex on #52). Before counting, `cleanup()` runs once to remove the expired entries — `get()` only treats them as misses and never deletes them, and uncleaned the page would keep showing a pile of unusable entries and bytes; this is also `cleanup()`'s only call site at runtime, so its failure has to be thrown rather than swallowed, or the statistics would report the expired entries it could not remove as a successful result. **No “clear this paper only”**: the settings page is a standalone extension page with no notion of the current paper, and taking a detour to ask the content script for it is not worth it; the real case for per-paper clearing (this one translated badly, start over) sits more naturally in the popup, kept for later. The cache key carries the engine, model, prompt and glossary anyway, and changing any of them misses the old translation; a manual clear is a fallback, not a routine operation
- **Eviction does not scan the store** [decided]: the count and the byte total are maintained incrementally in memory (the `byteSize` index, Dexie schema v2; initialised by reading index keys only with `orderBy(index).keys()`, deserialising no record), and only when the cap is really exceeded are the oldest entries fetched in batches by `lastAccessedAt` and deleted. The original FluentRead read every record of the store and summed on every `set`; a paper is several hundred writes, and once the store reaches thousands of entries every write deserialises the whole store; MV3's service worker is single-threaded, and other messages queue behind it for tens of seconds (measured with fake-indexeddb: 5.5 ms/set at 2000 entries, growing linearly with the store; after the change a steady 0.11 ms/set)
- **A cache read has a waiting budget; unreadable, translation goes on** [decided, 2026-09-05, issue #45]: the service “waits for the cache before sending the request”, and one hung read stops the whole page's translation there — an MV3 service worker's cold start, suspension or a lost message all cause it. The gate sits at the service layer: a 2s `CACHE_READ_BUDGET_MS` catches any `CachePort` implementation. A timeout **or a returned count that does not match the request** is treated as all misses, at the cost of one extra request; 2s is far above the measured hit round trip (of the order of 36 ms). (Since 2026-09-06 the cache and translation are both in the background, and the content side's 1.5s message-port gate was deleted with `cache-port.ts`)
- **No cache writes after a cancellation** [decided, 2026-09-06, Codex on #33]: one call is split over several batches, the ones finishing first may have fulfilled before `cancel(scope)` withdrew the rest, and when `Promise.allSettled` wakes it writes them into the store all the same, contrary to the promise “after restoring the original nothing is rendered and nothing cached”. `cancelledScopes` is checked once more before writing
- **Bad translations do not enter the store, and a re-send does not read it** [decided, 2026-09-05; since 2026-09-06 derived from the request text]: `translate-service` writes only translations that passed the placeholder validation into the cache (Codex on #30). It used to rely on an `accept` callback passed by the caller, which is a function and cannot cross the message boundary; now the validation expectations are derived by `expectationsFromText(request text)` — `serialize` has already escaped the literal `<` `>` of the source (§6.1), so every `<x>` / `<t>` in the request text is necessarily a real placeholder, and one scan rebuilds `slots` and `paired`. Zero protocol growth, and this invariant moved right next to the cache write, so the runs path is protected too (before, it carried no `accept` and wrote everything). The single-block re-send after a placeholder validation failure carries `cache.bypass` and writes without reading — the old store may still hold bad entries written before the fix, and reading as usual would only hand them back and fall to the runs path every time (Codex on #9); a successful re-send overwrites
- Configuration: WXT storage, a zod schema with `version` and migration functions (the pattern of Read Frog's `config/storage.ts` + `migration.ts` ported). The v1 shape: `{ version, provider: 'openai-compat' | …, openaiCompat: { baseURL, apiKey, model }, targetLanguage: 'zh-CN', mode: 'stack' | 'side' | 'only' }` (the default `mode` has been `side` since 2026-09-11, §7.3); v2 adds `prompts`, v3 `preload`, v5 `fallback: { enabled }` (on by default, §8.5), v6 `glossary` (an empty table by default, §8.2), v7 `style` (default `none`, §7.5), v8 `image` (the image translation's mode gate, §15), v9 three tunable decoration parameters on `style` (`color` / `opacity` / `accent`), v11 `image.enabled` (the switch in the popup, the mode multi-select staying on the settings page), **v12 replaces `openaiCompat` with `services[]` (the services the reader added, `provider` becoming a built-in id or a service id, §8.5) and `style` with `appearance` (two configuration lists, §7.5)** — the migration is a full mapping, every v11 value landing somewhere, no configuration falling back to a default; **v13 adds `uiLanguage`** (the interface language, UI.md §6), and **v10 changed no field**: it exists so that an older build finding a stored `microsoft` reports the version instead of silently resetting the configuration (`config/storage.ts`; both corrected 2026-09-13 — the list stopped at v12); **v4 replaces `targetLanguage` with ISO 639-3 codes** (`cmn` / `cmn-Hant` / `jpn`…, the 179 codes of `config/languages.ts`, the same as Read Frog; the migration looks up by BCP-47: exact → the primary language subtag → fall back to `cmn`; an LLM gets the English name, google-web converts back to BCP-47). The API key is stored locally only and never appears in a cache key, a log or a test fixture

- **A configuration fallback must be visible to the user** [decided, 2026-09-06, met in measurement]: falling back to `DEFAULT_CONFIG` when `getConfig()` fails validation is right (the extension must not go down), but it used to log a single `console.warn` — the user's key is stored yet out of effect, translation quietly degrades to a free engine, and the interface gives no clue. It was triggered once for real: a v7 configuration stored in Chrome while a v6 build was loaded, WXT refusing the downgrade migration by design (`Version downgrade detected`), and the whole configuration, API key included, silently ignored. Now `getConfig()` records the reason for the fallback (the version newer than the extension / which field is invalid), `configFallbackReason()` serves the UI, and a warning at the top of the settings page says “key 与引擎选择都没有生效” (S-O-02; the popup's copy of it, S-P-34, was removed on 2026-09-10 — corrected 2026-09-13). The reason is kept per execution context — the popup calls `getConfig()` itself anyway, and what it reads is exactly the conclusion of its own call. The same principle as the glossary caps being tidied in the migration (§8.2), seen from both sides: what can be tidied is tidied in the migration, what cannot must be said out loud

## 10. Scheduling [decided, redone 2026-09-05: Read Frog's loading model ported, the owner's call; implemented in PR 2a: `scheduler/lazy.ts`, `renderer/pending.ts`, `scheduler/title.ts`, `startTranslation` in `pipeline/run.ts`]

**Translate what is seen**: only the blocks in the viewport and within a distance below it are translated; blocks not scrolled to send no request and take no resources. This is Read Frog's **only** mode of page translation (`PageTranslationManager`, with no “translate the whole paper” switch), and the approach is ported as it is; its modules are decoupled and its effect proven, so whatever can be ported whole is (see `feat/lazy-loading` in §12).

- When translation starts every block is only marked (`data-axt-id`, `pending`) and handed one by one to an `IntersectionObserver`, **with no request sent**. The block marks are written in one go (§7.2, issue #67: slicing them let side prep run over half-marked pages; only the state attribute is still sliced — corrected 2026-09-13, it read “the marking is sliced”), and **before writing every block the session is checked to be still alive**: while the main thread is yielded the user may already have “restored the original”, and with the check outside the loop only, the loop would keep writing marks onto the DOM after `restore` cleaned up, leaving orphan `data-axt-*` on the page and breaking the invariant of §7.1 (experiment 1 of issue #45). The parameters follow the defaults of Read Frog's `pageTranslation.page.preload`: `rootMargin` **1000px**, `threshold` **0**; exposed on the settings page as steps — “半屏 … 三屏” for the distance and “刚露出 … 完全露出” for the threshold (UI.md S-O-50/51), mapped to `margin` / `threshold` inside (corrected 2026-09-13: they were the number fields “预翻译距离” 0–10000px / “可见阈值” 0–1, Read Frog's names, until 2026-09-10). The earlier 600px / 0.01 after FluentRead is withdrawn
- **Seeding and the observer use the same visibility threshold** [decided, 2026-09-06, Codex on #35]: the batch of anchors triggered synchronously at start used to judge by rectangle intersection only, ignoring `threshold`; a user who configured a threshold saw “a block just one pixel exposed translates at once”, while the same block entering the viewport a little later had to wait for the ratio — two inconsistent paths. Seeding now judges by “intersecting height ÷ element height ≥ threshold”, the same meaning as `IntersectionObserver`'s `intersectionRatio`. The default threshold is 0; the behaviour is unchanged
- A block sends its request only when it **first** enters the viewport plus margin, and is `unobserve`d at the same time — one-shot; a block outside the viewport is never requested. There is no background queue for “translate the whole paper”; to translate everything, raise the preload distance (Read Frog does the same)
- Blocks entering in the same IO callback **form one batch**: one scroll brings dozens of blocks in at once, cut into batches of 1000 characters / 4 items per §8.2 and sent, a table still one batch for the whole table; `planBatches` runs only over “the blocks that entered the viewport this time” and no longer plans the whole paper in advance. The IO's first callback is asynchronous, so at creation it still seeds once synchronously by `getBoundingClientRect`, and the first screen does not wait for the callback
- During the request a pending node with a skeleton is inserted beside the original block first (§7.6) and filled when the translation arrives; a failure swaps in the error hint and “重试”; a cancellation deletes it
- **Cancellation**: restoring the original or turning translation off withdraws the queued and in-flight requests by session id (the approach of Read Frog's `translation-session` + `cancelPageTranslationRequests`: the in-process `AbortController`s are aborted together, and the pending nodes are deleted with their rings); the result of a withdrawn request is neither rendered nor cached even if it returns
- Read Frog's `MutationObserver` (new content on dynamic pages) and giant-paragraph splitting (paragraphs taller than three screens observed by sub-paragraph) **are not ported**: arXiv pages are static, and no paragraph is taller than three screens; revisited when other sites are added
- The popup's progress semantics change accordingly: translation is a state that is “on”, not a task that ends. It shows “已翻 / 已进入视口 / 失败”, `total` for reference only; “翻译中” means requests are still in flight, with none in flight it is settled, and after scrolling it is “翻译中” again

The following is unchanged:

- **No scroll anchoring and no layout reads when inserting translations** [decided, 2026-09-05]: keeping the viewport from jumping is left to Chrome's native scroll anchoring (`overflow-anchor: auto` is the default; measured: inserting 600px above the viewport, the browser compensated 575px of scroll by itself, the anchor moving 0). The JS anchoring ported early from FluentRead (`elementFromPoint` + `getBoundingClientRect`) forced two full-page layouts per batch, 130–150ms each in side mode and 90–100ms in stack (15644 nodes, ~700 subgrid containers); over a hundred-odd batches from 8 workers, even 826 blocks all hitting the cache took 16.5s, with 52 main-thread long tasks of ~90ms end to end. Removed, translation is bound only by the network / cache round trips
- **Progress events use a coalescer with a maximum wait, not a pure debounce** [decided, 2026-09-05]: dozens of progress callbacks a second during translation kept resetting the 150ms debounce timer, and side prep did not run until the whole paper was translated (measured: 413 mirrors appeared together at the last moment, the formulas centred across both columns until then). `createCoalescer(fn, { delay: 150, maxWait: 1000 })`: however dense the events, it tidies at least once a second. **Since 2026-09-07 the coalescer collects a dirty set** (issue #46): `schedule(item)` adds the item to the current round, a bare `schedule()` means full, and when it runs it hands the deduplicated items (or null) to the callback — the tidy layer thus knows which blocks this pass should touch, without rescanning the whole paper every pass
- **Mirrors do not wait for translations** [decided, 2026-09-05]: formulas and figures have no translation to begin with, and waiting for their paragraph's translation before mirroring is waiting for nothing. The block marks (`data-axt-id`) are written at the very first moment translation starts, the mirror's container check became `:has(.axt-t, [data-axt-id])`, and the first prep pass mirrors them all; gate 2 (a block mark or blocks inside means no mirror) is unchanged, so the whole-block copy accident cannot recur. **And precisely because the decision looks only at the block marks, the mirror runs once per session** (2026-09-07, issue #46): an arriving translation changes no mirror decision, every scan after the first is wasted (measured on 2312.17141: 840 ms in all), and `prep.ts` runs it with one flag on the first full pass only
- **A concurrency cap and a total time limit** [decided, 2026-09-05, issue #43]: the token bucket controls **rate** only, not concurrency — when responses slow down the tokens refill and dispatch at the rate as usual, and the in-flight count is bounded only by the number of queued tasks (measured: under `rate=1 / capacity=1` three never-completing requests were all in flight at once). A 220-block paper piles up 50-odd batches, and all of them fired at one endpoint at once invite a 429 and hit the browser's connection cap. Two options were added to the ported queue: `maxConcurrent` (the service default **8**, the same as the rate; with responses under a second this gate never triggers) and `maxTotalMs` (the total limit for one task from enqueue to final failure, the service default **180 seconds**). Both defaults live in `translate-service`; the queue itself sets none, so the ported behaviour is unchanged.

  The actual number of `provider.translate` calls measured under four kinds of failure (2 queue retries, 3 batch retries):

  | Failure kind | Calls | Time | Outcome |
  |---|---|---|---|
  | network | 3 | 9 ms | failed |
  | auth | 2 | 3 ms | failed (the whole queue drained) |
  | invalid-response | 6 | 7.0 s | failed |
  | rate-limit | 4 | **> 60 s, not finished** | not finished |

  The number of attempts was bounded already (`MAX_CONSECUTIVE_RATE_LIMIT_PAUSES = 5` catches the 429s); what was missing was a **total limit**: every rate-limit pause may be long, and the caller needs a definite answer to “after how long may this batch be considered untranslatable”. Failing the batch at the deadline and leaving the retry to the user beats hanging indefinitely
- One pair of queues per provider (`translate-service`, since 2026-09-05 the whole directory of Read Frog's `utils/request/` ported): `request-queue` (a token bucket, by default 8 requests/second, burst 20; a provider overrides with `rateLimit`) + `batch-queue` (1000 characters / 4 items / 100ms of batching, a dispatch gate that batches more and sends less during rate limiting; every provider batches — corrected 2026-09-13, it read “only LLMs batch”) + `priority-queue` + `cancellation`, the tests ported with them; `p-queue` and the hand-written pause / probe of #30 are deleted. The batch key = provider, model, prompt, target language, render path, context (the section title included, so batches do not mix across sections); when a provider reports “the ids do not match” it is handled as a batch error: the whole batch retried 3 times, then item by item as the fallback, and request-queue does not retry on its own. Cancellation is by scope: one id per run, and restoring the original withdraws batch-queue first, then request-queue (the order of its translation-queues.ts); in-flight fetches are aborted, and a result that comes back is neither rendered nor cached
- The “重试” button of a failed block sits in the error hint (§7.6); the popup no longer lists failed blocks separately

## 15. Image translation [decided, in scope since 2026-09-07]

The goal is the same as Safari's built-in image translation: the text in the image is recognised, and the translation is overlaid as labels in place, with no other feature added. **Scope**: bitmaps `img.ltx_graphics` and externally referenced SVG figures `object.ltx_graphics[type="image/svg+xml"]` (§15.5), **inline `svg.ltx_picture` (TikZ) still skipped**; bitmap recognition on Mac only (Vision OCR), the non-Mac fallback path deferred, **SVG figures need no helper**; **no entry point for a single image** — once the user clicks translate for the whole page, bitmaps go through the same lazy-loading schedule as text blocks (translate what is seen, §10) and are cancelled with the session; one settings item “in which modes to translate images” (side / stack / only multi-select, all three on by default), gated by the mode in effect — switching to a mode not selected only hides the overlays, switching back shows them again, switching to a selected mode with images not yet translated schedules them, consistent with “switching modes sends no new requests”. When the helper is not detected (`ping` fails) only **bitmaps** go untranslated, SVG figures as usual — the settings item is no longer greyed out as a whole (§15.5).

### 15.1 Judgements

- Safari's image translation = Live Text (the Vision framework's OCR) + the Translation framework, both callable by third parties
- **The helper does OCR only; translation and the overlay stay in the extension**. Reasons: on macOS 15 Apple's Translation framework yields a session only through SwiftUI's `.translationTask`, and only macOS 26 has the UI-less `TranslationSession(installedSource:target:)`, which also requires the language pack installed; the extension already has a complete translation pipeline, and an LLM can take the caption as context. The thinner the helper, the smaller the platform-specific surface
- Non-Mac platforms degrade to a multimodal LLM reading the image directly for text and coordinates (lower coordinate precision, acceptable)
- **SVG has two populations, and only one should be skipped.** Inline `svg.ltx_picture` is TikZ output (164 across 10 fixtures, mostly drawn formulas), measured in Phase 0 to have no `<text>` and little `foreignObject` text; skipped by the text pipeline (§5.2, RESEARCH.md §2.9) — and, since 2026-09-11, read by the image pipeline for the labels the wider corpus turned out to hold (§15.6, 199 labels with words; corrected 2026-09-13). **The externally referenced `<object type="image/svg+xml">` is another matter**: 880 of 1792 figures in the sample (49.1%), the text drawn as glyph `<use>`s carrying `data-text`, readable exactly with no OCR, going through §15.5
- **Translation goes through the existing pipeline, not Safari's line-by-line, context-free way**. In the comparison sample the user gave (Safari translating the same physics diagram) "Dressed sites" became “打扮的网站”, "Even sites" became “甚至网站”, "String Extension" became “特林扩展名”, and a lone **B** in the figure was boxed as “字母b” — each line sent alone, with no caption or section, gives exactly that. We send each figure's lines together with the caption and the section as context in one batch to the existing provider; single letters, bare numbers and identifiers are skipped by the existing keep rules of §6
- **The overlay looks like Safari's**: a white, rounded, semi-transparent box covers the original text, the translation's font size follows the box height, vertically adjacent lines with aligned left edges merge into one box ("Pair / Production" two lines one box); hover shows the original. The background is a fixed semi-transparent white first, with sampling added once a dark-background figure is met in measurement (the idea of ImageTrans's `detectBackgroundColor`)
- **Use what exists**: the helper's core is ported from `bytefer/macos-vision-ocr` (MIT, single-file Swift, Vision revision 3, output per line text + normalised four corners + confidence, already the shape §15.3 wants), needing only the Native Messaging stdio frames around it; the overlay ports the DOM rendering part of `xulihang/ImageTrans_chrome_extension` (GPL-3.0) `getImage.js` (font-size fitting `fitBoxFontSize`, background sampling `detectBackgroundColor`, line wrapping, rounded boxes) and its viewport scheduling idea. [Correction 2026-09-12: this was the plan, not what was built. The overlay (`renderer/image.ts`, `image/boxes.ts`, cca11dc) was written from scratch — percentage geometry, closed-form container-query font sizes, CSS anchor positioning, no measurement, no background sampling; nothing from `getImage.js` was ported, so no attribution applies. Compared function by function against the `reference/` snapshot ef11ca7.]**Its way of replacing the `<img>` src is not ported** — it breaks §7.1

### 15.2 Architecture

```
content script                       background (service worker)          axt-helper (Swift, helper/)
  fetch <img> (same origin, HTTP cache)   axt:ocr {imageHash, image, scope}     Vision VNRecognizeTextRequest
  → SHA-256 → base64 ─────────────►   cache lookup by imageHash|helper version ──►  stdio length-prefixed JSON
                                       connectNative only on a miss       ◄── {lines:[{text, quad, conf}]}
  ◄── {lines} ──────────────────────  written back to the cache
  lines → boxes (adjacent lines merged, numbers / single letters filtered)
  → the existing axt:translate (plain-text path, the caption in the same batch)
  → an `.axt-img` sibling inserted after the <img>, labels positioned by normalised coordinates
```

- **Two cache layers**: the OCR result is stored in the same Dexie store by `imageHash | helper version` (recognition is deterministic, rerun only when the helper's version changes); each line's **translation goes through the ordinary text cache** — the key **does not** carry the imageHash, the translation of "Dynamical charge" has nothing to do with which figure it is in, and is shared across figures
- The overlay obeys the §7.1 invariants: **sibling nodes only** (`.axt-img`, `data-axt-for` pointing at the image's id), never a wrapper around the `<img>` — a wrapper changes the original node's parent-child relations. **It carries no `.axt-t`, and the `<img>` no `data-axt-id`** [decided, 2026-09-07, found in the plan phase]: with them it would be laid into the right column by side's pairing grid instead of over the image, the `<img>` would be deleted from the copy as a “paired original” on a split, mirrors suppressed, all twenty style presets slapped on it, and margin alignment writing inline styles on it. It is the third kind of injected mark: `marks.ts`'s `isInjected` / `stripInjected`, `restore()` and `splitFigures`' “real translation” check all recognise it
- **Positioned with CSS anchor positioning** (Chrome ≥131, for `anchor-scope` — the install floor, `minimum_chrome_version` in `wxt.config.ts`; the built-in translation API needs 138+ and is feature-detected, so on 131–137 only that engine is absent — corrected 2026-09-13): `img:has(+ .axt-img)` declares the anchor name, `.axt-img` attaches to the image's box with `anchor()` / `anchor-size()`, the parent `position: relative; anchor-scope` limits the scope, `grid-column: auto` leaves the pairing grid. Zero JS geometry reads, zero ResizeObserver; the split copy has the same structure, so the anchor holds automatically. Label font sizes use container query units (`cqh` / `cqw`), computed from the box height and character count into one string written once, reading no layout — ImageTrans's JS bisection of the font size forces 12 layouts per box, not used
- **No DOM nodes for the waiting / failed states**: a pending overlay would be cloned into the copy by the split, and `stripIds` would strip its state attribute. The overlay is inserted on success only (Safari too shows it only once translated); a failure is recorded in the image run, the popup shows the count, and the retry button covers it. The visibility CSS looks only at structure and the `<html>` attributes (`data-axt-img-modes`), not at the overlay's own attributes
- In side mode the figure is split in two whole (§7.2): the overlay belongs to the “translation only” copy, and the original's is hidden by style (**side only** — stack shows the original, only shows the copy, and the overlay follows whichever shows); the split copy's rebuild signature counts the overlay in, or once the translations are complete the copy lacks it. Mirrors run once per session, before OCR, and would land between the `<img>` and the overlay: `mirror.ts`'s gate recognises `isInjected`, and inserting the overlay deletes the mirror right after it; when OCR arrives only after side → only, the overlay went into the hidden original and the copy's signature is stale, the non-side branch of tidying deletes the stale copy for the dirty root, and it is rebuilt on returning to side
- **A configuration-level error stops the schedule** (Codex on #89): when translation returns `auth` / `no-key` it stops on the first, as the text pipeline does (`fatal()`), and images entering the viewport afterwards fetch no bytes and are not recognised; the popup's “once the configuration is fixed, click translate” note applies just the same. Ordinary failures (network, the helper disconnecting) are recorded for that one image, and the retry button counts images in
- **A concurrency cap of 2** (Codex on #89): fetching bytes, base64 and the message payload all take memory, and the helper is sequential anyway; opening everything at once only hoards 6 MB images in memory
- **The caption is the nearest enclosing figure's own** (Codex on #89): in a multi-panel figure each panel has its own caption, and taking the first `figcaption` from the outermost would give (a)'s caption to (b), both polluting the prompt and entering the wrong cache key
- **A new session first removes the previous round's mode gate** (Codex on #89): reopening after a fatal error without restoring the original leaves the previous round's overlays in place — the helper gone, image translation turned off, the target language changed, none of the old ones should still show; the new round replaces them as it reaches each image
- **Old overlays are cleared even with no labels** (Codex on #89): after a target-language change the translations may all equal the originals, and then the previous round's overlays have to be removed; an animation (the helper reporting `frames > 1`) is handled as “done, no overlay” likewise
- **The 6 MB cap is enforced while reading the response** (Codex on #89): Content-Length first, then a streaming read cancelled at once when exceeded; `arrayBuffer()` would allocate the whole response first
- **Browsers without anchor positioning**: the `.axt-img { display: none }` baseline is written outside `@supports`, so the overlay does not drop to a paragraph of text under the image (`wxt.config.ts` declares `minimum_chrome_version: '131'` since Codex on #99 — corrected 2026-09-13, it read “states no minimum Chrome version”; the baseline still guards a build without the feature)
- **Images inside blocks are not translated**: the target = `img.ltx_graphics` inside no translation block (the same criterion as the split's “loose media”). An image inside a block is cloned into the translation with the placeholder, and in only mode the whole original block is hidden, so the overlay has nowhere to hang; the 16 bitmaps of 12 fixtures are all inside a figure / flex cell, none inside a block
- **Cancellation**: `axt:ocr` carries the session `scope`; the helper client tells queued from in flight (in flight capped at 1, the helper being sequential anyway, so a withdrawal really withdraws work), withdrawing a scope rejects the queued ones and discards the in-flight one on arrival; `axt:cancel-scope` and a tab closing both call it through the `onDrop` hook of sessions. DOM safety is still guaranteed by the content side re-checking the session id after every `await` (the same pattern as the text pipeline)
- The helper lives in this repository's `helper/` (a Swift Package, no third-party dependencies) and evolves in the same PRs as the extension; split into a repository of its own when distribution is done

### 15.3 Message protocol (Native Messaging)

Request (extension → helper):
```json
{ "v": 1, "cmd": "ocr", "id": "req-1", "image": "<base64 png/jpeg>", "langs": ["en"] }
```
Response (helper → extension):
```json
{ "v": 1, "id": "req-1", "width": 1200, "height": 800,
  "lines": [ { "text": "Accuracy (%)", "quad": [[0.12, 0.05], [0.32, 0.05], [0.32, 0.08], [0.12, 0.08]], "conf": 0.98 } ] }
```
- `quad` is the normalised four corners `[top-left, top-right, bottom-right, bottom-left]`, origin top-left (Vision gives a bottom-left origin; the helper flips y). Four corners rather than `[x, y, w, h]`: a rotated axis label's corners are not axis-aligned, and the extension side decides whether to draw by the axis-aligned bounding box or by the angle
- Also `{ "cmd": "ping" }` → `{ "ok": true, "version": "..." }` for capability detection
- Size limit: helper → extension at most 1 MB per message (Chrome's hard cap; over it the whole connection is cut and everything queued is lost). When the helper's serialisation exceeds 250 KB (aligned with the cache's per-entry cap of 256 KiB, or a large result is recognised again every time) it drops lines by ascending confidence until it fits and the response carries `truncated: true`, passed through by the extension as it is; an ordinary image is a few KB, only an extremely text-dense one hits this, the smoke test cannot make such an image, and this item is guarded by reading the code. Extension → helper may be large (the image direction happens to suit)
- The handshake response must carry a non-empty `version`: it enters the OCR cache key, and a helper reporting no version does not count as available (the settings page shows “请重新安装 helper”). Version = program version + the revision of Vision's recognition model (`0.1.0+vision3`): when a system upgrade swaps the model the results change, and the old cache has to expire of itself
- The frame's length prefix has to be read in full, 4 bytes: the pipe may short-read, and treating that as EOF would void every queued recognition
- The response carries `frames` (`CGImageSourceGetCount`): the helper recognises frame 0 only, an animation's (GIF / APNG / animated WebP) boxes do not match the later frames, and the extension overlays no translation on an image with `frames > 1`, handling it as done
- Errors: `{ "v":1, "id":"...", "error": { "code": "...", "message": "..." } }`

### 15.4 helper

- Swift, ~100–200 lines: read length-prefixed JSON from stdin, decode the image, run Vision, write stdout
- The host manifest's user-level directory is **`<user data directory>/NativeMessagingHosts/<name>.json`** (measured 2026-09-07: not a fixed `Google/Chrome/…`, that is only where the default user data directory happens to be; Dia's is `Dia/User Data/NativeMessagingHosts`). The install script writes the default directories of Chrome and Chromium; Playwright points `--user-data-dir` at a temporary profile, so e2e has to copy the manifest into `<profile>/NativeMessagingHosts/`, and in the system-level `Google/Chrome` directory Chrome for Testing does not find it either. `allowed_origins` binds the extension id. **No `key` pinned** [decided, 2026-09-07]: pinned, the id changes and every locally stored configuration is lost; an unpacked extension's id derives from its path and is stable on one machine, and Playwright loading from the same path `.output/chrome-mv3` gets the same id. The install script takes the id as an argument; distribution is discussed later
- **Distribution deferred** [decided, 2026-09-07]: the first stage is a developer install only — `swift build` + a registration script, validating the value on the author's Mac; signing, notarisation, pkg / Homebrew are planned then. The extension probes at start-up, and undetected it shows the install guide in the popup and on the settings page (UI.md S-P-86, S-O-27; §15 above) — corrected 2026-09-13, it read “the settings item is greyed out and image translation silently does not run”
- **`nativeMessaging` a required permission for now** [decided, 2026-09-07, Codex on #87 suggested optional]: a required permission makes store installs / updates show the “communicate with cooperating native applications” warning, visible to non-Mac users too, and an update adding a permission may disable installed extensions until the user accepts. All of that happens only at **distribution**; an unpacked load has no such step; when distribution is planned it changes to `optional_permissions` + a grant button on the settings page together with signing / pkg (`permissions.request` needs a user gesture, and the save button is one), with e2e copying the build output like local-endpoint and adding the permission to the copy's manifest — Playwright cannot click the native permission prompt **[corrected 2026-09-13]** The rebuild changed it to an optional permission (ADR-0002): requested from the “允许” button in the popup / settings page; a running worker cannot get the newly granted API, and an alarm wakes a new worker to take over.
- **The protocol version**: a request carries `v`, and a helper that does not recognise it answers `unsupported-protocol`; the extension checks the response's `v` at the handshake, and a mismatch is handled as a failed handshake (queued work rejected, the port closed), the settings page showing “请重新安装 helper”. The extension and the helper are installed separately, and the versions will drift apart
- **The first OCR's timeout**: the first recognition in this worker gets 120 s (the machine's first Vision run does a one-time model preparation, measured 26.6 s, and 30 s would take a healthy helper for hung), 30 s after one success
- **The install guide runs its course in the popup, and once installed the extension recognises it by itself** [decided, 2026-09-12, the owner's call, issue #102]: the guide used to be on the settings page only; the reader had to go there themselves and click “我已经装好了” after installing. Now the popup and the settings page **share one component** (`src/ui/HelperSetup.tsx`), and the flow is down to two steps — open a terminal, run the command — **with no third step**.
  - **“我已经装好了” is gone**: the last thing the install script writes is the native host manifest on disk, and Chrome reads it only at the moment of `connectNative`, **with no reload of the extension needed**. So the question “is it installed” is one the program can answer itself and should not ask the reader — who, when pressing it, is most likely still in the terminal, the popup long since unfocused and destroyed. Copying the command sends an `axt:helper-await`, the background probes every 2 seconds for at most 3 minutes, and on detection takes the existing `axt:helper-ready` broadcast: the open papers let their waiting bitmaps out to translate by themselves, and what the reader sees is the figures beginning to show translations, not a button waiting to be clicked.
  - **The waiting state lives in the background, not in the component**: the popup is destroyed the moment it loses focus, and state in the component is as good as none. The deadline is written into **session** storage (once the browser is closed this install need not be waited for), and a worker woken after reclaim picks up the unexpired wait with `resume()`. `axt:helper-await` is one message with two uses: with `start` it is “start waiting”, without it “still waiting?” — a reopened popup reconnects to the same wait by the latter.
  - **The round is scheduled before the probe**: with `arm()` after `await probe()`, one hung probe would stall the wait silently (no timer left, nobody checks at the deadline). Scheduling the next round first makes the rhythm independent of how fast a probe is; `probing` blocks overlapping probes at the same time.
  - **No separate small window**: opening a small window with `windows.create` that does not close on losing focus, so the reader still sees the instructions after switching to the terminal, was considered earlier. With automatic detection that reason no longer holds — the command has been copied away, and there is nothing left to look back at.
  - **No downloadable `.command` to double-click**: a script downloaded from the network triggers Gatekeeper quarantine, a worse experience than `curl | bash`.
  - **A failure does not block**: when nothing is detected within 3 minutes only one line of hint is added in place, the command block stays visible and can be copied again; no dialog, no interception, no greying out of image translation as a whole — only the bitmap path is affected.
  - No separate MV3 keep-alive is needed: the probe itself is an extension API call (`connectNative`), and a round every 2 seconds is far below the 30-second idle line.
- Afterword: with the helper in place an `apple-translate` provider (`wireFormats: []`, Mac only, offline) can be added along the way; on macOS 15 it needs the workaround of hosting SwiftUI in a transparent window (see the SystemTranslation library), on macOS 26 it can be initialised directly

### 15.5 SVG figures: the text is read out, not recognised [decided, implemented 2026-09-09, issue #121]

Externally referenced figures (`<object type="image/svg+xml">`, 880 of the 1792 figures in the sample, 49.1%; 99 of 178 papers have at least one) have no `<text>`: every character is an outline, drawn by a `<use>` pointing into `<defs>`. But **every `<use>` carries `data-text` saying which character it draws**, so the text is **read** rather than recognised, with zero error. Measured over 316 distinct files and 58045 `<use>`, glyph coverage 100% (RESEARCH.md §6.11).

- **Read only, never write.** The overlay is built in the **main document**; `contentDocument` is read, not changed. The premise is measured: the figure's `viewBox` maps linearly onto the `<object>` element's box (normalised coordinates agree to four decimals). So neither the DOM invariant of §7.1 nor `restore()` changes by a word, and the question of “restore semantics for a second document” does not exist
- **One pipeline shared with bitmaps**: `src/core/svg/glyphs.ts` produces `OcrLine[]` — the same shape the OCR helper returns — and everything after (`linesToBoxes`, the translation request, the cache key, viewport scheduling, progress reporting) is shared; `process()` branches by `ImageTarget.kind` only at the very start
- **Segmentation by geometry**: `transform="matrix(a,b,c,d,e,f)"` is decomposed into the angle `atan2(b,a)` and the font size `hypot(a,b)` (**`a` must not be taken for the font size**), projected along the baseline, and a gap over 1.5 font sizes cuts a segment. Spaces are glyphs themselves, so the text of a segment in document order is the exact original
- **The decomposition reads one matrix only, so a glyph must have no transform above it — and measured, none has**: of all 276 fetchable files and 54344 glyphs, **not one glyph has an ancestor with `transform`**. **The reason is not that the tree is flat** (the earlier sentence “the converter does no grouping” was inferred from one flat 159-glyph figure and is withdrawn: **21.1%, 11467 glyphs, are not direct children of the root**, nested up to 4 deep), but that no container carries a transform. `glyphsOf` **enforces** this rather than assuming it: a glyph with a transformed ancestor is skipped outright; such a figure is better left untranslated than drawn with half a transform
- **Every segment is drawn, along its own axis** [revised, 2026-09-11, the owner's feedback]: of the 58028 glyphs in the whole sample 90.279% are horizontal, 8.455% at -90°, 0.107% at +90°, and **1.160% (673) spread over 42 other angles**, most often -30°. v1 drew only multiples of 90° and dropped the rest whole, because the overlay described a label by “axis-aligned bounding box + angle”, and that box coincides with the text only at multiples of 90°. On 2609.10326v1 the cost became two concrete annotations: `reheating` (6°) and `radiation domination` (5°) — the only two explanatory texts in the whole figure, while the 0° `inflation` in the same figure was translated (the owner's feedback of 2026-09-11). **Now a segment carries its own box**: `len` (the length along the baseline) and `thick` (the thickness), both normalised by the figure's **width**, and the overlay places the label at the segment's centre and turns it with `translate(-50%,-50%) rotate(θ)`. Both axes use `cqw` — a length unit (1% of the figure width), the same real length in any direction; written as `width: X%` it is “percent of the container's width”, wrong vertically when the container is not square (exactly the problem v1's `cqw`/`cqh` swapping worked around; on a single axis 90° and 5° are one formula). **Horizontal still has to be exactly zero**: every downstream asks only whether `angle` is truthy (`linesToBoxes` does not merge lines with an angle), so a residual within 1.8° is zeroed, and the 17 lines in the corpus that are nearly but not exactly horizontal still go as horizontal and can still merge with the line before. 180° is drawn too: the result is upside-down text, matching the figure
- **A vertical label's size cannot use percentages**: turned 90° about its centre, the box's width is the vertical length on screen, while `width: X%` is a percentage of the container's **width**. `cqh` / `cqw` are used for the axis the text really extends along
- **Code is not translated**: §5 skips `<pre>` and code blocks, and a code listing in a figure is the same kind of content. But §5's selectors are HTML and cannot reach a run of flat `<use>`s inside an SVG, so this path recognises it itself (`src/core/svg/runs.ts`), the criteria set from the passages in real figures
- **Known gap**: 10.1% of the figures (32 of 316) draw text not with `<use>` but with the outlines written straight into `<path>`, and cannot be read — **“no OCR needed” holds only for figures that draw text with `<use>`**. All 32 rendered and classified: 11 really have no text, 10 have only mathematical symbols, 2 are logos, **9 carry real word labels** (legends, block-diagram module names, small-multiple axis titles). Those 9 v1 cannot translate, and they are exactly where the bitmap OCR path will be worth something in the future

### 15.6 Inline TikZ pictures: the labels are HTML, reading them is enough [decided, 2026-09-11, the owner's feedback]

LaTeXML draws a `tikzpicture` as an inline `<svg class="ltx_picture">` in the page, with each node's label inside a `<foreignObject>`, **as plain HTML**:

```html
<foreignObject width="140.33" height="13.84" transform="matrix(1 0 0 -1 0 10.38)">
  <span class="ltx_foreignobject_container"><span class="ltx_foreignobject_content">(a) Imbalanced routing</span></span>
</foreignObject>
```

So neither OCR nor a rebuild from glyphs like the external figures (§15.5): the text and its rectangle are both in the main document, two `getBoundingClientRect` calls suffice, and a figure scaled by `.ltx_transformed_inner`'s CSS `scale()` does not matter — the figure and the label are measured in the same screen coordinates, and the ratio is unchanged.

- **Phase 0's conclusion was right, but the corpus changed.** It measured this kind of figure as having “no translatable text” because the mathematics papers of 2023 drew formulas with TikZ, and formulas are `<math>`. Modern ML papers draw whole architecture diagrams with it: 12 fixtures plus 4 online papers have 170 inline figures and 954 `foreignObject`s, of which **199 carry real words**, 184 from one paper (2607.24653v2; the owner's feedback of 2026-09-11 that a whole figure was untranslated)
- **The text pipeline still skips these figures whole** (the rule `picture` unchanged): translated by block, a translation node would be inserted inside the `<svg>` and burst the canvas. They take the image pipeline, meeting bitmaps and external SVGs at `linesToBoxes`, sharing the cache key, viewport scheduling, the “图片翻译” switch and the mode gate; no helper needed
- **A pure-formula node sends not a word**: the criterion is “are two letters left once the formulas are removed” (`proseText`). What is removed is not only `<math>` — LaTeXML also marks identifiers typeset as text in math mode `.ltx_markedasmath`, and `visibleText` counts them as words all the same (Codex on #163). Measured: of 507 in-figure labels in the corpus exactly 1 is of this kind, the `initMT` of 2609.00246, which would pass the word test, be sent for translation and covered by a white box. Only **the word test** looks at `proseText`; when it is really sent, the whole line still goes (an identifier inside the words goes with the words, and the white box covers it too). The body-text path is unchanged — an `initMT` inside a sentence still goes with the sentence, and changing that is another matter (86 places in the corpus, touching `RULES_VERSION` and the whole site's cache). `softmax`, `argmax`, `exp` are words to a translation engine and symbols to a reader, and a white box reading “软最大” is worse than no translation. Conversely **a node of words plus symbols is sent whole** (`Block n−1`): the white box covers the whole node, and sending `Block` alone would cover the `n−1` blank
- **Adjacent lines are not merged**: the OCR and glyph paths give “lines”, and a wrapped label has to be joined back; here one line is one complete TikZ node, and merging would only glue the text of two boxes one above the other into one sentence (`Stable LatentMoE` and `Gated MLA`). A wrapped label carries its own `rows` (8.6% of the corpus wraps), and the font size is shared out by the row count
- **A node drawn twice at the same place counts once**: the architecture diagram of 2607.24653v2 has four `Stable LatentMoE`, two with exactly coinciding coordinates — undeduplicated, that is two identical white boxes stacked and one extra segment in the request
- **No geometry is read when collecting targets**: `collectImageTargets` has to ask every inline figure of the whole paper “does it hold words”, and reading a rectangle per figure means forcing a whole-page layout before translation starts. The criterion reads text only (`pictureTexts`)
- **`url(#…)` in the clone needs no renaming** (verified 2026-09-11, against Read Frog renaming the clone's ids in `sanitizeInlineAtomClone`): LaTeXML's TikZ figures clip with `<clipPath id="pgfcpN">` + `clip-path="url(#pgfcpN)"` (37 places in the inline figures of 2607.24653v2, 32 in 2608.29808), and `stripIds` removes every id from the clone. It looks like it would dangle, and in fact it does not: `url(#…)` resolves **at document level**, the clone's reference lands on the original's definition, and both share the same user coordinate system, so the clipping is identical; the original is valid as long as it stays in the document, and `restore()` deletes only our own nodes. Read Frog has to rename because their clone may not share the original's coordinate system (MathJax's font cache `<defs>`); we have no such case
