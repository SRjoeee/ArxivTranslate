### 2b. The fallback chain: what triggers it, who decides

- **The chain's composition** (`src/providers/index.ts:59-85` `buildChain`): the primary = `getProvider(config)` (`provider` is a service id → `createOpenAICompatProvider`; `'google-web'`; `'chrome-builtin'`; anything else (including the id of a deleted service) → `createMicrosoftProvider`). With `config.fallback.enabled`, `FREE_ENGINES = [chrome-builtin, google-web]` are considered in order: the one with the primary's id is skipped; one not supporting the primary's `wireFormats[0]` is skipped (`index.ts:72`); one whose `isAvailable()` is false is skipped (`index.ts:76`). An unavailable primary **stays at the head of the chain** (the popup needs that for its hint). `microsoft` is deliberately not in `FREE_ENGINES` (#98). `renderPath` = the primary's format; with a primary of `wireFormats: []` the whole session goes through `runs`.
- **Who decides the engine on each call**: `src/providers/fallback.ts:105-132`. `available()` (89) = the undemoted steps, falling back to the last step when all are demoted. A step returning `ok:false` with `error.kind ∈ FALLBACK_KINDS` (everything except `aborted`) → `demote()` (95): `no-key`/`auth` permanent (for this service's lifetime), the rest a 60 s cooldown (`DEFAULT_COOLDOWN_MS`); the record is cleared on that step's next success. The queue layer's retries (retry-policy) have already run by then; the chain stacks no further retries.
- **Session-level fatal stickiness**: `src/providers/translate-service.ts:168,334-342,475-477`: `no-key`/`auth` are recorded per scope in `fatal.scopes`, and later batches of the same session are refused on the spot in `executeBatch` without touching the endpoint again (#96 / #113).
- **Who decides “restart the whole page”**: on the content side `src/entrypoints/content/index.ts:230-249` `onProvider`: when the engine differs from the session's starting engine it asks `backend.status(session)` (through `axt:provider-status` with the scope → `router.transportFor(scope).status()`), and if the starting engine's kind in `demotions` is `no-key`/`auth` it restarts once with `start(undefined, true, session)` (once per session, the `restarted` gate).
- **When the chain is rebuilt**: (1) `background/index.ts:43-55` `watchConfig`: `load(next)` only on `chainConfigChanged` (one of `provider`/`services`/`prompts`/`targetLanguage`/`fallback` changed); bound sessions are not migrated; (2) `axt:engine-ready` (`index.ts:225-241`): `activate()` rebuilds unconditionally, `rebindAll` → `router.dropAndRebindAll` (withdraws the work on the old chain first, then migrates every session; used by `ServiceDrawer.remove`), `scope` → `router.rebind` (migrates that one only; used by the popup's language pack download), neither → rebuild only (used by the options language pack download and by ServiceDrawer's connection test after saving).
- **Status reporting**: `src/providers/transport.ts:130-165` `status()`: `available = primary.isAvailable()`; when unavailable it scans `chain.slice(1)` for the first available one as `fallback`; `engine` takes `service.status().activeId`, with `demoted` attached when it differs from `configuredId`; `demotions` in full; `revision` is this chain's build number.

### 2e. The recognition helper: the Native Messaging protocol, version negotiation, the install script contract

- **Host name**: `io.github.srjoeee.arxivtranslate` (`shared/ocr.ts:6`; `helper/install.sh:24`; `helper/install-remote.sh:13`; `tests/e2e/image.mjs:19`).
- **Frames**: a 4-byte native-endian length prefix + UTF-8 JSON (`main.swift:45-89`; the smoke script reads LE). The helper uses `readExactly` to read the prefix and the body in full (a short read is not EOF).
- **Requests** (extension → helper, `helper.ts:189,220,243`): `{ v: 1, cmd: 'ping' | 'ocr', id: '<cmd>-<seq>', image?: <base64>, langs?: string[] }`. `langs` is in the `HelperClient.ocr` signature, but `ocr.ts:60` never passes it, and the helper defaults to `["en-US"]`.
- **Responses** (helper → extension, `main.swift:142-167`): ping → `{ v:1, id, ok:true, version:'<VERSION>+vision<revision>' }`; ocr → `{ v:1, id, width, height, frames, lines:[{ text, quad:[[x,y]×4] (top-left origin, normalised), conf }], truncated?:true }`; error → `{ v:1, id, error:{ code:'bad-base64'|'undecodable-image'|'bad-request'|'unsupported-protocol'|'vision', message } }`.
- **Version negotiation**: on the helper side a request with `v !== 1` → `unsupported-protocol`; on the extension side the handshake reply must have `v === HELPER_PROTOCOL(1)` **and** a non-empty `version` (`helper.ts:159`), else `dropPort()` + `failAll('invalid-response')`; every new connection inserts an internal `ping` before any OCR (`helper.ts:187-190`); `version` enters `ocrCacheKey` (`cache/key.ts:112`, `OCR_KEY_VERSION = 1`).
- **Sizes and time limits**: a helper reply > 250 KB drops lines by confidence and sets `truncated` (Chrome's cap is 1 MB); 30 s per request, 120 s for this worker's first OCR, 30 s for the handshake; in-flight cap 1.
- **Error mapping** (`helper.ts:111-116`): `bad-request`/`bad-base64`/`undecodable-image` → `ProviderErrorKind 'bad-request'`, the rest → `'invalid-response'`; a disconnect → `'network'`; host not registered (`lastError` matching `/not found|forbidden|not registered|无法找到|找不到/i`) → `missing` remembered inside this worker.
- **The install script contract**:
  - Manifest paths: `~/Library/Application Support/Google/Chrome/NativeMessagingHosts/<host>.json` and `.../Chromium/NativeMessagingHosts/<host>.json` (both scripts write both; Chrome really looks in `<user data directory>/NativeMessagingHosts/`, and the Playwright profile is copied and its `allowed_origins` rewritten by the e2e itself).
  - Manifest shape: `{ name, description, path, type: 'stdio', allowed_origins: ['chrome-extension://<id>/', …] }`.
  - The extension id: `^[a-p]{32}$`; an unpacked extension's id derives from its load path (no pinned `key`).
  - `install.sh`: `cd helper && swift build -c release`; `path` = `<repo>/helper/.build/release/axt-helper`; `allowed_origins` = the argument list (**overwritten**); description “arXiv HTML Translator 的本机 OCR 助手（Vision）”.
  - `install-remote.sh`: `REPO=SRjoeee/ReadarXiv`, `REF=${2:-${AXT_HELPER_REF:-main}}`, downloads `https://codeload.github.com/$REPO/tar.gz/refs/heads/$REF`, takes the tarball's single top-level directory (the repository name not hard-coded, 3cf1852), copies `helper/{Sources,Package.swift,LICENSE-macos-vision-ocr.txt,Tests}` to `~/Library/Application Support/Readarxiv/helper`, `path` = that directory's `.build/release/axt-helper`; `allowed_origins` **unioned** with the existing ids (bd9e930); description “Readarxiv 的图片识别助手（Apple Vision）”; requires macOS + `xcode-select -p`.
  - The command copied from the popup is generated by `src/ui/HelperSetup.tsx` (`curl -fsSL https://raw.githubusercontent.com/SRjoeee/ReadarXiv/<ref>/helper/install-remote.sh | bash -s -- <extension-id> [<ref>]`); `--version` is used by both scripts to echo.
- **Manifest permission** (`wxt.config.ts:41`): `nativeMessaging` is a required permission (the DESIGN §15.4 decision, to become optional at distribution).

## 6. Not understood, or to be verified

1. **The key name of WXT storage's version metadata**: `configItem` uses `storage.defineItem('local:config', { version: 13, migrations })`. WXT stores the version number in a companion key (from memory a `{ v }` under `local:config$`); the implementation file of `defineItem` was not found in `node_modules` this time (the `@wxt-dev/storage` path missed). The “saved configuration” contract of §4 should count that companion key in too, and it has to be migrated if the rebuild stops using WXT storage.
2. **The `revision` misreport across a worker restart** (D1): deduced from the code, not reproduced. To verify: let the worker idle for over 30 s during a translation until it is reclaimed, then open the popup and see whether the “重新翻译” hint appears.
3. **The real purpose of the branch at `sessions.ts:126-128`** (D30): the reason the comment gives (tasks still in the queue after a worker restart) disagrees with the memory model; it may be meant for “a scope that never went through forCall” (for instance one that only did image OCR and never translated text), but in that case `bind()` has already recorded the binding. Needs the author's confirmation, or the intent read from the test “a scope never bound is withdrawn all the same”.
4. **`helper-await` relies on `setTimeout` 2 s polling + `connectNative` extending the life**: DESIGN §15.4 and the file header assert “the probe itself is an API call, 2 s is far below the 30 s idle line”, but once `missing` is remembered `status()` returns at once without calling `connectNative` (`helper.ts:228`) — only `recheck: true` clears `missing`, and `helperWaiter.probe` does pass `recheck` (`index.ts:131`), so every round really does `connectNative`. The logic holds, but no test guards “every round made the API call”; the path where the worker is reclaimed inside the 3 min window relies on `resume()` alone.
5. **The comment at `translate-service.ts:186-188` says a provider with `maxItemsPerBatch` of 1 degrades naturally**: no provider declares 1 today; the assertion is for the future, untested.
6. **The public API key constant at `google-web.ts:13`**: from Google Translate's web version; whether it still works can only be known by e2e / measurement; the endpoint's survival was not verified this time.
7. **The supported-language table at `microsoft.ts:36-42` is a snapshot taken 2026-09-08**: the endpoint's language table changes; no automated check.
8. **What `scripts/check-output.mjs` checks**: H11 assumed it might assert manifest fields; grep finds no `minimum_chrome_version`/`permissions`, so it should count as “no test”.
9. **`tests/entry/context-menu.test.ts`, `tests/renderer/direction.test.ts`** are outside this scope; B40 / C24 cite them as existing but were not checked case by case.
10. **`cache/store.ts:217` a hot-layer hit does `await db.entries.update` every time**: N hits in a batch = N database writes (`getMany` concurrent), a deliberate change at the port (047de1f); whether it is worth it (vs needing an accurate `lastAccessedAt` only at eviction) was never measured.
11. **`buildChain` does `await candidate.isAvailable()` on every chain build**: the time `chrome-builtin`'s `Translator.availability()` takes in the extension worker is not recorded; every rebuild `watchConfig` triggers probes again.
12. **`ProviderStatus.maxBatchChars/maxBatchItems` take the primary engine's values** (`transport.ts:149-150`): demoted to `chrome-builtin`, content still plans batches by the primary (e.g. google-web 8000/100), relying on E8's semaphore inside the provider; whether DESIGN §8.5 accepts “planned by the primary” is not stated.
