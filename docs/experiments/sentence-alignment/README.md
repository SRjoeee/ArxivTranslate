# 实验：句子级对照与纯文本占位符（2026-09-08）

这个分支只存**测量数据与探针脚本**，不含任何实现。做左右对照阅读（悬停某句 → 高亮原文对应句）时切回这里，数据都在，不用重跑。

脚本里的路径是硬编码的绝对路径（当时在 scratchpad 里跑的），复用前要改。

## 起因

用户问：沉浸式翻译用免费非 LLM 引擎，为什么每个节点都保护得很好？把它的扩展复制一份加载进 Playwright 做黑盒观察（只看请求形状与 DOM 结构，**不读、不抄它的打包代码**——闭源商业产品，与本项目 GPL-3.0 不兼容）。

## 一、沉浸式翻译的实际做法（`scripts/oracle.mjs`、`it-probe*.mjs`）

它的 content script 匹配 `<all_urls>`，所以可以起本地服务器喂构造好的测试页，精确地问它「遇到这种情况你怎么办」。

- 记号 `@N#`，**编号块内局部、每块从 0 重新开始**；记号两侧补空格
- 整段一起送，线上传纯文本；打到的正是 #98 那个微软免鉴权端点
- 内联元素（`<em>` / `<strong>` / `<a>` / `<cite>`）**一律拍平**，译文 DOM 里只剩 `font`——**链接因此点不动**
- 只有公式没有文字的块不发送
- 整页攒成一个请求
- 译文**插进原节点内部**（我们不能学，违反 §7.1）

**它的两个缺陷**（`data/oracle-sent.json`）：

1. 不转义正文里的字面量记号。构造一段同时含字面量 `@0#` 与真占位符的文字，渲染结果是「字面标记 w 和实公式 w」——公式被克隆进两个位置，原文字消失。
2. 记号被引擎复制时它照单全收。30 个记号那段实测 `trMath: 31`，译文里同一个符号出现两次。

## 二、线上格式：按引擎选，不是全局换一种（`scripts/baseline.mts`）

90 个真实块、400 个占位符：

| 线上格式 | 微软 | Google |
|---|---|---|
| 现在的 `<x id="N"/>` 标签 | **0%**（400 个全丢） | **100%** |
| `@abc#` 纯文本记号 | 98% 块 / 99.3% 记号 | 93% 块 / 96.8% 记号 |

结论：**保留两套**。Google 走标签（100%，零改动），微软等只收纯文本的引擎走记号。整体换成记号是净损失。

### 记号语法对比（`scripts/bakeoff.mts`）

- **字母 id 明显优于数字 id**：`@abc#` 在 Google 上 93% 块，`@N#` 只有 79%。数字太像引用编号，会被改写成「第 1 节」「表 1」
- **私用区字符（U+E000+）被微软整个吞掉，0% 存活**，淘汰
- 冲突率 0：12 篇 fixture、725572 字符里，所有候选记号的完整形式一次都没出现过（裸 `@` 5 次全是邮箱，裸 `#` 1 次是 F#）

### 成对记号不可用（`scripts/paired.mts`）

80 个含成对占位符的块、275 个 void、143 个 paired：

```
                块完好   void      paired
扁平  微软        99%    99.6%      —
扁平  Google      95%    98.5%      —
成对  微软        85%    99.6%     92.3%
成对  Google      63%    95.6%     70.6%   ← 42/143 直接丢
```

只能像沉浸式翻译那样拍平。代价：占位符里 23.4% 是成对的，49.2% 的块至少含一个。**但我们比它强的地方**：带功能的元素（链接）按 void 处理保住可点击，`runs.ts` 里 issue #44 那条规则直接继承。

### 开销（`scripts/cost.mts`）

```
markup 线上载荷  894 KB
marker 线上载荷  745 KB   −16.7%（记号比标签短）
送出段数         都是每块一段（runs 路径是每块 3.43 段）
splitRuns 额外耗时 10 ms（12 篇合计）
```

**性能是净收益**，不是代价。marker 路径应建在 `splitRuns()` 之上，不要另写序列化器。

## 三、句子级对齐

### CSS Custom Highlight API 可用（`scripts/highlight-api.mjs`）

```
supported: true, Chrome 153, domUnchanged: true
```

高亮任意 Range **完全不碰 DOM**，与 §7.1 天然兼容。原文侧不需要（也不允许）包 `<span>`。

### 两条产生对齐的路

**A. 句子边界记号**（`scripts/sent-align.mjs`）：微软 3/3 段对齐，Google 2/3（第三段边界记号全丢）。失败是软的——那段没有高亮，译文完好。

**B. 按句切分成独立段送**（`scripts/quality.mts`，40 段真实语料）：

```
微软    逐字相同 37/40，相似度中位 1.000
        sentLen [140,84,157,227,147] ← 它内部本来就按句切
Google  逐字相同 0/40，相似度中位 0.919，p10 0.811
```

**微软按句切分零质量代价**（本质是句子级模型）；**Google 确实用跨句上下文**，切了会掉术语一致性，实测有一处把 conditioning 误译成「条件反射」。

所以：**微软走 B（对齐 100% 精确且免费），Google 走 A，LLM 走 A**。上层统一看一个可选的「句子映射」，渲染层不关心它怎么来的。

### 切句器本身是风险

微软那 3 处失败全是参考文献里的 `Phys. Rev.` 被当成句号断开，翻成「物理学。牧师。」。§5.4 的参考文献块应直接不做句子切分；正文里的缩写要认真处理。`scripts/build-eval.mts` 里的 `ABBR` 正则是当时用的版本。

## 四、免费引擎盲评（`scripts/build-eval.mts`、`data/eval-sheet.md`、`data/eval-key.json`）

38 段真实块，跨 12 篇 9 个学科，A/B 随机打乱、占位符统一显示成 `⟦n⟧` 以免语法泄底，打完分再揭晓。**评委是我（单一 LLM 评委），不是人类评审团，结论当参考。**

**Google 22 胜，微软 11 胜，5 平。**

### 一个已确认的方法学缺陷

我没有归一化空白就送出去了。fixture 的 HTML 原文带换行符，微软会原样保留并近似逐行翻译，Google 内部会归一化。`scripts/ws.mjs` 验证：归一化后微软那几段完全正常。**至少 4 段是因此失分的**，最坏情况修正后是 18 : 15，排序不变但差距小得多。

→ **归一化空白是接任何 marker 路径引擎前的必改项**。现在 `src/core/pipeline/batches.ts:25` 只对标题归一化，正文原样送。

### 两者的错法不同

- **微软弱在专业术语**：Galactocentric → 半乳系、Myr → 米尔、1 Gyr → 金刚期、rapidity → 快速、data race → 数据竞赛/数据种族（同段不一致）、barrier → 障碍物
- **Google 弱在数学语域**：total order → 总订单、"one has" → 一个人有、"Let X be" → 让 X 是（应为「设」）、Figure → 数字
- **学科倾向**：两篇纯数学论文（math.AP / math.OC）微软 4:2 领先，物理与 CS Google 压倒性赢。样本小，方向明确

### 主力引擎建议：维持 Google

| | Google | 微软 |
|---|---|---|
| 盲评质量 | 22 胜（最坏 18） | 11 胜（最好 15） |
| 占位符完整率 | **100%**（现有标签路径） | 99.3%（需记号路径） |
| 内联样式 | **全保留** | 49.2% 的块要拍平 |
| 实现成本 | **零**，已在跑 | 记号路径全套 |

微软的价值是**第二免费引擎的韧性**（硬规则 4），以及**承担句子对齐**——做悬停对照时它反而是更合适的那个。

## 五、现成实现调研：没有可搬的

- 三个参考仓库都没做真正的逐句对齐。FluentRead 的 `bilingualSentenceHighlight.ts` 只有 15 行，是个开关属性，真正的高亮是 `page.css` 里 `.fluent-read-bilingual:hover` 的**整块**高亮
- GitHub 上的 "bilingual sentence aligner"（Gale & Church 1993、LaBSE、微软的对齐器）全是**语料库工具**：拿两段成品译文用统计方法事后对齐
- 做到类似功能的扩展（Bilingual Reader、FluentRead）都停在**段落级**

**我们的处境更好**：那些工具没有翻译过程的控制权，只能事后猜；我们控制请求，可以让对齐在翻译时免费产生。
